# 技能 05 — 系統管理

## 功能概述

系統管理模組提供用戶 CRUD、角色管理、以及系統參數動態配置。用戶管理支援啟用/停用狀態切換，系統管理員（admin）不可被刪除。角色管理中系統管理員角色（_key='admin'）不可被刪除。

## 功能地圖

| 頁面 | 路由 | 說明 |
|------|------|------|
| 用戶管理 | `/app/users` | 用戶 CRUD，啟用/停用開關 |
| 角色管理 | `/app/roles` | 角色 CRUD，系統管理員不可刪除 |
| 系統參數 | `/app/params` | 動態 Tab（來自 DB）+ 特殊子頁面 |

## 1. 用戶管理（UserManagement）

### 路由
`/app/users`

### 前置條件
- 已登入系統
- 具有系統管理員角色

### 操作步驟

**Step 1. 進入用戶管理頁**
點擊左側側邊欄「**系統管理**」→「**用戶管理**」。

**Step 2. 瀏覽用戶列表**
- 顯示欄位：用戶名、姓名、角色、狀態、會員等級、創建時間
- 角色透過 role_keys 映射顯示角色名稱（非 _key）

**Step 3. 新增用戶**
- 點選右上角「**新增用户**」按鈕
- 填寫表單（全部為必填）：
  - **用戶名**：系統唯一，登入帳戶
  - **密碼**：至少 6 個字元
  - **姓名**：顯示名稱
  - **角色**（Select，多選）：從已存在角色中選擇
  - **狀態**（Select）：啟用 / 禁用
  - **會員等級**（Select）：一般用戶 / VIP
- 點選「**確認**」完成新增

**Step 4. 編輯用戶**
- 點選該列「**編輯**」按鈕
- 編輯表單，用戶名不可修改（disabled）
- 密碼欄位不出現（無需修改密碼）
- 點選「**確認**」儲存

**Step 5. 重設密碼**
- 點選該列「**重置密码**」按鈕（KeyOutlined 圖示）
- 彈出密碼 Modal，填寫：
  - **新密碼**：至少 6 個字元
  - **確認密碼**：需與新密碼一致
- 點選「**確認**」完成

**Step 6. 啟用/停用用戶**
- 點選該列的「**Switch 開關**」
- 即時更新狀態（userApi.update），顯示成功/失敗訊息

**Step 7. 刪除用戶**
- 點選該列「**刪除**」按鈕（DeleteOutlined）
- Popconfirm 確認後刪除
- **用戶名為 admin 的帳戶不可刪除**

### 介面元素

| 元素 | 說明 |
|------|------|
| 新增用户按鈕 | 建立新用戶（Primary + PlusOutlined） |
| 用戶表格 | 欄位：用戶名、姓名、角色、狀態、會員等級、創建時間 |
| 編輯按鈕 | 開啟編輯 Modal |
| 重置密码按鈕 | 開啟密碼重置 Modal（KeyOutlined） |
| 刪除按鈕 | 刪除用戶（DeleteOutlined，Popconfirm 確認） |
| StatusSwitch | 自定義 Switch，綠色=啟用，灰色=禁用 |
| 新增/編輯 Modal | 寬度 500，Form 表單 |
| 密碼重置 Modal | 標題「重置密码」，含密碼確認校驗 |

### 用戶欄位說明

| 欄位 | 說明 |
|------|------|
| 用戶名 | 登入帳戶，系統唯一，編輯時不可修改 |
| 姓名 | 顯示名稱 |
| 角色 | 透過 role_keys 陣列映射顯示角色名稱（多選） |
| 狀態 | enabled=啟用，disabled=停用 |
| 會員等級 | general=一般用戶，vip=VIP |
| 創建時間 | 格式：YYYY/MM/DD HH:mm:ss |

### 常見問題

**Q: 為什麼無法刪除 admin 帳戶？**
> 系統保護機制：用戶名為 `admin` 的帳戶被設定為不可刪除，防止系統失去唯一管理員。

**Q: 停用的用戶可以登入嗎？**
> 不可以。狀態為 `disabled` 的帳戶登入時會被拒絕。

**Q: 編輯時為什麼不能修改用戶名？**
> 用戶名是系統唯一識別碼，修改會導致歷史資料無法關聯，因此設計為不可修改。

## 2. 角色管理（RoleManagement）

### 路由
`/app/roles`

### 前置條件
- 已登入系統
- 具有系統管理員角色

### 操作步驟

**Step 1. 進入角色管理頁**
點擊左側側邊欄「**系統管理**」→「**角色管理**」。

**Step 2. 瀏覽角色列表**
- 顯示欄位：角色名稱、角色描述、創建時間
- 目前系統存在三個預設角色：系統管理員（_key='admin'）、經理、顧問

**Step 3. 新增角色**
- 點選「**新增角色**」按鈕
- 填寫表單：
  - **角色名稱**（必填）
  - **角色描述**（TextArea）
- 點選「**確認**」完成

**Step 4. 編輯角色**
- 點選「**編輯**」按鈕
- 修改角色名稱或描述
- 點選「**確認**」儲存

**Step 5. 刪除角色**
- 點選「**刪除**」按鈕
- **系統管理員角色（_key='admin'）不可刪除**，會顯示錯誤訊息「系统管理员角色不可删除」
- 其他角色 Popconfirm 確認後刪除

### 介面元素

| 元素 | 說明 |
|------|------|
| 新增角色按鈕 | 建立新角色（Primary + PlusOutlined） |
| 角色表格 | 欄位：角色名稱、角色描述、創建時間 |
| 編輯按鈕 | 開啟編輯 Modal |
| 刪除按鈕 | 刪除角色（DeleteOutlined，Popconfirm 確認） |
| 新增/編輯 Modal | 寬度 500，含 name(TextInput) + description(TextArea) |

### 預設角色

| 角色名稱 | _key | 說明 |
|----------|------|------|
| 系統管理員 | admin | 完整系統權限 |
| 經理 | （非 admin） | 部分管理權限 |
| 顧問 | （非 admin） | 一般操作權限 |

### 常見問題

**Q: 為什麼無法刪除系統管理員角色？**
> 系統保護機制：_key 為 `admin` 的角色被設定為不可刪除，確保系統永遠有管理員存在。

**Q: 角色和用戶的關係？**
> 一個用戶可以屬於多個角色（role_keys 為陣列），每個角色代表一組權限集合。

## 3. 系統參數（SystemParams）

### 路由
`/app/params`

### 前置條件
- 已登入系統
- 具有系統管理員角色

### 架構說明

系統參數頁的 Tab 清單**並非固定**，而是從資料庫動態讀取所有參數，按 `category` 分組後動態生成 Tab。

此外存在**特殊 Tab**，對應獨立子頁面（這些 Tab 在 groupedParams 中被排除，改用專用元件渲染）：

| Tab Key | 對應子頁面/元件 |
|---------|----------------|
| models | SystemParamsModels |
| theme-templates | ThemeTemplateManagement |
| basic-tools | SystemParamsBasicTools |
| floating-assistant | FloatingAssistantSettings |
| data-agent | SystemParamsDataAgent |
| intent | SystemParamsIntent |
| backup | DatabaseBackupPanel |

其餘類別（basic、theme、window、behavior、update、knowledge 等）由 groupedParams 動態生成 Form。

### 操作步驟

**Step 1. 進入系統參數頁**
點擊左側側邊欄「**系統管理**」→「**系統參數**」。

**Step 2. 瀏覽與切換 Tab**
- 頂部 Tab 列，點選切換
- Tab 來自動態參數分組

**Step 3. Basic Tab（特殊 Tab）**
包含兩大部分：

**左側 - Logo 上傳**：
- 顯示當前 Logo（Image 或虛線佔位）
- 點選「上傳」按鈕（UploadOutlined）選擇圖片檔案
- 圖片自動轉為 base64 並寫入參數 `app.logo`

**右側 - 頭像選擇**：
- 大頭像預覽（Avatar，96px）
- 網格排列的頭像選擇器
- 點選頭像自動寫入參數 `basic.avatar`，並觸發全域 CustomEvent `avatar-changed`

**Step 4. 編輯參數**
- 在各 Tab 的表單中修改參數值
- 部分參數有不同的輸入類型（Input/Select/Switch/InputNumber/Input.Password）
- 特殊參數：
  - `basic.system_type`：Select，選項為 'sap' / 'ragic'，會同步寫入 localStorage
  - `ragic.api_key`：Input.Password（密碼輸入）

**Step 5. 保存**
- 點選「**保存**」按鈕（SaveOutlined）
- 系統逐一调用 `paramsApi.update(param_key, value)` 保存
- 保存成功顯示訊息並重新載入

**Step 6. 重置**
- 點選「**重置**」按鈕（ReloadOutlined）
- 表單回復至上一次 fetchParams 的值（即放棄未保存的修改）

### 介面元素

| 元素 | 說明 |
|------|------|
| 動態 Tab 列 | 由資料庫參數 category 分組自動生成 |
| Logo 顯示 | 當前 Logo 預覽 |
| 上傳按鈕 | UploadOutlined，支援 JPG/PNG |
| 頭像網格 | 點選切換頭像，選中者有視覺標記 |
| 參數表單 | 動態生成，根據 param_key 或 param_type 選擇輸入元件 |
| 保存按鈕 | 儲存該 Tab 所有參數變更 |
| 重置按鈕 | 放棄變更，回復原值 |

### 常見問題

**Q: 為什麼有些 Tab 是空白的？**
> 該類別在資料庫中可能沒有參數記錄，因此動態生成的表單為空。

**Q: 修改 system_type 後有什麼影響？**
> `basic.system_type` 會寫入 localStorage（'app.system_type'），其他模組可能會根據此值調整行為（如 Ragic vs SAP 差異）。

**Q: 頭像選擇後其他頁面為什麼也跟著變？**
> 頭像變更時會 dispatch 全域 CustomEvent `avatar-changed`，其他監聽此事件的模組（如浮動助手）會自動更新。
