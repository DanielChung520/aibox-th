# 技能 06 — 功能與意圖管理

## 功能概述

本模組包含兩個功能：**功能維護**（FunctionManagement）和**意圖編排**（IntentCatalog）。功能維護提供系統功能表（群組/子功能）的 CRUD 與拖曳排序；意圖編排管理 AI 對話意圖，提供 TopOrchestrator 和 DataAgent 兩組意圖目錄。

## 功能地圖

| 頁面 | 路由 | 說明 |
|------|------|------|
| 功能維護 | `/app/functions` | 功能群組拖曳排序，圖示選擇，授權管理 |
| 意圖編排 | `/app/intent-orchestration` | TopOrchestrator / DataAgent 雙 Tab |

## 1. 功能維護（FunctionManagement）

### 路由
`/app/functions`

### 前置條件
- 已登入系統
- 具有系統管理員角色

### 操作步驟

**Step 1. 進入功能維護頁**
點擊左側側邊欄「**系統管理**」→「**功能維護**」。

**Step 2. 瀏覽功能群組列表**
- 以表格顯示功能群組（group）
- 支援雙擊展開群組，顯示該群組下的子功能（sub_function / tab）
- 子功能透過 `parent_key === group.code` 過濾

**Step 3. 新增功能群組**
- 點選「**新增功能**」按鈕
- 填寫表單：
  - **名稱**（必填）
  - **代碼**（必填，系統唯一）
  - **功能類型**：group / sub_function / tab
  - **圖示**：點選開啟 IconPicker 選擇
  - **路徑**：功能連結路徑
  - **狀態**：enabled / disabled
- 點選「**確認**」完成

**Step 4. 編輯功能**
- 點選「**編輯**」按鈕
- 代碼（code）不可修改（disabled）
- 點選「**確認**」儲存

**Step 5. 刪除功能**
- 點選「**刪除**」按鈕
- Popconfirm 確認後刪除

**Step 6. 拖曳排序**
- 支援拖曳改變群組的排列順序（DndKit + AntD Table 整合）
- 拖曳結束後自動呼叫 `functionApi.update` 更新每個群組的 `sort_order`

**Step 7. 授權管理**
- 點選「**授權**」按鈕
- 開啟授權 Modal：
  - 顯示**目前繼承的角色**（inherited_role_keys），以 Tag 標示來源
  - 可新增**額外授權角色**（Select mode=multiple）
- 點選「**確認**」呼叫 `functionApi.setRoles`

### 介面元素

| 元素 | 說明 |
|------|------|
| 新增功能按鈕 | 建立新功能或群組 |
| 功能表格 | 欄位：名稱、代碼、功能類型、圖示、路徑、狀態 |
| 展開/收合 | 雙擊列或點選展開按鈕顯示子功能 |
| 拖曳把手 | 拖曳列改變群組排序 |
| 編輯按鈕 | 開啟編輯 Modal |
| 刪除按鈕 | 刪除功能（Popconfirm） |
| 授權按鈕 | 開啟角色授權 Modal |
| IconPicker | 選擇功能圖示的元件 |
| 授權 Modal | inherited_role_keys（唯讀 Tag）+ 額外角色 Select |

### 常見問題

**Q: 為什麼無法改變子功能的順序？**
> 目前拖曳排序僅作用於群組（flatGroups），子功能跟隨其所屬群組，不支援單獨拖曳。

**Q: inherited_role_keys 和 role_keys 有何不同？**
> inherited_role_keys 為從父功能繼承而來的角色，不可編輯；額外授權的 role_keys 由管理者自行添加。

## 2. 意圖編排（IntentCatalog）

### 路由
`/app/intent-orchestration`

### 前置條件
- 已登入系統
- 具有系統管理員角色

### 操作步驟

**Step 1. 進入意圖編排頁**
點擊左側側邊欄「**知識管理**」→「**意圖編排**」。

**Step 2. 切換 Tab**
- **TopOrchestrator**：TopOrchestrator 意圖（默認 Tab）
- **DataAgent**：DataAgent 意圖（由 DataAgentTables 元件渲染）

**Step 3. 瀏覽意圖列表（TopOrchestrator）**
- 頂部統計卡片：總意圖數、Chat 型數量、Task 型數量、已啟用數
- 表格欄位：Intent ID、名稱、描述、行動（action_type 標籤）、目標（target_agent 標籤）、工具、類型（intent_type 標籤）、信賴度、狀態、操作

**Step 4. 搜尋與篩選**
- 搜尋框：依 Intent ID 或描述關鍵字過濾
- 類型下拉：全部類型 / 全部狀態

**Step 5. 新增意圖**
- 點選「**新增意圖**」按鈕
- 填寫詳細表單（眾多欄位）：
  - Intent ID、Name、Description
  - action_type：direct_answer / tool_call / confirm_then_execute
  - target_agent、tool_category、tool_name
  - pdpa_id、ca_id、intent_type（task/chat/tool）
  - domain、bpa_id、task_type（conditional）
  - response_strategy、capabilities
  - confidence_threshold（預設 0.7）、priority、status
  - nl_examples（多行文字，系統自動分行）
- 點選「**確認**」完成

**Step 6. 檢視意圖詳情**
- 點選該列「**眼睛**」按鈕
- Drawer 拉出，顯示：名稱/描述 Tags + 三個 Tab（基本資訊 / 行動方案 / NL Examples）

**Step 7. 編輯意圖**
- 點選「**編輯**」按鈕
- 開啟與新增相同的表單，預填當前值
- 點選「**確認**」儲存

**Step 8. 刪除意圖**
- 點選「**刪除**」按鈕
- Modal 確認後刪除

**Step 9. 同步到 Qdrant**
- 點選「**同步到Qdrant**」按鈕
- 將所有已同步意圖的向量同步至 Qdrant 向量資料庫
- 顯示成功訊息與 synced_count

**Step 10. 設定（Embedding 配置）**
- 點選「**設定**」按鈕
- Drawer 拉出設定面板：
  - Embedding Model（文字輸入）
  - Embedding Dimension（數字）
  - Match Threshold（數字）
- 點選「**保存**」更新參數（`orch.embedding_model`、`orch.embedding_dimension`、`orch.match_threshold`）

### 介面元素

| 元素 | 說明 |
|------|------|
| TopOrchestrator Tab | 預設 Tab，TopOrchestrator 意圖 |
| DataAgent Tab | DataAgent 意圖（使用不同元件渲染） |
| 統計卡片 | 總意圖數、Chat 型、Task 型、已啟用 |
| 搜尋框 | 關鍵字過濾 |
| 類型/狀態下拉 | 精確過濾意圖列表 |
| 新增意圖按鈕 | 開啟新增 Modal |
| 重新整理按鈕 | 重新載入意圖列表 |
| 設定按鈕 | 開啟 Embedding 設定 Drawer |
| 同步到Qdrant按鈕 | 同步向量至 Qdrant |
| 操作按鈕 | 眼睛(詳情) / 編輯 / 刪除 |
| 詳情 Drawer | 三個 Tab：基本資訊 / 行動方案 / NL Examples |
| 設定 Drawer | Embedding Model、Dimension、Match Threshold |

### 常見問題

**Q: 修改 Embedding 設定後需要做什麼？**
> 修改 Embedding Model 或 Dimension 後，必須重新執行「同步到 Qdrant」，否則向量資料庫中的向量維度會與新設定不一致。

**Q: action_type 的三種模式有何不同？**
> - `direct_answer`：直接由 LLM 回覆，不調用任何工具
> - `tool_call`：路由至指定工具執行
> - `confirm_then_execute`：需使用者確認後才執行

**Q: 信賴度（confidence_threshold）如何影響匹配？**
> 當 NL 查詢的意圖匹配分數低於此閾值時，系統可能會回覆「無法理解」或要求澄清。
