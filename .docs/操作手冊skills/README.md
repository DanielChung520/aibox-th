# Edge Enterprise AI — 企業知識智能系統

## 我們相信：企業 AI 的本質是輔助，不是替代

當前 AI 市場充斥著「AI 將取代人類」的論述。這對以**創意為產品**的企業或許成立——但對絕大多數**以知識為基礎、以穩定為生命**的企業而言，這是一條危險的路。

企業的核心資產是知識，知識的邊界就是責任的邊界。

> **AI 的職責，是在已知知識的邊界內，輔助人類做出更精準的判斷；從來不是跨越這個邊界，替人類做決定。**

---

## 企業 AI 的五項核心價值

| 價值 | 意涵 |
|------|------|
| **降本** | 減少重複性查詢、降低錯誤決策成本 |
| **增效** | 縮短知識檢索時間，加速工作流程 |
| **提質** | 減少人為錯誤，提升知識準確性 |
| **創收** | 快速找到正確資訊，支撐業務決策 |
| **固安** | 知識邊界清晰，AI 不會超越範圍給出危險建議 |

**穩定、準確，是企業 AI 的根本。**

---

## 核心問題：為何企業 AI 總是幻覺？

### LLM 的上下文窗口是有限的

企業知識有多龐大？

- 一套 ERP 的 Schema：6MB+
- 企業文件知識庫：數百份文件
- 累積的客服對話、維修記錄、產業規範：無上限

而最強大的 LLM，context window 也不過 128K～200K tokens（約 0.1～0.2MB）。把整個企業知識塞進去？不可能。

**結果：AI 看不見企業的全貌，只能臆測。幻覺由此而來。**

### 我們的答案：有邊界的人工智慧

艾企不是讓 AI 去看整個企業知識庫，而是：

1. **建立知識的邊界**（Knowledge Boundary）：哪些是已知知識，哪些是不確定的領域
2. **有界的推斷**（Bounded Inference）：AI 只在已知邊界內工作，從不天馬行空
3. **人類始終是決策主體**：AI 提供選項，人類做出選擇

## 系統架構：混合檢索（HybridRAG）

### 兩種檢索，兩種智慧

**向量檢索（Vector Search）**：
- 透過 embedding 模型將知識轉為向量，存於 Qdrant 向量資料庫
- 根據語義相似度找回最相關的知識片段
- 強項：理解「這個詞背後的語義」

**圖譜檢索（Graph Search）**：
- 將知識抽成實體（Entity）與關係（Relation），存於 ArangoDB（離線建構階段由 graph_task 完成）
- 線上查詢時，以關鍵字匹配實體名稱 + BM25 排序取回相關節點
- 強項：理解「這個概念和其他概念的關聯」，並以結構化的節點-邊關係呈現事實網絡

### HybridRAG：讓兩種智慧形成有機整體

```
使用者查詢
    ↓
[查詢分類器] — 判斷是結構查詢 / 實體查詢 / 語義查詢
    ↓
根據分類動態調整權重
    ↓
┌──────────────────────────────────────────────────────┐
│  向量檢索 (Qdrant)         圖譜檢索 (ArangoDB)       │
│  Embedding 語義相似度匹配    關鍵字→實體名匹配+BM25   │
│  權重：vector_weight         權重：graph_weight        │
└──────────────────────────────────────────────────────┘
    ↓
[RRF 融合] — Reciprocal Rank Fusion
    Score(doc) = Σ weight_i / (k + rank_i)
    ↓
有序、去重、帶源的融合結果
    ↓
LLM 基於精確上下文生成回答
```

**關鍵設計**：
- **查詢分類**：自動判斷當前查詢適合向量為主、圖譜為主，還是兩者均衡
- **RRF 融合**：不是簡單加分，而是根據排名融合，讓出現在兩種檢索結果前列的知識優先入選
- **邊界控制**：透過 `root_id`（知識庫 ID）過濾，確保 AI 只檢索指定的知識範圍，不會跨庫臆測

### 知識本體（Ontology）：讓知識結構化

圖譜的根基是**知識本體**——領域概念模型。

```
Domain（領域）
  └── Major（主題）
        ├── Entity（實體）：人物、組織、概念、事件、流程
        └── Relation（關係）：誰屬於誰、什麼導致什麼
```

當一份文件進入系統：
1. **向量化**：切成 chunk，生成 embedding，存入 Qdrant
2. **圖譜抽取**：LLM 從文件中識別實體與關係，建立知識網絡
3. **混合檢索**：HybridRAG 同時使用兩種檢索結果，確保語義與結構並重

## 有邊界的推斷：如何避免幻覺？

### 機制一：知識邊界隔離

每個知識庫有獨立的 `root_id`。AI 的檢索永遠被限定在單一知識庫內——它看不見其他知識庫的內容，更不會跨庫臆測。

### 機制二：多重邊界約束

檢索範圍並非無限制，而是由多層機制共同約束：

- **top_k 限制**：最終只回傳 Top-K 融合結果（預設 10）
- **關鍵字上限**：圖譜檢索最多取 10 個關鍵字，避免無限展開
- **min_relevance 閾值**：RRF 分數低於閾值的結果直接過濾丟棄
- **Pipeline 管理**：可隨時 abort / delete 任務，控制知識庫生命週期

### 機制三：混合檢索的交叉驗證

當同一知識片段同時出現在向量檢索和圖譜檢索的前列，RRF 融合演算法會給予更高分數。這是兩種智慧相互校準的過程——比任何單一檢索方式都更可靠。

### 機制四：Prompt 上下文的精確控制

傳給 LLM 的不是整個企業知識庫，而是：

- HybridRAG 融合後的 Top-K 知識片段（通常 5～10 個）
- 每個片段帶有來源標記（source: vector / graph）
- 這些片段本身就是邊界——AI 看不見邊界外的東西

### 機制五：圖譜結構約束的事實網絡

圖譜檢索以實體-關係的結構化節點呈現知識。AI 看不見未被結構化的純文字，只能在已識別的實體節點之間推理——無法憑空臆造一段不存在的事實鏈。

## AI 與人類：協作而非替代

### 共同演化模式

艾企不是一次性給出答案，而是與使用者共同演化：

1. **AI 提出假設**：根據檢索結果，AI 猜測使用者的意圖
2. **人類確認或否定**：透過 UI 元素（按鈕、標籤、選項），人類給出反饋
3. **AI 持續修正**：反饋信號進入下一輪檢索，形成正循環

### 人機協作的具體場景

**場景一：NL→SQL 查詢**
- 使用者輸入「查詢本月採購金額超過 100 萬的供應商」
- AI 用意圖分類（Intent RAG）匹配到相關 Schema
- 若信心度不足，AI 主動詢問「您是指 PURCHASE_1 這張表嗎？」
- 人類回覆確認或選擇正確選項
- AI 才生成 SQL，確保語意準確

**場景二：知識庫檢索**
- 使用者詢問「這個異常該怎麼處理」
- HybridRAG 同時檢索相關維修文件（圖譜）和過往案例（向量）
- 結果經 RRF 融合後呈現，並標明來源
- 人類閱讀後做出維修決策——從不是 AI 告訴你「就這樣修」

### 企業責任的歸屬

> **當 AI 輔助人類，人類永遠是決策的主體，對結果承擔責任。**

這不是免責條款，而是企業 AI 的本質：**AI 提供工具，不提供答案**。答案來自對業務有深度理解的人。

## 與一般企業 AI 的比較

| 維度 | 一般企業 AI | 艾企 Edge Enterprise AI |
|------|-------------|-------------------------|
| 知識範圍 | 全部塞進 prompt（幻覺風險高） | 有邊界的混合檢索（精確可控） |
| 檢索方式 | 純向量（語義為主） | HybridRAG：向量 + 圖譜 + RRF |
| 推斷方式 | 無限制生成 | 有邊界約束，結果可溯源 |
| 人機關係 | AI 替代人類做判斷 | AI 輔助，人類做決策 |
| 錯誤處理 | 可能一口氣錯到底 | 信心度不足時主動要求澄清 |
| 企業適用性 | 創意產業可能適用 | 降本、增效、提質、創收、固安 |

## 技術特性

### 混合檢索引擎（HybridRAG）

| 元件 | 技術 |
|------|------|
| 向量資料庫 | Qdrant（本地部署） |
| 圖譜資料庫 | ArangoDB（本地部署） |
| Embedding | Ollama（本地 bge-m3 模型） |
| 融合演算法 | Reciprocal Rank Fusion（RRF, k=60，常數越高越重視低排名結果） |
| LLM 推理 | Ollama（本地部署，資料不外流） |

### 查詢分類（Query Classifier）

| 查詢類型 | 觸發關鍵字 | 預設權重 |
|----------|-----------|---------|
| 結構查詢 (structure_query) | 含「流程」「步驟」「哪些」「怎麼做」等 | graph_weight 較高 |
| 實體查詢 (entity_query) | 含「誰」「什麼組織」「哪張表」「什麼關係」等 | graph_weight 較高 |
| 語義查詢 (semantic_query) | 預設（其餘所有查詢） | vector_weight = graph_weight |

### 知識庫管理

- **檔案向量化**：Chunk 級別的 embedding，支援任意語言文件
- **圖譜抽取**：LLM 自動識別文件中的實體與關係
- **知識庫隔離**：每個知識庫有獨立 root_id，檢索範圍嚴格受限
- **混合檢索**：Vector + Graph → RRF 融合 → LLM 生成

## 設計理念總結

> **沒有邊界的 AI，是危險的 AI。**
>
> 艾企 Edge Enterprise AI 的核心，不是讓 AI 去看整個企業、生成無限答案；而是建立一個**有結構、有邊界、可溯源**的知識系統，讓 AI 在已知範圍內輔助人類，人類在這個範圍內做出精準決策。
>
> **知識的邊界，就是安全的邊界。**
>
> **安全的邊界，就是責任的邊界。**
>
> **責任在人來，AI 永遠是輔助。**
