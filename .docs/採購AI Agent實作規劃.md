## 1. 為什麼從 10 個變 5 個 Agent？

原始需求列出了 10 個 Agent，但其中有許多是「同一件事的不同步驟」或「同一角色做的連續動作」。合併後的好處：

- **對使用者更直覺** — 5 個 Agent = 5 個角色，而不是 10 個功能碎片
- **流程串得起來** — 比價完直接產生採購單，不用在兩個 AI 之間傳資料
- **開發維護成本更低** — 少一半的系統複雜度

### 合併邏輯一覽

```mermaid
mindmap
  原始10個Agent
    PA-01 智慧請購建議
    PA-02 請購重複偵測
      ──合併為── 採購請購小秘
    PA-03 自動詢比價
    PA-04 採購單自動生成
      ──合併為── 採購比價下單小秘
    PA-05 交期跟催
    PA-06 採購變更影響評估
      ──合併為── 採購跟單小秘
    PA-07 進貨驗收比對
    PA-08 進料不合格處理
      ──合併為── 進貨品管小秘
    PA-09 供應商績效評核
    PA-10 採購數據儀表板
      ──合併為── 採購分析評鑑小秘
```

## 4. Agent 1 — 採購請購小秘

### 對應的角色

> 🙋 **請購人員** 和 **生管人員** — 負責提出物料採購需求的人

### 他負責回答的 QA（5 題）

| 角色 | 問題 | AI 怎麼回答 |
|:----|------|-----------|
| 管理部主管 | 目前有幾張請購單等我簽核？有沒有急件？ | 調出待簽清單，按金額/急迫度排序 |
| 倉管人員 | 輪椅升降機目前庫存還有幾台？夠不夠下週的生產需求？ | 查庫存 + 比對下週工單需求量 |
| 倉管人員 | 新到的空壓機比較大台，建議放哪個儲位？ | 查儲位表 + 物料尺寸 → 建議適當儲位 |
| 生產人員 | 輪椅固定座缺貨，有沒有相容的替代品可以先用？ | 查替代料表 + 庫存 → 列出可用替代品 |
| 生產人員 | 我需要領一把新的電鋸，請購流程怎麼走？ | 引導填寫請購單，告知所需資訊 |

### 他解決什麼問題？

**現在**：生管拿到一張改裝工單，要手動去查 BOM 表 → 查庫存 → 算要買多少 → 手寫請購單 → 送簽核。如果剛好有人已經買了同樣的東西，沒人知道。

**以後**：工單一建立，AI 30 秒內就算好缺什麼料、該買多少，還順便檢查有沒有人已經買了，自動產出請購單草稿。

### 工作流程

```mermaid
flowchart TD
    S[📥 觸發] --> C{什麼情況觸發？}
    C -->|工單建立| W1[BOM展開<br/>算出這張工單需要哪些物料]
    C -->|庫存量過低| W2[掃描庫存<br/>找出低於安全水位的物料]
    C -->|手動查詢| W3[使用者提問<br/>像是「XX物料庫存夠不夠？」]

    W1 --> W4
    W2 --> W4
    W3 --> W4

    W4[比對庫存<br/>現有量 vs 安全庫存 vs 已在運送中的量]
    W4 --> W5{缺口分析}
    W5 -->|庫存足夠| END1[✅ 不動作，記錄正常]
    W5 -->|庫存不足| W6[查歷史用量<br/>計算建議採購量]
    
    W6 --> W7[檢查近期有沒有人<br/>已經請購或採購同一物料]
    W7 --> W8[產出請購單草稿<br/>帶入上次買的供應商和價格]
    W8 --> END2[📋 送簽核流程]
```

### 他會用到的 Ragic 表單

| 表單名稱 | 做什麼用 | AI 讀取 | AI 寫入 |
|---------|---------|:-------:|:-------:|
| 請購憑單 | 建立採購申請單 | ✅ | ✅ |
| 庫存主檔 | 查目前庫存量 | ✅ | |
| BOM 表 | 展開工單所需物料清單 | ✅ | |
| 工單表 | 得知目前正在進行的改裝案 | ✅ | |
| 歷史採購紀錄 | 參考上次跟誰買、多少錢 | ✅ | |
| 儲位表 | 建議存放位置 | ✅ | |

### 需要懂的專業知識

- **BOM 結構**：一台改裝車需要哪些物料、有沒有替代料可用
- **庫存邏輯**：什麼是「安全庫存」、什麼是「在途量」
- **採購流程**：請購單怎麼跑簽核

### AI 用在這裡

```
「根據過去6個月該物料的使用趨勢，以及目前工單計畫，
建議本次採購數量為 15 個（原計算需求 12 個 + 安全緩衝 3 個），
因為往年同期需求量平均上升 25%。」
```

→ **只是產出這一段「建議說明」而已**，其他所有計算都是規則。

## 5. Agent 2 — 採購比價下單小秘

### 對應的角色

> 🙋 **採購人員** 和 **管理部主管** — 負責比價和決定跟誰買的人

### 他負責回答的 QA（5 題）

| 角色 | 問題 | AI 怎麼回答 |
|:----|------|-----------|
| 管理部主管 | 這張請購單的三家報價結果如何？你建議選哪家？ | 列出三家 TCO 排名 + AI 建議 + 價格異常標記 |
| 管理部主管 | 這張大額採購超出預算了，有沒有更經濟的替代方案？ | 查替代物料/供應商 + 價差分析 |
| 採購人員 | 這個新物料要跟哪些供應商詢價？有合格供應商清單嗎？ | 調出合格供應商名單 + 聯絡方式 + 過去報價參考 |
| 採購人員 | 這張請購單核准了，幫我產生採購憑單並帶入報價資料 | 自動填入採購單 + 附報價文件 + 送簽核 |
| 財務人員 | 這張進口的輪椅升降機有沒有關稅減免？稅額怎麼算？ | 依稅則查詢關稅 + 減免條件說明 |

### 他解決什麼問題？

**現在**：請購單核准了，採購要手動找合格供應商 → 打電話或寄信詢價 → 手動比價 → 主管決定 → 手KEY採購單。

**以後**：一鍵核准後，AI 自動調出合格廠商清單和歷史報價，算出 TCO 排名（含運費+付款條件），主管選定後直接產生採購單。

### 工作流程

```mermaid
flowchart TD
    S[📥 請購單核准] --> W1[自動查詢合格供應商<br/>依 QP-S06 標準篩選]
    W1 --> W2[調出每家供應商<br/>對該物料的歷史報價]
    W2 --> W3[計算TCO總持有成本<br/>單價+運費+付款條件]
    
    W3 --> W4{比對歷史均價}
    W4 -->|價格正常| W5[列出TCO排名]
    W4 -->|某家價格異常偏高或偏低| W6[標記異常<br/>AI 自動備註說明]
    
    W5 --> W7[🔍 管理部主管決定供應商]
    W6 --> W7
    W7 --> W8[自動產生採購憑單<br/>帶入品項/數量/價格/交期]
    W8 --> W9[送簽核流程<br/>簽核完成後自動通知供應商]
```

### 他會用到的 Ragic 表單

| 表單名稱 | 做什麼用 |
|---------|---------|
| 供應商主檔 | 查合格供應商清單、評鑑分數 |
| 歷史報價紀錄 | 各供應商過去報價單價 |
| 請購憑單 | 輸入來源（已核准的請購需求） |
| 採購憑單 | **產出**（建立採購單） |
| 國定假日表 | 計算預估到貨日（排除假日） |

### 需要懂的專業知識

- **供應商管理 QP-S06**：什麼樣的供應商算「合格」
- **TCO 計算**：除了單價，運費和付款條件怎麼換算

## 9. AI 夠聰明嗎？模型與技術需求

### 系統現在用什麼 AI？

你目前的系統（ABC Desktop）已經串接多種 AI 模型：

```
已在使用的 AI 模型：
├── 🔵 Ollama 本地模型（免網路、免付費）
│   ├── Gemma 4 31B（Google 開源，強大通用）
│   ├── Qwen3-Coder 30B（阿里巴巴，程式碼強）
│   └── Llama 3.2（Meta，輕量）
│
├── 🟢 DeepSeek V4 Flash（雲端 API，付費）
│
└── 🟡 Gemini 2.5 Flash（Google 雲端 API，用於 ESG Agent）
```

### 採購 Agent 真的需要 AI 嗎？

很多人會以為「AI Agent = 全部用 AI」，但實際上：

```mermaid
pie title 5個Agent 的 AI 使用比例
    "純規則（不需要 AI）" : 70
    "AI 輔助（LLM 產出建議說明）" : 30
```

**70% 的工作是規則**，例如：
- BOM 展開、庫存比對 → 像 Excel VLOOKUP
- TCO 排名、加權評分 → 公式計算
- 比對送貨單 vs 採購單 → 簡單的數值比對
- WORKDAY 計算、分級催貨 → If-Then 邏輯

**只有 30% 需要 AI 的語言能力**，例如：
- 「根據歷史趨勢建議採購量」
- 「這個 Delay 對張三的車影響有多大？」
- 「這批不合格品建議退貨還是特採？」

### 12B 等級的本地模型夠用嗎？

**答案是：夠，而且還有剩。**

下面是這些採購工作對 AI 能力的需求程度：

```mermaid
quadrantChart
    title 採購 Agent 的 AI 需求分析
    x-axis 不需專業知識 --> 需專業知識
    y-axis 不需要思考 --> 需要思考
    quadrant-1 簡單但需知識
    quadrant-2 困難任務
    quadrant-3 簡單任務
    quadrant-4 需分析能力

    "請購建議": [0.3, 0.4]
    "重複偵測": [0.2, 0.1]
    "TCO排名": [0.4, 0.2]
    "催貨分級": [0.3, 0.1]
    "影響評估": [0.7, 0.7]
    "不合格建議": [0.6, 0.5]
    "供應商評分": [0.5, 0.2]
    "預算預測": [0.4, 0.6]
```

以上任務中，**影響評估**（Agent 3）是最需要 AI 推理能力的——但它的複雜度也就相當於「一個有 3 年經驗的採購助理 3 分鐘的思考量」。這對當前主流的 12B~14B 模型來說非常輕鬆。

**建議使用的本地模型：**

| 模型 | 大小 | 中文能力 | 優點 | 建議用於 |
|:-----|:---:|:-------:|------|---------|
| **Qwen2.5 14B** | 14B | 🥇 優秀 | 中文理解最好、穩定 | 全部 Agent |
| **Mistral Nemo 12B** | 12B | 🥈 良好 | 推理能力強 | Agent 3（最需要思考） |
| **Gemma 2 9B** | 9B | 🥉 中等 | 穩定輕量 | Agent 2、4（較簡單） |

> **重點**：採購 Agent 不需要跟 ChatGPT 一樣聰明。他要的是「規則能力強 + 會說人話」——前者靠程式，後者靠 ~12B 模型就夠了。
