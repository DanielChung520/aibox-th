## 1. 概述

EEA-CRM 客戶列表為三源資料（衛福部、業務王、ERP）的統一客戶管理介面，提供搜尋、篩選、分類、權限管理及資料同步功能。

### 1.1 技術棧

| 層 | 技術 |
|---|------|
| 前端框架 | React 18 + TypeScript |
| UI 元件庫 | Ant Design 6.x |
| HTTP 客戶端 | Axios |
| 後端 | Rust Axum (port 6500) |
| 資料庫 | ArangoDB |

### 1.2 資料來源

| 來源 | key | 說明 |
|------|-----|------|
| 衛福部 | `mohw` | 衛生福利部長照機構公開資料 |
| 業務王 | `business_kindom` | 潛在客戶資料庫 |
| ERP | `ragic` | 既有客戶 ERP 資料 |

## 2. 資料模型

### 2.1 CRMCustomer

```typescript
interface CRMCustomer {
  _key: string;
  source: 'mohw' | 'business_kindom' | 'ragic';
  status: 'potential' | 'lead' | 'customer' | 'merged';
  name: string;
  name_short?: string;
  name_raw?: string;
  mohw_id?: string;
  business_kindom_id?: string;
  phone?: string;
  email?: string;
  contact_person?: string;
  address?: string;
  city?: string;
  district?: string;
  lat?: number;
  lng?: number;
  abc_grade?: string;         // A/B/C/E，E=未分類
  category?: string[];        // 服務類別（喘息服務、居家服務…）
  org_tags?: string[];        // 機構分類標籤（長照機構、醫院附設…）
  sales_rep?: string;         // 業務負責人
  tags?: string[];
  last_contact_at?: string;
  last_contact_note?: string;
  merge_status?: string;
  merged_into?: string;
  created_at: string;
  updated_at: string;
  synced_at?: string;
  import_batch?: string;
  _perm_assigned?: boolean;   // 是否有權限設定（計算欄位）
  _perm_authorized?: boolean;  // 當前用戶是否已授權（計算欄位）
}
```

### 2.2 狀態 enum

| 值 | 顯示 | 說明 |
|----|------|------|
| `potential` | 潛在客戶 | 尚未接觸 |
| `lead` | 業務接觸中 | 已建立聯繫管道 |
| `customer` | 既有客戶 | 已成為正式客戶 |
| `merged` | 已合併 | 已被合併至其他記錄 |

### 2.3 ABCE 分類

| 等級 | 標籤顏色 | 顯示文字 |
|------|---------|---------|
| A | `green` | A類 |
| B | `gold` | B類 |
| C | `red` | C類 |
| E | `default` | 未分類 |

## 3. API

### 3.1 列表查詢

```
GET /api/v1/crm/customers
Authorization: Bearer <token>
```

**Query Parameters:**

| 參數 | 型態 | 說明 |
|------|------|------|
| `page` | number | 頁碼（預設 1） |
| `page_size` | number | 每頁筆數（預設 15） |
| `q` | string | 全文搜尋（機構名稱、電話、地址） |
| `source` | string | 資料來源篩選：`mohw` / `business_kindom` / `ragic` |
| `status` | string | 狀態篩選：`potential` / `lead` / `customer` / `merged` |
| `abc_grade` | string | ABCE 分類篩選 |
| `city` | string | 區域篩選 |

**Response:**

```json
{
  "data": [ CRMCustomer, ... ],
  "pagination": {
    "page": 1,
    "page_size": 15,
    "total": 32490,
    "total_pages": 2166
  },
  "summary": {
    "total": 32490,
    "by_source": { "mohw": 15362, "business_kindom": 16604, "ragic": 524 },
    "by_status": { "potential": 16604, "lead": 12866, "customer": 3020 }
  }
}
```

### 3.2 更新客戶

```
PATCH /api/v1/crm/customers/{key}
```

**Body:** 支援部分更新，可更新欄位：
`name`, `phone`, `email`, `address`, `status`, `abc_grade`, `sales_rep`, `tags`, `category`, `org_tags`, `last_contact_at`, `last_contact_note`

### 3.3 權限管理

| 方法 | 路徑 | 說明 |
|------|------|------|
| GET | `/api/v1/crm/permissions/{customer_key}` | 取得單一客戶權限 |
| POST | `/api/v1/crm/permissions/{customer_key}` | 新增/更新權限 |
| DELETE | `/api/v1/crm/permissions/{customer_key}` | 移除權限 |
| GET | `/api/v1/crm/users-and-roles` | 取得使用者與角色清單 |

### 3.4 資料匯入

| 方法 | 路徑 | 說明 |
|------|------|------|
| POST | `/api/v1/crm/customers/import/business-kindom` | 匯入業務王資料 |
| POST | `/api/v1/crm/customers/import/mohw` | 觸發衛福部資料更新 |

### 3.5 合併客戶

```
POST /api/v1/crm/customers/merge
Body: { primary_key: string, merge_keys: string[], reason?: string }
```

## 4. 頁面功能

### 4.1 佈局

```
┌─────────────────────────────────────────────┐
│  [搜尋框] [狀態篩選] [ABC篩選] [區域篩選]   │ [總計: N筆][來源Tag...][衛服部更新]
├─────────────────────────────────────────────┤
│  [全部] [衛福部] [潛在客戶] [ERP]           │  ← Tabs 切換資料來源
├─────────────────────────────────────────────┤
│  ★ | 來源 | 機構名稱 | 電話 | 區域 | ABC |   │
│  機構分類 | 業務負責人 | 最近互動 | 狀態 |   │
│  權限 | 操作                                │
│  ───────────────────────────────────────── │
│  data rows...                              │
│  ───────────────────────────────────────── │
│  [分頁]                                    │
└─────────────────────────────────────────────┘
```

### 4.2 表格欄位

| 欄位 | 寬度 | 說明 |
|------|------|------|
| ★ (關注) | 40px | 星號圖示，黃色 = 已關注，點擊切換 |
| 資料來源 | 80px | Tag 顏色標示（綠=衛福部、金=潛在客戶、藍=ERP） |
| 機構名稱 | 200px | 粗體顯示，長名稱 ellipsis 截斷，hover Tooltip 顯示完整名稱 |
| 電話 | 120px | |
| 區域 | 80px | |
| ABC分類 | 90px | Tag 顏色（綠/金/紅/灰） |
| 機構分類 | 160px | 顯示前 3 個 Tag，超出顯示 +N |
| 業務負責人 | 100px | 權限受限時顯示 `-` |
| 最近互動 | 110px | 權限受限時顯示 `-` |
| 狀態 | 100px | Tag 顯示（潛在客戶/業務接觸中/既有客戶/已合併） |
| 權限 | 60px | 盾牌圖示，黃色=有權限設定，灰色=公開 |
| 操作 | 80px | 詳情按鈕 |

### 4.3 搜尋與篩選

**搜尋欄位：** 機構名稱、電話、地址模糊搜尋，即時觸發查詢

**來源 Tabs：**
- 全部（預設）
- 衛福部
- 潛在客戶
- ERP

**下拉篩選：**
- 狀態（潛在客戶 / 業務接觸中 / 既有客戶）
- ABC 分類（A類 / B類 / C類 / E類）
- 區域（北部 / 中部 / 南部 / 東部 / 離島）

### 4.4 表格互動

| 操作 | 行為 |
|------|------|
| 滑鼠左鍵點擊行 | 選中 |
| 滑鼠雙擊行 | 開啟詳情 Drawer |
| 滑鼠右鍵行 | 開啟右鍵上下文選單 |

### 4.5 排序

預設依照 `created_at DESC` 排序（由 API 後端處理）。關注的客戶（★）會置頂（前端排序）。

## 5. 右鍵選單

### 5.1 選單項目

```
┌─────────────────────┐
│ ★ 標記關注 / 取消關注 │
│ 🏷 ABCE             │  ← 子選單
│    ├ ✓ A類          │
│    ├ B類            │
│    ├ C類            │
│    └ E類 (未分類)   │
│ 🏷 機構分類          │
│ 🔄 指派/變更業務負責人│  ← 僅管理員/業務主管
│ 👤 查看聯繫人/名片    │  ← (開發中)
│ 📋 查看互動 Timeline  │  ← (開發中)
│ 📅 安排行程計劃       │  ← (開發中)
└─────────────────────┘
```

### 5.2 ABCE 分類

- 點選子選單中的 A/B/C/E 即時更新
- 目前等級顯示 ✓ 標記
- **Optimistic update**：先更新前端 state → 非同步呼叫 API → 失敗時 rollback
- E 以灰色 `default` Tag 顯示為「未分類」

### 5.3 指派/變更業務負責人

- 僅 `role_keys` 包含 `admin` 或 `role_names` 包含 `業務主管` 的使用者可見
- 開啟 Modal → 搜尋選擇使用者 → 確認後更新 `sales_rep` 欄位

### 5.4 機構分類編輯

- 所有使用者均可使用（權限公開）
- 開啟 Modal → `Select mode="tags"` 可選取預設標籤或輸入自訂標籤→ 確認後更新 `org_tags` 欄位
- 空陣列 = 清除分類

## 6. 詳情 Drawer

### 6.1 區塊

| 區塊 | 欄位 |
|------|------|
| 頂部 Tags | 資料來源、狀態、ABC 分類、受限標記 |
| 基本資訊 | 機構名稱、原始名稱、衛福部ID、業務王ID |
| 聯絡資訊 | 電話、Email、地址、區域 |
| 業務資訊 | 業務負責人、最近互動、最近備註、服務類別、機構分類 |

| 系統資訊 | 資料來源、匯入批次、建立時間、更新時間、同步時間 |

**權限控制：** 若客戶已設定權限且當前使用者未獲授權 → 業務資訊區塊隱藏

## 7. 權限管理

### 7.1 Modal 元件

- 點擊表格「權限」欄位的盾牌圖示開啟
- 使用 Ant Design Transfer 雙欄選擇元件
- 分為「指派使用者」與「指派角色」兩個區塊
- 底部左側有「移除權限（回到公開）」按鈕

### 7.2 狀態標記

| 狀態 | 圖示顏色 | 說明 |
|------|---------|------|
| 無權限設定 | `#aaa` 灰色 | 公開資料 |
| 有權限設定 | `#faad14` 黃色 | 限制部分使用者可見 |

### 7.3 欄位遮罩

當 `_perm_assigned === true && _perm_authorized === false`：
- 業務負責人 → 顯示 `-`
- 最近互動 → 顯示 `-`
- 業務資訊區塊 → 隱藏

## 8. 衛服部資料更新

### 8.1 權限

僅 `admin` 或 `業務主管` 角色可見按鈕。

### 8.2 流程

```
點擊按鈕
  ├─ 背景執行中 → message.info('正在背景執行中…')
  └─ 空閒狀態 → 開啟確認 Modal
                  ├─ 顯示上次更新時間（localStorage）
                  ├─ 警告說明：下載 CSV、比對、新增、標記下架、更新狀態
                  ├─ 提示：背景執行，需數分鐘
                  └─ 確定 → 呼叫 API → 寫入 localStorage 時間
```

### 8.3 比對邏輯（規劃中，後端實作）

| 情境 | 處理 |
|------|------|
| 本地有、新 CSV 無 | 標記「可能已下架」 |
| 本地無、新 CSV 有 | 新增至資料庫 |
| 新 CSV 名稱模糊比對到 ERP/潛在客戶 | 更新狀態為既有客戶 |

**名稱比對策略（規劃）：**
- 第一關：正規化（移除前綴/後綴、臺→台） + Token 覆蓋率
- 第二關：Ollama embedding (`nomic-embed-text`) → cosine similarity threshold 0.85+

## 9. 機構分類自動分類

### 9.1 觸發時機

- 資料匯入時自動分類
- 可透過右鍵選單手動編輯

### 9.2 演算法

1. **關鍵字比對**（機構名稱）
   - 服務類型關鍵字：綜合式、居家式、社區式、住宿式
   - 機構屬性關鍵字：護理之家、長照、養護、安養…
   - 附設關係關鍵字：基金會、協會、合作社、醫院、財團法人…
   - 商業模式關鍵字：企業社、有限公司、實業、行號…
   - 其他：宗教、慈善、治療所、衛生所、客運…

2. **Category 映射**（業務王資料）
   - `社福團體` → 社福團體
   - `醫院/診所` → 醫院/診所
   - `政府單位` → 政府單位
   - `車商` → 車商
   - …（約 20 組映射）

3. **未分類處理**
   - 未命中任何規則 → 留空，可由使用者手動或後續 AI 補充

### 9.3 分類覆蓋率

截至 2026-06-13，32,490 筆客戶中 24,511 筆已分類（75.4%）。未分類主要為業務王個人帳號/測試記錄及少量衛福部邊緣案例。

## 10. 關注（Favorite）

### 10.1 儲存方式

localStorage `crm_favorites` key，JSON string array 儲存客戶 `_key`。

### 10.2 行為

- 表格最左欄 ★ 按鈕切換關注狀態
- 右鍵選單第一項切換關注
- 已關注客戶在表格中自動置頂

## 11. 響應式滾動

表格高度動態計算，透過 `ResizeObserver` 監聽容器尺寸變化：

```
tableScrollY = containerHeight - headerHeight - tabsHeight - paginationHeight - padding
pageSize = max(5, min(50, floor(tableScrollY / ROW_HEIGHT)))
```
