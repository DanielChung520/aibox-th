# EEA-CRM 聯絡人管理 規格書

## 1. 產品定位

### 1.1 功能目標

為業務員提供統一的客戶聯絡人管理中心，彙整三種來源的聯絡人資料，支援 **Grid（虛擬名片）** 與 **List（縮圖列表）** 兩種檢視模式。

### 1.2 目標用戶

| 角色 | 權限範圍 | 主要場景 |
|------|---------|---------|
| 一般業務員 | 僅見自己被指派的聯絡人 | 管理個人客戶通訊錄、查看名片、發送 LINE 訊息 |
| 業務主管 | 所屬團隊的聯絡人 + 可指派 | 指派聯絡人給下屬、盤點團隊客戶覆蓋 |
| 系統管理員 | 全部 | 維護、除錯、批量操作 |

### 1.3 三種資料來源

```
┌─────────────────────────────────────────────────────────┐
│                    EEA-CRM 聯絡人管理                      │
├─────────────┬─────────────────┬─────────────────────────┤
│  ① LINE 名片  │  ② 手動維護      │  ③ 公司/主管指派           │
│             │                 │                         │
│  LINE OA     │  業務員自行      │  主管在系統中              │
│  客戶傳名片   │  新增/編輯/刪除   │  指派聯絡人給業務員         │
│  或業務拍照  │  (CRUD)         │  (assign API)           │
│             │                 │                         │
│  → LINE Agent │  → ContactForm │  → Assignment Modal      │
│  (未來獨立開發) │  (本規格範圍)   │  (本規格範圍)              │
└─────────────┴─────────────────┴─────────────────────────┘
```

> **關於 LINE**：LINE 資料收集將由後續獨立開發的 **LINE Agent** 負責，本規格已在資料模型中預留 LINE 相關欄位，Agent 完成後可直接寫入 `crm_contacts` collection，前端無須大幅改動。

#### 欄位說明

| 欄位 | 類型 | 必填 | 說明 |
|------|------|------|------|
| `customer_key` | string | N | 所屬機構 PK。null = 獨立聯絡人 |
| `name_cn` | string | N | 中文姓名 |
| `name_en` | string | N | 英文姓名 |
| `titles` | array | N | `[{title, department?, is_primary?}]` 職稱列表 |
| `phones` | array | N | `[{number, code?, type?, is_primary?}]` 電話列表，type: mobile/office/fax/other |
| `emails` | array | N | `[{address, type?, is_primary?}]` Email 列表 |
| `social_accounts` | array | N | `[{platform, account, label?, is_primary?}]` 社群帳號列表 |
| `organizations` | array | N | `[{name, title?, is_primary?}]` 公司/組織列表 |
| `notes` | string | N | 備註 |
| `card_images` | array | N | `[{url, side}]` 名片圖檔，side: front/back |
| `avatar_url` | string | N | 自訂頭像 URL |
| `line_uid` | string | N | LINE User ID |
| `line_status` | enum | N | `connected` / `disconnected` / `expired` / `none` |
| `source` | enum | Y | 資料來源 |
| `source_detail` | object | N | 來源 metadata |
| `is_primary` | bool | N | 是否為該機構主要聯絡人 |
| `owner_key` | string | Y | 歸屬業務員 user `_key` |
| `assigned_by` | string | N | 指派者 user `_key` |
| `assigned_at` | string | N | 指派時間 |

#### 索引設計

```javascript
{ type: "persistent", fields: ["owner_key", "source"] }
{ type: "persistent", fields: ["customer_key"] }
{ type: "persistent", fields: ["line_uid"] }
{ type: "persistent", fields: ["line_status"] }
```

### 2.2 與 `crm_customers` 的關係

```
crm_customers (機構)
    │ 1
    │
    │ N
crm_contacts (聯絡人)
```

- 一個機構可以有多個聯絡人（N 對 1）
- 聯絡人可以不屬於任何機構（`customer_key = null`）
- `is_primary = true` 的聯絡人是機構的主要窗口

## 3. API 設計

### 3.1 Rust API Gateway (`api/src/api/crm.rs` 擴充)

#### 路由

| 方法 | 路徑 | 說明 |
|------|------|------|
| `GET` | `/api/v1/crm/contacts` | 列表 + 搜尋 + 篩選 |
| `POST` | `/api/v1/crm/contacts` | 新增聯絡人 |
| `GET` | `/api/v1/crm/contacts/{key}` | 單筆詳情 |
| `PATCH` | `/api/v1/crm/contacts/{key}` | 更新聯絡人 |
| `DELETE` | `/api/v1/crm/contacts/{key}` | 刪除聯絡人 |
| `GET` | `/api/v1/crm/contacts/by-customer/{customer_key}` | 依機構查詢聯絡人 |
| `POST` | `/api/v1/crm/contacts/assign` | 指派聯絡人給業務員 |
| `POST` | `/api/v1/crm/contacts/{key}/set-primary` | 設為主要聯絡人 |

#### 查詢參數 (`GET /api/v1/crm/contacts`)

| 參數 | 類型 | 說明 |
|------|------|------|
| `q` | string | 全文搜尋（name / phone / email / title） |
| `source` | string | 來源篩選 |
| `line_status` | string | LINE 狀態篩選 |
| `customer_key` | string | 所屬機構篩選 |
| `owner_key` | string | 業務員篩選（預設當前 user） |
| `is_primary` | boolean | 僅主要聯絡人 |
| `page` | number | 頁碼（預設 1） |
| `page_size` | number | 每頁筆數（預設 20，最大 100） |

#### 回應格式

```json
{
  "code": 200,
  "data": [
    {
      "_key": "uuid",
      "name": "張淑芬",
      "title": "院長",
      "phone": "0912-345-678",
      "email": "sfchang@sunny.com",
      "source": "manual",
      "line_status": "connected",
      "is_primary": true,
      "customer_name": "陽光老人養護中心",
      "avatar_url": null,
      "line_picture_url": null,
      "created_at": "2026-06-13T00:00:00Z"
    }
  ],
  "pagination": {
    "page": 1,
    "page_size": 20,
    "total": 42,
    "total_pages": 3
  }
}
```

#### 權限邏輯

```rust
// 一般業務員：只看到自己的聯絡人
FILTER c.owner_key == @current_user_key

// 業務主管：可看 team + 可指派
// 沿用現有 crm_customer_permissions 或 role check

// 管理員：全部
```

### 3.2 前端 API 層 (`src/services/api.ts` 擴充)

```typescript
export const crmApi = {
  // 既有 customer API...

  // --- 聯絡人 API ---
  listContacts: (params?: ContactListParams) =>
    api.get<CRMContactListResponse>('/api/v1/crm/contacts', { params }),

  createContact: (data: CreateContactPayload) =>
    api.post('/api/v1/crm/contacts', data),

  getContact: (key: string) =>
    api.get(`/api/v1/crm/contacts/${key}`),

  updateContact: (key: string, data: Partial<UpdateContactPayload>) =>
    api.patch(`/api/v1/crm/contacts/${key}`, data),

  deleteContact: (key: string) =>
    api.delete(`/api/v1/crm/contacts/${key}`),

  listContactsByCustomer: (customerKey: string) =>
    api.get(`/api/v1/crm/contacts/by-customer/${customerKey}`),

  assignContact: (key: string, ownerKey: string) =>
    api.post('/api/v1/crm/contacts/assign', { key, owner_key: ownerKey }),

  setPrimaryContact: (key: string) =>
    api.post(`/api/v1/crm/contacts/${key}/set-primary`),
};
```

### 4.2 Grid 模式 — 緊湊式名片卡片

每張卡片 240px 寬，**點擊後右側 Drawer 顯示完整明細**。

```
┌──────────────────────┐
│ 📇        ⭐         │
│  ┌──────┐            │
│  │ initials │        │
│  │ 頭像   │  張淑芬    │  ← 頭像 + 中文姓名
│  └──────┘  Shu-Fen.. │  ← 英文姓名
│              院長     │  ← 主要職稱
│  ────────────────    │
│  📞 +886 0912-345..  │  ← 主要電話
│  ✉️ sfchang@sunny..  │  ← 主要 Email
│  🏢 陽光老人養護中心   │  ← 主要組織
│                      │
│  [🟢 連線中]          │  ← LINE 狀態標籤
│  [主要] [✏️] [✉️]     │  ← 標籤 + 操作按鈕
└──────────────────────┘
```

**卡片規格**：
- 寬度：240px
- 頭像：50x50px 圓形漸層
- 僅顯示主要（primary）資料：第一個職稱、電話、Email、組織
- 📇 徽章 = 有名片圖檔，⭐ = 主要聯絡人
- 點擊卡片 → 開啟右側 ContactDetailDrawer（完整欄位）
