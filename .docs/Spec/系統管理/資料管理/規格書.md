## 1. 定位與範圍

### 1.1 功能定位

系統資料管理涵蓋兩大職責：

1. **SeaweedFS 儲存管理** — 統一管理所有應用層寫入 SeaweedFS 的檔案路徑、Bucket 分類、容量監控與檔案瀏覽
2. **資料備份管理** — ArangoDB / Qdrant / SeaweedFS Volume 的備份、排程、還原（與原有 `專案db備份管理` 整合）

### 1.2 系統架構位置

```
系統設置 (SystemParams.tsx)
  ├── 系統資料管理 (SystemDataManagement.tsx) ← 本規格書
  │     ├── Bucket 總覽（Filer 根目錄）
  │     ├── 知識庫文件 (/bucket-aibox-assets/)
  │     ├── 智慧報表 (/reports/)
  │     ├── LINE 多媒體 (/line-media/)
  │     └── 上傳/下載/刪除
  │
  └── 備份管理 (BackupManager.tsx) ← 既有規格書
        ├── ArangoDB 備份
        ├── Qdrant 快照
        └── SeaweedFS Volume 備份（新增）
```

## 2. 現狀盤點：SeaweedFS 路徑硬編碼

### 2.1 環境變數混亂

目前程式碼中使用了 **3 種不同的環境變數名稱** 指向 SeaweedFS：

| 變數名 | 使用檔案 | 預設值 |
|--------|---------|--------|
| `SEAWEEDFS_URL` | `shared/multimedia.py`, `shared/conversation/archiver.py`, `tools/report_generator/*`, `tools/report_agent/*` | `http://localhost:8888` |
| `SEAWEED_URL` | `tools/multimedia_analyzer/router.py`, `unified_agents/main.py` | `http://localhost:8888` |
| `SEAWEED_AIBOX_URL` | `api/src/config.rs`, `api/src/api/knowledge.rs`, `api/src/services/chat/*.rs`, `knowledge_agent/routers/pipeline.py` | `http://localhost:8888` |
| 硬編碼（無變數） | `api/src/api/mod.rs` L240 (`filer_proxy`) | `http://localhost:8888`（寫死） |

### 2.2 路徑規則不統一

| # | 路徑模式 | 使用位置 | 用途 |
|---|---------|---------|------|
| A | `/buckets/{platform}_media/{user_id}/...` | `shared/multimedia.py` | LINE 多媒體備份 |
| B | `{platform}/{user_id}/...`（無 bucket） | `tools/multimedia_analyzer/router.py` | 多媒體分析（重複實作） |
| C | `/buckets/bot_chat_archive/{platform}/...` | `shared/conversation/archiver.py` | 聊天記錄歸檔 |
| D | `/buckets/bucket-ai-box-assets/user_{user}/reports/...` | `tools/report_generator/*` | HTML 報表 |
| E | `/buckets/user_{user}/reports/...` | `tools/report_agent/*` | HTML 報表（不同元件） |
| F | `bucket-aibox-assets/{root_id}/{file_key}.{ext}`（無前綴 /） | Rust `knowledge.rs` | 知識庫檔案 |
| G | `bucket-aibox-assets/sessions/{session_key}/...` | Rust `chat/files.rs` | 對話附件 |
| H | `bucket-aibox-assets/action-trail/{account}/{date}/...` | Rust `action_trail.rs` | 使用者操作足跡 |
| I | 無路徑，全代理 | Rust `filer_proxy` | 前端 Filer 代理（任意寫入） |

### 2.3 其他問題

| 問題 | 說明 |
|:-----|:------|
| 重複實作 | `tools/multimedia_analyzer/router.py` 自有一套 `upload_to_seaweedfs()`，與 `shared/multimedia.py` 重複 |
| 缺少認證 | `shared/multimedia.py` 上傳無任何 auth，而 Rust 端用 `basic_auth` |
| 硬編碼憑證 | `tools/multimedia_analyzer/router.py` 寫死 `admin:admin123` |
| 不一致的 Method | 有的用 `POST multipart`，有的用 `PUT raw`，有的用 `GET-then-PUT` |
| 不一致的檔名規則 | 有的含 uuid，有的不含，有的用 timestamp 前綴 |

## 3. 目標架構

### 3.1 統一環境變數

收斂為單一環境變數：

```bash
# .env
SEAWEEDFS_URL=http://localhost:8888
PUBLIC_SEAWEED_URL=https://eeas3.ent4i.com
SEAWEEDFS_USER=admin
SEAWEEDFS_PASS=your-password
```

所有程式碼統一讀取 `shared.seaweedfs.get_config()`，不再各自讀 env。

### 3.2 統一寫入路徑規則

```python
# shared/seaweedfs.py
BUCKET_PATHS = {
    "knowledge":      "/bucket-aibox-assets/kb_welfare_iso/",
    "knowledge_other":"/bucket-aibox-assets/{root_id}/",
    "chat_sessions":  "/bucket-aibox-assets/sessions/{session_key}/",
    "action_trail":   "/bucket-aibox-assets/action-trail/{account}/{date}/",
    "reports":        "/reports/{username}/{filename}",
    "line_media":     "/line-media/{channel_key}/{date}_{uuid}_{filename}",
    "wecom_media":    "/wecom-media/{business_user_key}/{date}_{uuid}_{filename}",
    "whatsapp_media": "/whatsapp-media/{business_user_key}/{date}_{uuid}_{filename}",
    "dingtalk_media": "/dingtalk-media/{business_user_key}/{date}_{uuid}_{filename}",
    "plugin_storage": "/plugins/{plugin_key}/{filename}",
    "chat_archive":   "/buckets/bot_chat_archive/{platform}/{date}/",
    "backup_temp":    "/backup/{date}/{filename}",
}
```

所有寫入透過 `shared.seaweedfs.upload(bucket, filename, content, **params)` 單一進入點。

### 3.3 統一上傳函式

```python
# shared/seaweedfs.py
async def upload(bucket: str, filename: str, content: bytes,
                 mime_type: str = "application/octet-stream",
                 **kwargs) -> str:
    """
    統一的 SeaweedFS 寫入介面。

    Args:
        bucket: BUCKET_PATHS 的 key（knowledge / reports / line_media / ...）
        filename: 原始檔名
        content: 檔案內容
        mime_type: MIME type
        **kwargs: 路徑模板參數（root_id, channel_key, session_key, ...）

    Returns:
        完整 URL（可公開存取）
    """
    path_template = BUCKET_PATHS[bucket]
    full_path = path_template.format(**kwargs) + filename
    # POST multipart to SeaweedFS Filer
    ...
    return f"{PUBLIC_SEAWEED_URL}{full_path}"
```

## 5. 跨平台通訊媒體儲存

### 5.1 路徑規則

不同通訊平台的媒體檔統一儲存格式：

```
/line-media/{business_user_key}/{date}_{uuid8}_{filename}
/wecom-media/{business_user_key}/{date}_{uuid8}_{filename}
/whatsapp-media/{business_user_key}/{date}_{uuid8}_{filename}
```

### 5.2 實作方式

由 `line_media_handler` / `wecom_media_handler` 等 skill 呼叫 `shared.seaweedfs.upload()`：

```python
url = await upload(
    bucket="line_media",
    filename="20260621_abc123_image.jpg",
    content=image_bytes,
    mime_type="image/jpeg",
    channel_key="ch_1bb039dd",
    # 自動產生路徑: /line-media/ch_1bb039dd/20260621_abc123_image.jpg
)
```

## 6. 備份策略（整合既有 + SeaweedFS Volume）

### 6.1 現有備份管理

既有 `專案db備份管理/規格書.md` 已規劃 ArangoDB + Qdrant 的備份。本規格書新增 **SeaweedFS Volume 備份**。

### 6.2 SeaweedFS 備份方式

SeaweedFS 的備份不需要透過 API，直接備份 Volume Server 的磁碟目錄即可：

```bash
# 方式一：rsync 到 NAS（建議）
rsync -avz /data/seaweed/volumes/ user@nas:/backup/seaweedfs/volumes/

# 方式二：tar 壓縮備份到指定目錄
tar czf /backup/seaweedfs/volumes_$(date +%Y%m%d).tar.gz /data/seaweed/volumes/
```

### 6.3 備份排程建議

| 資料 | 方式 | 頻率 | 保留 |
|:-----|:-----|:-----|:-----|
| ArangoDB | `arangodump` | 每日 02:00 | 7 天 |
| Qdrant | Snapshot API | 每週日 03:00 | 4 週 |
| SeaweedFS Volume | rsync / tar | 每日 04:00 | 30 天 |
| SeaweedFS + ArangoDB + Qdrant | 整機備份 | 每月 1 日 | 12 個月 |

### 6.4 還原流程

```bash
# 還原 SeaweedFS
rsync -avz user@nas:/backup/seaweedfs/volumes/ /data/seaweed/volumes/
# 重啟 SeaweedFS
docker restart seaweedfs
```

### 6.5 儲存容器管理（新增功能建議）

| 功能 | 說明 | 實作難度 |
|:-----|:------|:---------|
| 備份磁碟設定 | 在 UI 設定備份目標路徑（本機 / NAS） | 🟡 中 |
| 排程設定 | 選擇備份頻率、時間、保留份數 | 🟢 低 |
| 手動執行備份 | 一鍵執行各資料庫備份 | 🟢 低 |
| 備份歷史列表 | 顯示所有備份檔、大小、狀態 | 🟢 低 |
| 還原操作 | 選擇備份檔進行還原（需二次確認） | 🟡 中 |
| 磁碟用量監控 | 顯示各儲存位置的使用量 | 🟡 中 |
