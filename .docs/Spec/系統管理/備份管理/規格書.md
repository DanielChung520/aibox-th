## 1. 定位與範圍

### 1.1 功能定位

資料備份管理是系統設置下的子功能頁面，提供 ArangoDB 和 Qdrant 兩大核心資料庫的備份與還原功能，並支援自訂備份策略。

### 1.2 支援範圍

| 資料庫 | 備份方式 | 還原方式 | 策略支援 |
|--------|---------|---------|---------|
| ArangoDB | Volume Snapshot / arangobackup | tar 解壓還原 | 每日/每週/手動 |
| Qdrant | Collection Snapshot API | Snapshot Restore API | 每日/每週/手動 |

### 1.3 系統架構位置

```
系統設置 (SystemParams.tsx)
    └── 備份設置 (BackupManager Tab)
            ├── ArangoDB 備份管理
            ├── Qdrant 備份管理
            └── 備份策略配置
```

## 3. API 規格

### 3.1 後端 Service

新建 `backup_agent/` service，port 8010：

```
ai-services/
└── backup_agent/
        ├── __init__.py
        ├── main.py          # FastAPI app
        ├── routers/
        │   ├── __init__.py
        │   └── backup.py    # 備份/還原端點
        ├── services/
        │   ├── __init__.py
        │   ├── arangodb_backup.py
        │   └── qdrant_backup.py
        └── models.py        # Pydantic models
```

### 3.2 端點清單

| 方法 | 路徑 | 說明 |
|------|------|------|
| `POST` | `/backup/arangodb` | 執行 ArangoDB 備份 |
| `POST` | `/backup/arangodb/restore` | 還原 ArangoDB |
| `GET` | `/backup/arangodb/history` | 取得 ArangoDB 備份歷史 |
| `DELETE` | `/backup/arangodb/{backup_id}` | 刪除 ArangoDB 備份 |
| `POST` | `/backup/qdrant` | 執行 Qdrant 快照備份 |
| `POST` | `/backup/qdrant/restore` | 還原 Qdrant |
| `GET` | `/backup/qdrant/history` | 取得 Qdrant 快照歷史 |
| `DELETE` | `/backup/qdrant/{snapshot_id}` | 刪除 Qdrant 快照 |
| `GET` | `/backup/status` | 磁碟使用狀態 |

## 4. 備份技術方案

### 4.1 ArangoDB 備份

**原理**：直接複製 Docker Volume 到指定目錄

```python
async def backup_arangodb(backup_path: str, retention: int) -> BackupResult:
    volume_name = "aibox_arango-data"  # 從 system-params 或 docker inspect 取得
    container = get_docker_container("arangodb")
    
    # 熱備份：從容器內執行 foxx 匯出
    # 或冷備份：複製 volume（需短暫停寫）
    
    backup_file = f"{backup_path}/arangodb_{timestamp}.tar.gz"
    
    # Docker volume → 本地檔案
    subprocess.run([
        "docker", "run", "--rm",
        "-v", f"{volume_name}:/src",
        "-v", f"{os.path.dirname(backup_file)}:/dst",
        "alpine",
        "tar", "czf", f"/dst/{os.path.basename(backup_file)}", "-C", "/src", "."
    ])
    
    return BackupResult(backup_id=..., backup_file=backup_file, ...)
```

### 4.2 Qdrant 備份

**原理**：使用 Qdrant Snapshot API

```python
async def backup_qdrant(backup_path: str, collections: list[str]) -> BackupResult:
    base_url = "http://localhost:6333"
    
    # 1. 為每個 collection 建立 snapshot
    for collection in collections:
        r = await httpx.post(
            f"{base_url}/collections/{collection}/snapshots"
        )
        snapshot_name = r.json()["result"]["name"]
        
        # 2. 下載 snapshot
        r2 = await httpx.get(
            f"{base_url}/collections/{collection}/snapshots/{snapshot_name}"
        )
        save_snapshot(r2.content, f"{backup_path}/{collection}_{snapshot_name}")
    
    return BackupResult(...)
```

### 4.3 自動清理策略

每次備份完成後，根據 `retention` 參數刪除過舊的備份：

```python
def cleanup_old_backups(backup_path: str, retention: int):
    backups = sorted(Path(backup_path).glob("*.tar.gz"), key=lambda p: p.stat().st_mtime)
    for old in backups[:-retention]:
        old.unlink()
```

## 5. 備份策略

### 5.1 策略類型

| 策略 | 說明 | 預設 |
|------|------|------|
| `manual` | 手動備份，點擊執行 | ✅ |
| `daily` | 每日凌晨執行（可設定時間） | 凌晨 2:00 |
| `weekly` | 每週日凌晨執行 | 週日 凌晨 3:00 |

### 5.2 排程實作

使用 Celery Beat 或系統 cron job 觸發備份：

```python
# celery_app.py
from celery import Celery
from celery.schedules import crontab

app = Celery('backup_tasks')
app.conf.beat_schedule = {
    'arangodb-daily-backup': {
        'task': 'backup_agent.tasks.arangodb_backup',
        'schedule': crontab(hour=2, minute=0),
        'args': ('~/Documents/backups/arangodb', 7),
    },
    'qdrant-weekly-backup': {
        'task': 'backup_agent.tasks.qdrant_backup',
        'schedule': crontab(hour=3, minute=0, day_of_week=0),
        'args': ('~/Documents/backups/qdrant', 4),
    },
}
```

### 5.3 系統參數

| 參數 Key | 說明 | 預設值 |
|---------|------|--------|
| `backup.arangodb.enabled` | 啟用 ArangoDB 備份 | `true` |
| `backup.arangodb.path` | ArangoDB 備份路徑 | `~/Documents/backups/arangodb` |
| `backup.arangodb.strategy` | 備份策略 | `daily` |
| `backup.arangodb.retention` | 保留份數 | `7` |
| `backup.arangodb.schedule_time` | 排程時間 | `02:00` |
| `backup.qdrant.enabled` | 啟用 Qdrant 備份 | `true` |
| `backup.qdrant.path` | Qdrant 備份路徑 | `~/Documents/backups/qdrant` |
| `backup.qdrant.strategy` | 備份策略 | `weekly` |
| `backup.qdrant.retention` | 保留份數 | `4` |
| `backup.qdrant.schedule_time` | 排程時間 | `03:00` |

## 7. 錯誤處理

| 錯誤碼 | 說明 | 處理 |
|--------|------|------|
| `BACKUP_PATH_NOT_FOUND` | 備份路徑不存在 | 自動建立目錄 |
| `BACKUP_PATH_NO_SPACE` | 磁碟空間不足 | 回傳警告，建議清理 |
| `ARANGO_NOT_RUNNING` | ArangoDB 未執行 | 提示啟動服務 |
| `QDRANT_NOT_RUNNING` | Qdrant 未執行 | 提示啟動服務 |
| `RESTORE_FAILED` | 還原失敗 | 回滾，保留原資料 |
| `BACKUP_TIMEOUT` | 備份超時（>30min） | 終止並報告 |

## 10. 安全性考量

| 項目 | 說明 |
|------|------|
| 還原前確認 | 所有還原操作需二次確認 Modal |
| 覆寫風險 | 還原時顯示覆寫警告，確認後執行 |
| 路徑驗證 | 備份路徑必須為絕對路徑，不允許 `../` 跳脫 |
| 權限檢查 | 備份目錄需有寫入權限 |
| 空間檢查 | 備份前檢查磁碟空間，預留 20% buffer |
