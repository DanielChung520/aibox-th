# 客戶 Timeline 活動整理 — Ragic 摘要腳本

## 說明

6 張 Ragic 表的輪巡與 Timeline 寫入規則。每張表定義：
- **客戶比對欄位**：用哪個欄位匹配 `crm_contacts`
- **event_type**：寫入 `customer_timelines.events[].event_type`
- **摘要模板**：summary 的組成方式
- **日期欄位**：用於排序與 timeline 時間戳

---

## 表 1：報價分析（order-operation/11）

| 項目 | 內容 |
|------|------|
| **event_type** | `quote_analysis` |
| **客戶比對** | `客戶全稱`（主要）、`客戶編號`（輔助） |
| **日期欄位** | `訂購單日期` |
| **摘要模板** | `報價#{訂購單編號} {客戶全稱} — {狀態}` |
| **備註** | 含 Approval 流程狀態（Approval status） |

**腳本邏輯：**
```python
summary = f"報價#{row['訂購單編號']} {row['客戶全稱']} — {row['狀態']}"
if row.get('未稅合計'):
    summary += f" ${row['未稅合計']}"
```

## 表 4：詢價憑單（order-operation/32）

| 項目 | 內容 |
|------|------|
| **event_type** | `inquiry_sent` |
| **客戶比對** | ❌ 無直接客戶名稱欄位（僅有 `請購人員`、`請購部門`） |
| **日期欄位** | `請購日期` |
| **摘要模板** | `詢價#{請購單號} — {請購人員} ({請購部門}) — {單況}` |
| **備註** | 缺乏客戶名稱，需透過請購人員反查 |

**客戶比對策略：**
此表無直接客戶欄位。若有業務上的對應關係，可透過 `請購人員` → 查詢 CRM → 找出該業務負責的客戶。否則僅記為內部活動，不關聯客戶 timeline。

```python
# 若無法比對客戶，可選擇性寫入或跳過
if customer_id:
    summary = f"詢價#{row['請購單號']} — {row['請購人員']} — {row['單況']}"
else:
    skip  # 不寫入 customer_timelines
```

## 注意事項

1. **詢價憑單（表4）** 無客戶名稱欄位，建議跳過不寫入 timeline，或等業務確認對應關係後再啟用
2. **欄位名稱**以 Ragic API 回傳的 EID 為準（上述為中文顯示名稱，實際 API 欄位 ID 需查 schema）
3. **增量檢查**：每筆記錄以 `單據號碼` 作為 `ref_key`，比對 `customer_timelines.events[].ref_key`，避免重複寫入
4. **日期格式**：Ragic 回傳的日期需轉為 ISO 8601 後存入 `timestamp`
