# 需求提交與審查規格書

## 概述
使用者在智能體市集編輯 Agent 時，可透過「需求」Tab 填寫並提交開發需求。系統透過 AI 審查需求的完整性、合理性與可行性，審查通過後需求成立（qualified），自動建立需求看板紀錄。

需求支援**版本管理**：已成立的需求可發起變更（建立新版），或撤銷（開發前）。若需求已進入開發階段，撤銷將被阻擋，僅能變更。

## 兩層狀態機

### Level 1 — Demand（需求文件生命週期）

```
┌────────┐    ┌─────────┐    ┌──────────┐    ┌────────┐
│ draft  │───→│submitted│───→│ qualified│───→│ online │
└───┬────┘    └─────────┘    └─────┬────┘    └────────┘
    │                              │
    │                              ├── withdraw (開發前) → cancelled
    │                              ├── change → 建立新版 draft
    │                              └── (Kanban completed) → online
    │
    └── reactivate ←───── cancelled
```

| 狀態 | 意義 | 表單可編輯？ | 看板顯示？ |
|------|------|:----------:|:---------:|
| `draft` | 正在撰寫中 | ✅ | ❌ |
| `submitted` | 已提交，等待 AI 判定 | ❌ | ❌ |
| `qualified` | **需求成立**，可被開發者接單 | ❌ | ✅ pending_accept |
| `online` | 已上線 | ❌ | ✅ 標示已上線 |
| `cancelled` | 已撤銷（開發前） | ❌ | ❌ |
| `superseded` | 被新版取代（歷史版本） | ❌ | ❌ 不顯示 |

### Level 2 — Kanban（開發執行追蹤）

```
pending_accept → accepted → analyzing → spec_ready → in_development → completed
                      ↓                          ↑
                analyze_failed ── retry ──────┘
```

僅在 Demand 達到 `qualified` 時啟動。詳細說明見 [02-需求看板](./02-需求看板.md)。

## 流程

### 提交流程（Submit）

```mermaid
graph TD
    A[DemandTab - 需求 Tab] --> B{status = draft?}
    B -->|是| C[編輯需求表單]
    C --> D[點擊「提交需求」]
    D --> E[POST /api/v1/demands/review]
    E --> F{Ollama AI 審查}
    F --> G[顯示審查結果 Modal]
    G --> H{評分 >= 70?}
    H -->|是| I[確認提交]
    H -->|否| J[阻止提交，顯示 AI 建議]
    I --> K[POST /api/v1/demands/{key}/submit]
    K --> L[status: submitted]
    L --> M[等待後端判審]
    M --> N[POST /api/v1/demands/{key}/qualify]
    N --> O[status: qualified]
    O --> P[自動建立 agent_requirements 看板記錄]
```

**變更點（v1.0 → v2.0）：**
- 不再由前端 `fetch` 建立看板記錄 → 改由後端 `qualify` handler 自動建立
- 新增 `submit` + `qualify` 兩個階段（原本一次到位）
- 看板記錄建立失敗不影響 demand 狀態（原子性後續補強）

### 變更流程（Change）

```mermaid
graph TD
    A[qualified / online 狀態] --> B[點擊「變更需求」]
    B --> C[輸入變更原因]
    C --> D[POST /api/v1/demands/{key}/change]
    D --> E[建立新版需求 v2.0]
    E --> F[status: draft]
    F --> G[supersedes: v1.0]
    G --> H[舊版不變，仍為 qualified/online]
    H --> I[使用者編輯新版 → 提交 → 審查]
    I --> J{新版 qualified?}
    J -->|是| K[舊版自動 → superseded]
    J -->|否| L[退回 draft，舊版不受影響]
    K --> M[新版自動建立看板記錄]
```

**規則：**
- 變更時**舊版保持原狀態**，開發中的團隊不受影響
- 新版 `qualified` 後，舊版才標為 `superseded`
- 若新版未通過審查，退回 draft 修改，舊版持續有效

### 撤銷流程（Withdraw）

```mermaid
graph TD
    A[submitted / qualified] --> B[點擊「撤銷需求」]
    B --> C[POST /api/v1/demands/{key}/withdraw]
    C --> D{需求已開發？}
    D -->|是 - 看板 in_development 或 completed| E[❌ 阻擋撤銷]
    D -->|否| F[status → cancelled]
    E --> G[提示：需求已開發，請使用「變更需求」]
```

**撤銷檢查條件：**
查詢對應的 `agent_requirements` 看板記錄，若 `status IN ['in_development', 'completed']`，則阻擋撤銷。

## AI 審查

### 呼叫方式
```
POST /api/v1/demands/review
```

### 使用模型
`qwen3-coder:30b`（Ollama `/api/generate`，temperature=0.3）

### 審查輸出

| 欄位 | 說明 |
|------|------|
| completeness | 需求完整性評估 |
| reasonableness | 合理性評估 |
| feasibility | 可行性評估 |
| estimated_hours | 預估總工時 |
| hour_breakdown | 工時明細：consulting / development / testing / review |
| confidence | 估計信心（low/medium/high） |
| summary | 需求摘要 |
| suggestions | 改進建議（陣列） |
| score | 綜合評分（0-100） |

### 評分門檻
- **≥ 70 分**：可提交
- **< 70 分**：阻止提交，顯示 AI 建議

## 版本管理

### 版號規則
- 格式：`v{major}.{minor}`（如 v1.0, v2.0, v3.0）
- 初始建立：v1.0
- 每次變更：minor + 1（v1.0 → v2.0 → v3.0）
- 版號唯一性：同一 agent 下不重複

### 版本連結欄位

| 欄位 | 所在 Document | 說明 |
|------|--------------|------|
| `version` | agent_demands | 當前版本號 |
| `supersedes` | agent_demands | 從哪個 demand key 變更來的 |
| `superseded_by` | agent_demands | 被哪個 demand key 取代 |
| `change_reason` | agent_demands | 變更原因 |
| `change_history` | agent_demands | `[{from_version, to_version, changed_at, actor, reason}]` |

### 狀態與版本互動

```
v1.0 draft → submitted → qualified (看板出現)
                               │
                    ┌──────────┘
                    │ 使用者發起變更
                    ▼
v1.0 qualified ─── (保持不變)
v2.0 draft ─────── 開始編輯
                    │
                    ▼
v2.0 qualified ───→ v1.0 → superseded (自動)
                    │
                    ▼
            v2.0 看板記錄建立
```

## 狀態流轉表（Formal Transition Table）

| 當前狀態 | 事件 | 下一狀態 | 條件 / 備註 |
|---------|------|---------|------------|
| draft | submit | submitted | 需通過 AI 審查（score ≥ 70） |
| submitted | qualify | qualified | 系統判定合格，自動建立看板記錄 |
| submitted | withdraw | cancelled | 使用者主動撤回 |
| qualified | withdraw | cancelled | 須檢查看板，若 `in_development/completed` 則阻擋 |
| qualified | change | draft (v2.0) | 建立新版，舊版保持 qualified |
| qualified | （看板 completed） | online | 看板開發完成時自動觸發 |
| online | change | draft (v2.0) | 建立新版，舊版保持 online |
| cancelled | reactivate | draft | 重新開啟（同版本，非新版） |
| qualified(v2) | （自動） | superseded | 作用於 v1.0：當 v2.0 qualified 時 |

## 檔案上傳

```
PUT /demands/{agentKey}/{demandKey}/documents/{filename}
PUT /demands/{agentKey}/{demandKey}/images/{filename}
```
