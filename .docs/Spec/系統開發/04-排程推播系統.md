# 排程推播系統 — Skill 規格書

## 概述

排程推播系統（Scheduled Push Engine）是福祉業務小秘的核心元件之一，負責**以逐一推送（Push）取代廣播（Broadcast）**的方式，實現可個人化、可追蹤、可排程的大量訊息發送。

### 為什麼不用 Broadcast

| 方式 | LINE API 限制 | 個人化 | 送達追蹤 | 中斷續傳 |
|:----:|:-------------:|:------:|:--------:|:--------:|
| Broadcast | 60次/hour | ❌ | ❌ 僅總數 | ❌ |
| Narrowcast | 60次/hour | ❌ 僅群體模板 | ❌ | ❌ |
| Multicast | 200次/秒（2025/4降速） | ⚠️ 有限 | ❌ | ❌ |
| **Push × N** | **2,000次/秒** | ✅ 逐筆可不同 | ✅ 逐筆記錄 | ✅ |

Broadcast 每小時只能發 60 次，而且同一則訊息發給所有人，無法區分客戶、無法個人化、無法追蹤個別送達狀態。改用 Push 逐筆發送，完全避開這些限制。

## 系統架構

```
業務/排程觸發
    │
    ▼
┌─────────────────────┐
│  broadcast_tasks     │  ← 任務定義（誰、什麼、何時）
│  (ArangoDB 集合)     │
└────────┬────────────┘
         │ scheduler.py 輪詢
         ▼
┌─────────────────────┐
│  Push Engine         │  ← 核心引擎
│                      │
│  1. 讀取任務目標清單  │
│  2. 套用個人化模板    │
│  3. Rate Limiter     │
│  4. 逐筆 push 發送   │
│  5. 記錄送達狀態      │
└────────┬────────────┘
         │
         ├── LINE Messaging API (push)
         │     2,000 req/sec
         │
         ▼
┌─────────────────────┐
│  broadcast_recipients│  ← 逐筆送達記錄
│  (ArangoDB 集合)     │
└─────────────────────┘
```

## 模組設計

### scheduler.py — 排程引擎

```
scheduler.py
├── poll_loop()
│   └── 每 30 秒掃描 broadcast_tasks
│       ├── status == 'scheduled' AND scheduled_at ≦ now
│       │   └── → status = 'running' → 交付 Push Engine
│       └── status == 'running' AND 上次中斷
│           └── → 續傳（從 last_index 繼續）
│
├── handle_recurring()
│   └── 處理週期性任務（每日早安問候）
│       └── 讀取 greeting_templates → 建立 broadcast_task
│
└── cleanup()
    └── 清理超過 30 天的歷史記錄
```

**檔案位置**：`ai-services/bpa/welfare_secretary/scheduler.py`

### push_engine.py — 推送核心

```
push_engine.py
├── execute_task(task)
│   ├── 讀取 target_customers（from CRM / 分群條件）
│   ├── 逐筆生成個人化內容
│   ├── rate_limiter.acquire() → LINE push API
│   ├── 寫入 broadcast_recipients
│   └── 更新 task progress
│
├── personalizer(content_template, customer)
│   ├── 取代 {{customer_name}}、{{visit_date}} 等變數
│   └── 支援 Liquid-like 模板語法
│
└── rate_limiter
    ├── token bucket: 每秒最多 20 筆（安全預設）
    └── 可透過 system_params 調整
```

**檔案位置**：`ai-services/bpa/welfare_secretary/push_engine.py`

## 資料模型

### broadcast_tasks（任務定義）

```json
{
  "_key": "uuid",
  "title": "2026-06-15 早安問候",
  "status": "scheduled | running | paused | completed | failed | cancelled",
  "task_type": "one_time | recurring",
  "schedule_cron": "0 8 * * *",
  "scheduled_at": "2026-06-15T08:00:00Z",
  "started_at": null,
  "completed_at": null,
  "target_source": "crm_query | manual_list",
  "target_query": {
    "filter": { "tags": { "$contains": "vip" }, "status": "active" },
    "fields": ["line_user_id", "name", "phone"]
  },
  "target_count": 150,
  "processed_count": 0,
  "success_count": 0,
  "fail_count": 0,
  "last_index": 0,
  "content_template": {
    "type": "text",
    "text": "{{customer_name}} 早安，今天是 {{date}}，祝您有美好的一天！"
  },
  "created_by": "user_key",
  "created_at": "2026-06-14T10:00:00Z",
  "updated_at": "2026-06-14T10:00:00Z"
}
```

### broadcast_recipients（送達記錄）

```json
{
  "_key": "uuid",
  "task_key": "broadcast_task_key",
  "customer_id": "crm_contact_key",
  "line_user_id": "LINE_user_id",
  "customer_name": "陳先生",
  "status": "pending | sent | failed | read",
  "content_sent": {
    "type": "text",
    "text": "陳先生早安，今天是 2026-06-15，祝您有美好的一天！"
  },
  "error_msg": null,
  "sent_at": "2026-06-15T08:00:01Z",
  "read_at": null
}
```

### 集合與索引

| 集合 | 索引 | 用途 |
|------|------|------|
| `broadcast_tasks` | `[status, scheduled_at]` | 排程輪詢 |
| `broadcast_tasks` | `[created_by]` | 業務查詢自己的任務 |
| `broadcast_recipients` | `[task_key]` | 任務送達清單 |
| `broadcast_recipients` | `[customer_id, created_at]` | Timeline 關聯 |

|------|------|------|
| POST | `/api/v1/bpa/welfare/broadcast/tasks` | 建立推播任務 |

## 核心流程

```
建立任務
  │
  ├── 選擇目標：全部/VIP/區域/自訂查詢
  ├── 編輯內容：文字/圖片/Flex Message
  ├── 預覽：系統抽樣 3 筆顯示個人化結果
  ├── 確認送出
  │
  ▼
broadcast_tasks 寫入 (status: scheduled)
  │
  ▼
scheduler.py 輪詢
  │
  ├── 任務到期 → status: running
  ├── 讀取 target_customers（from CRM / query）
  ├── 逐筆：
  │   ├── 套用個人化模板（取代變數）
  │   ├── rate_limiter.acquire()（20tps）
  │   ├── LINE push API 發送
  │   ├── 寫入 broadcast_recipients
  │   ├── task.processed_count++
  │   ├── task.last_index++
  │   └── 失敗 → task.fail_count++，記錄 error_msg
  │
  ├── 全部完成 → status: completed
  └── 異常中斷 → status 保持 running，下次輪詢續傳
```

## 錯誤處理與可靠度

| 情境 | 處理方式 |
|------|---------|
| LINE API 瞬斷 | retry 3 次（exponential backoff 1s→2s→4s） |
| LINE API 持續失敗 | 跳過該用戶，記錄 error_msg，繼續下一筆 |
| 任務執行中程式重啟 | 啟動時掃描 status=running 的任務，從 last_index 續傳 |
| Rate limit 429 | 自動降速（rate_limiter 動態調整） |
| 用戶封鎖 Bot | LINE 回傳 403 → 標記 status=failed, error="blocked" |

## 安全規則

1. **所有推播必須經業務確認預覽**，不可直接排程發送（系統排程的週期性問候除外）
2. 週期性問候模板需在後台先建立並啟用
3. 每筆發送記錄保留至少 30 天
4. 支援發送前抽樣預覽（最多 5 筆），業務確認後才正式發送
