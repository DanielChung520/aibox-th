# 08 — 請假小幫手

> **Agent Key**: `leave_assistant`
> **Endpoint**: `POST /leave-assistant/chat`（建議）
> **Ragic 關聯**: CONFIGURATIONFILE_7（員工管理－假別欄位）、假單（待確認 Sheet ID 或自建）
> **狀態**: ⬜ 未實作
> **身份依賴**: ✅ 需要 `shared/user_binding.py`（LINE user_id → 員工編號）

---

## 1. 概述

協助員工透過 LINE 查詢假別餘額、提交請假申請、查詢請假歷史。包含讀取（餘額/歷史）和寫入（請假申請，需確認）兩種操作。

### 負責業務邊界

```
員工在 LINE 上的請假需求
  ├── 我還有幾天特休 → 查詢假別餘額（讀取）
  ├── 我要請假 → 提交請假申請（寫入，需確認）
  └── 我請過哪些假 → 查詢請假記錄（讀取）
```

### 不負責

- ❌ 審核請假單（主管審核不在 LINE 進行）
- ❌ 修改/刪除已送出的請假單
- ❌ 查詢他人假別（只能查自己的）

## 3. 狀態機 (SEQ)

### 3.1 請假申請狀態流轉

```
  ┌──────────────┐
  │  PENDING     │ ← LINE 送出，等待審核
  │  (待審核)    │
  └──────┬───────┘
         │ 主管審核
    ┌────┴────┐
    │         │
 ┌──▼──┐  ┌───▼────┐
 │已核准│  │已拒絕   │
 │     │  │        │
 └──┬──┘  └───┬────┘
    │         │
 ┌──▼──┐  ┌───▼────┐
 │已完成│  │已退回   │ ← 可重新申請
 │     │  │        │
 └─────┘  └────────┘
```

### 3.2 LINE 對話狀態機（寫入操作）

```
  ┌────────────┐
  │    IDLE    │ ← 等待使用者輸入
  └─────┬──────┘
        │ 使用者提出請假
  ┌─────▼──────┐
  │  RESOLVE   │ ← 查 user_binding
  │  IDENTITY  │    取得員工編號
  └─────┬──────┘
        │ 身份確認
  ┌─────▼──────┐
  │  PARSING   │ ← LLM 解析請假資訊
  │  LEAVE     │    假別/日期/天數/原因
  └─────┬──────┘
        │
  ┌─────▼──────┐
  │ AWAIT_CONFIRM │ ← 等待使用者確認
  │              │    若修改 → 回 PARSING
  └─────┬──────┘
        │ 使用者確認
  ┌─────▼──────┐
  │   WRITING  │ ← 寫入 leave_requests
  │            │    狀態: PENDING
  └─────┬──────┘
        │
   ┌────┴────┐
   │         │
┌──▼──┐  ┌───▼───┐
│DONE │  │ FAIL  │
└──┬──┘  └───┬───┘
   │         │
   └────┬────┘
   ┌────▼────┐
   │  IDLE   │
   └─────────┘
```

## 4. LINE 對話範例

### 4.1 假別餘額查詢

```
User > 我還有幾天特休？

Agent > 您的假別餘額（截至 2026-05-07）
       ─────────────────────────
       員工：王小明（EMP-00042）
       部門：生產部
       ─────────────────────────
       特休：7.5 天
       事假：3 天
       病假：已使用 2 天（全年度額度 14 天）
       婚假：7 天（未使用）
       喪假：尚未使用
       ─────────────────────────
```

### 4.2 請假申請（含確認流程）

```
User > 我要請假

Agent > 好的，請提供以下資訊：
       1. 假別（特休/事假/病假/婚假/喪假）
       2. 日期（例如：5/10 或 5/10~5/12）
       3. 原因

User > 特休 5/10 一天，處理個人事務

Agent > 好的，以下是您的請假內容：
       ─────────────────────────
       員工：王小明（EMP-00042）
       假別：特休
       日期：2026-05-10（1 天）
       原因：處理個人事務
       ─────────────────────────
       請問以上內容是否正確？
       (回覆「確認」以送出申請，
        或提供修改內容)

User > 改成 5/10~5/11 兩天

Agent > 好的，已更新：
       ─────────────────────────
       假別：特休
       日期：2026-05-10 ~ 2026-05-11（2 天）
       原因：處理個人事務
       ─────────────────────────
       請問以上內容是否正確？

User > 確認

Agent > ✅ 請假申請已送出！
       申請單號：LV-20260507-0001
       狀態：待主管審核
       我們將於審核完成後通知您。
```

### 4.3 請假紀錄查詢

```
User > 我今年請過哪些假？

Agent > 您 2026 年的請假紀錄
       ─────────────────────────
       1. LV-20260401  04/01~04/01  特休  1 天  ✅ 已核准
```

| 意圖 | 觸發關鍵字 | 類型 | 處理方式 |

## 6. 資料模型

### user_bindings（身份綁定）

```json
{
  "_key": "line:{channel_key}:{line_user_id}",
  "platform": "line",
  "channel_key": "ch_xxx",
  "line_user_id": "U1234567890",
  "employee_id": "EMP-00042",
  "employee_name": "王小明",
  "department": "生產部",
  "bound_at": "2026-05-01T10:00:00Z",
  "bound_by": "admin"
}
```

### leave_requests（請假申請）

```json
{
  "_key": "LV-20260507-0001",
  "leave_id": "LV-20260507-0001",
  "employee_id": "EMP-00042",
  "employee_name": "王小明",
  "leave_type": "annual",  
  "start_date": "2026-05-10",
  "end_date": "2026-05-11",
  "days": 2.0,
  "reason": "處理個人事務",
  "status": "PENDING",
  "source": "line",
  "created_at": "2026-05-07T10:00:00Z",
  "updated_at": "2026-05-07T10:00:00Z",
  "approved_by": null,
  "approved_at": null
}
```

### 請假狀態列舉

| 值 | 說明 |
|----|------|
| `PENDING` | 待審核（LINE 送出後預設） |
| `APPROVED` | 已核准 |
| `REJECTED` | 已拒絕 |
| `RETURNED` | 已退回（可重新申請） |
| `DONE` | 已完成（請假日期已過） |
| `CANCELLED` | 已取消 |

### 假別對照

| leave_type | 中文 | Ragic 假別欄位 |
|-----------|------|---------------|
| `annual` | 特休 | 員工管理.特休時數 |
| `personal` | 事假 | 員工管理.事假時數 |
| `sick` | 病假 | 員工管理.病假時數 |
| `marriage` | 婚假 | 員工管理.婚假時數 |
| `funeral` | 喪假 | 員工管理.喪假時數 |

## 8. 確認機制

| 階段 | 條件 | Agent 行為 |
|------|------|-----------|
| **身份驗證** | 使用者提出請假 | 先查 user_binding，無綁定則提示聯絡 HR |
| **摘要** | LLM 解析請假資訊後 | 結構化顯示假別/日期/天數/原因，要求確認 |
| **確認** | 使用者確認 | 寫入 `leave_requests`，狀態 PENDING |
| **修改** | 使用者提供修改內容 | 重新解析 → 更新摘要 → 再次要求確認 |
| **拒絕** | 使用者說「不用」 | 放棄，回到 IDLE |
| **逾時** | 30 分鐘無回應 | 放棄暫存 |
| **假別不足** | 餘額小於申請天數 | 提示「特休僅剩 X 天，請修改假別或天數」 |
