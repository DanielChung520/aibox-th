# 02 — 採購小幫手（含請購單）

> **Agent Key**: `purchase_assistant`
> **Endpoint**: `POST /purchase-assistant/chat`（建議）
> **Ragic 關聯**: ERP_13（採購單）、CONFIGURATIONFILE_10（供應商）、請購單（待確認 Sheet ID）
> **前端對應**: RagicLogisticProcess「請購單」→「採購單」節點
> **狀態**: ⬜ 未實作

---

## 1. 概述

協助採購人員透過 LINE 查詢請購進度、採購單狀態、供應商資訊。因為 LINE 只能查詢（無法直接簽核），所有操作以「閱讀追蹤」為主。

### 負責業務邊界

```
採購人員在 LINE 上的查詢需求
  ├── 請購單核准了沒 → 查詢請購單進度
  ├── PO 到哪了 → 查詢採購單狀態 + 收貨進度
  └── XX 供應商資料 → 查詢供應商基本資訊
```

### 不負責

- ❌ 建立/修改採購單（需要 ERP 權限，不在 LINE 處理）
- ❌ 簽核採購單
- ❌ 詢價/比價（由詢價小幫手負責）

## 3. 狀態機 (SEQ)

### 3.1 請購單狀態流轉（Ragic 既有）

```
請購單 (PR)
  ┌──────────┐
  │  未處理   │ ← 剛提出
  └─────┬────┘
        │
  ┌─────▼────┐
  │  審核中   │ ← 主管審核
  └─────┬────┘
        │
  ┌─────▼──────┐
  │ 已轉採購單  │ ← 已建立對應 PO
  └─────┬──────┘
        │
  ┌─────▼──┐
  │  已結案  │
  └─────────┘
```

### 3.2 採購單狀態流轉（Ragic 既有 — ERP_13）

```
採購單 (PO)
  ┌──────────┐
  │  成立中   │ ← 剛建立，尚可編輯
  └─────┬────┘
        │
  ┌─────▼────┐
  │  待核簽   │ ← 等待主管簽核
  └─────┬────┘
        │
  ┌─────▼──┐
  │  已簽核  │ ← 已核准，可轉收貨
  └─────┬──┘
        │
  ┌─────▼─────┐
  │  轉收貨    │ ← 已部分或全部收貨
  │(部分/全部) │
  └─────┬─────┘
        │
  ┌─────▼──┐
  │  已結案  │
  └─────────┘
```

### 3.3 LINE 對話狀態機

```
  ┌────────────┐
  │    IDLE    │ ← 等待使用者輸入
  └─────┬──────┘
        │ 使用者提出查詢
  ┌─────▼──────┐
  │  INTENT    │ ← 判斷查詢類型
  │ CLASSIFY   │    pr_query / po_query / vendor_query
  └─────┬──────┘
        │
  ┌─────▼──────┐
  │  QUERYING  │ ← 呼叫 Data Agent / Ragic Proxy
  │            │    查詢對應資料
  └─────┬──────┘
        │ 取得結果
  ┌─────▼──────┐
  │  RESPOND   │ ← LLM 整理結果呈現給使用者
  └─────┬──────┘
        │
  ┌─────▼──────┐
  │    IDLE    │ ← 回到等待狀態
  └────────────┘
```

**讀取操作不需要確認機制**，但若查無資料或發生錯誤，需清楚告知使用者。

## 5. 意圖分類

| 意圖 | 觸發關鍵字 | 類型 | 資料來源 |
|------|-----------|------|---------|
| `pr_query` | 請購, PR-, 請購單, 核准, 申請 | 讀取 | Data Agent / Ragic Proxy |
| `po_query` | 採購單, PO-, 採購進度, 到哪, 交期 | 讀取 | Data Agent（ERP_13 + 收貨資訊） |
| `vendor_query` | 供應商, 廠商, 資料, vendor, 交易對象 | 讀取 | Ragic Proxy（CONFIGURATIONFILE_10） |
| `general_chat` | 其他 | 閒聊 | LLM 一般對話 |

## 8. 確認機制

本 Agent **所有操作皆為讀取**，不需要寫入確認機制。但需注意：

| 情境 | 處理方式 |
|------|---------|
| 查無請購單 | 「查無 PR-XXX 資料，請確認單號是否正確」 |
| 查無採購單 | 「查無 PO-XXX 資料，可能單號有誤或尚未建立」 |
| 查無供應商 | 「查無 XX 供應商資料，請確認名稱是否完整」 |
| Data Agent 逾時 | 「系統查詢逾時，請稍後再試或聯絡 MIS」 |
| 單號格式錯誤 | 「請購單號格式為 PR-YYMMDD-NNNN」 |
