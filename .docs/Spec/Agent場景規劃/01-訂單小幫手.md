# 01 — 訂單小幫手 ✅（已實作）

> **Agent Key**: `order_secretary`
> **Endpoint**: `POST /order-secretary/chat`
> **Ragic 關聯**: ERP_14（訂購單）、STOCK_16（庫存表/品項查詢）
> **狀態**: ✅ Phase 1 已上線（支援 LINE 文字/圖片/檔案建立預購單）

---

## 1. 概述

協助客戶/業務透過 LINE 提交訂單查詢、建立預購單、查詢可訂購品項。最早上線的 Agent，也是後續 Agent 的實作範本。

### 負責業務邊界

```
客戶/業務在 LINE 上的訂單相關操作
  ├── 我要訂購 → 建立預購單（需確認）
  ├── 我的訂單到哪了 → 查詢預購單進度
  └── 你們有什麼 → 查詢可訂購品項列表
```

## 2. 流程圖

### 2.1 讀取流程（訂單查詢 / 產品列表）

```
User                    Agent                        Ragic/DB
 │                       │                             │
 ├─「我的訂單到哪了？」──→│                             │
 │                       ├─ query order_preorders ────→│
 │                       │←─ return preorder list ────│
 │                       ├─ LLM 整理回應              │
 │←── 顯示訂單狀態 ──────┤                             │
 │                       │                             │
 │                       │                             │
 ├─「你們有哪些產品？」─→│                             │
 │                       ├─ STOCK_16 cache ──────────→│
 │                       │←─ return items ───────────│
 │                       ├─ LLM 整理回應              │
 │←── 顯示產品列表 ──────┤                             │
```

### 2.2 寫入流程（建立預購單）— 含確認機制

```
User                    Agent                        Ragic/DB
 │                       │                             │
 ├─「我要訂 10 箱A001」─→│                             │
 │                       ├─ LLM 解析訂單資訊           │
 │                       │  (品名/數量/單位/規格)       │
 │                       │                             │
 │                       ├─ 摘要訂單內容               │
 │←── 請確認訂單內容 ────┤                             │
 │    A001 x 10 箱       │                             │
 │    規格：XX           │                             │
 │    請確認(Y/N)        │                             │
 │                       │                             │
 ├─「確認」─────────────→│                             │
 │                       ├─ 寫入 order_preorders ────→│
 │                       │←─ return order_id ────────│
 │←── 已建立預購單 ──────┤                             │
 │    PO-20260507-0001   │                             │
 │                       │                             │
 │ (若 User 回「修改」)  │                             │
 ├─「數量改 20 箱」─────→│                             │
 │                       ├─ 更新摘要重新詢問            │
 │←── 請再次確認 ────────┤                             │
```

### 2.3 LINE 群組 @mention 流程

```
群組中：
  [UserA] @訂單小幫手 我要訂 10 箱 A001
       │
       ▼
  訂單小幫手解析 → 回覆（含 @UserA）
       │
       ▼
  [UserA] 確認 → Agent 執行 → 回覆結果
  [UserB] 無 @mention → 被忽略
```

## 3. 狀態機 (SEQ)

### 3.1 預購單狀態流轉

```
                         ┌─────────────┐
                         │    開立      │ ←  LINE 建立後預設狀態
                         │  (OPEN)     │
                         └──────┬──────┘
                                │ 業務確認訂單內容
                         ┌──────▼──────┐
                         │  預購確認中  │ ←  電話/LINE 跟客戶確認
                         │ (CONFIRMING) │
                         └──────┬──────┘
                                │ 正式立單到 Ragic
                         ┌──────▼──────┐
                         │ 已正式立單   │ ←  已在 Ragic 建立正式訂購單
                         │ (ORDERED)   │
                         └──────┬──────┘
                                │
                    ┌───────────┼───────────┐
                    │           │           │
             ┌──────▼───┐ ┌────▼────┐ ┌───▼──────┐
             │  已完成   │ │  取消   │ │  異常    │
             │(DONE)    │ │(CANCEL) │ │(ERROR)   │
             └──────────┘ └─────────┘ └──────────┘
```

### 3.2 LINE 對話狀態機（寫入操作）

```
  ┌────────────┐
  │    IDLE    │  ← 等待使用者輸入
  └─────┬──────┘
        │ 使用者提出訂購需求
  ┌─────▼──────┐
  │  PARSING   │  ← LLM 解析訂單內容
  │            │     提取：品名/數量/單位/規格
  └─────┬──────┘
        │ 解析成功，產生摘要
  ┌─────▼──────┐
  │ AWAIT_CONFIRM │  ← 等待使用者確認
  │              │     若使用者修改 → 回 PARSING
  └─────┬──────┘
        │ 使用者確認
  ┌─────▼──────┐
  │ EXECUTING  │  ← 寫入 ArangoDB order_preorders
  │            │     產生預購單編號
  └─────┬──────┘
        │
   ┌────┴────┐
   │         │
┌──▼──┐  ┌───▼───┐
│DONE │  │ FAILED │  ← 錯誤回報 + 回到 IDLE
└──┬──┘  └───┬───┘
   │         │
   └────┬────┘
   ┌────▼────┐
   │  IDLE   │
   └─────────┘
```

## 4. LINE 對話範例

### 4.1 建立預購單（完整確認流程）

```
User > 我要訂購

Agent > 好的，請提供以下資訊：
       1. 品名（例如：A001 原料）
       2. 數量
       3. 單位（例如：箱、KG、個）
       4. 規格（如需要）
       5. 希望交期（如需要）

User > A001 原料 10 箱

Agent > 好的，以下是您的訂購內容：
       ─────────────────────────
       品名：A001 原料
       數量：10
       單位：箱
       規格：-
       交期：未指定
       ─────────────────────────
       請問以上內容是否正確？
       (請回覆「確認」以建立預購單，
        或提供修改內容)

User > 數量改 15 箱

Agent > 好的，已更新：
       ─────────────────────────
       品名：A001 原料
       數量：15
       單位：箱
       ─────────────────────────
       請問以上內容是否正確？
       (回覆「確認」以建立預購單)

User > 確認

Agent > ✅ 已為您建立預購單！
       訂單編號：PO-20260507-0001
       狀態：開立
       我們將盡快為您處理。

       如需查詢訂單狀態，請輸入「查詢訂單」。
```

### 4.2 查詢訂單狀態

```
User > 查詢我的訂單

Agent > 您目前的預購單：
       ─────────────────────────
       1. PO-20260507-0001
          品項：A001 原料 x 15 箱
          狀態：開立
          建立日期：2026-05-07
       ─────────────────────────
       目前共 1 筆預購單。
```

### 4.3 產品列表查詢

```
User > 你們有哪些產品？

Agent > 目前可供預購的品項：
       ─────────────────────────
       1. A001 原料（XX規格）— 庫存 1,500 KG
       2. B002 成品（YY規格）— 庫存 800 箱
       3. C003 包材（ZZ規格）— 庫存 3,000 個
```

## 5. 意圖分類

| 意圖 | 觸發關鍵字 | 類型 | 處理方式 |
|------|-----------|------|---------|
| `order_text` | 訂購, 我要買, 下單, 訂, 需要, 數量 | 寫入 | LLM 解析 → 確認 → 建立預購單 |
| `order_track` | 訂單, 查詢, 進度, 到哪, 預購單, PO- | 讀取 | 查 `order_preorders` → LLM 整理 |
| `product_list` | 產品, 品項, 有什麼, 商品, 菜單, 目錄 | 讀取 | 查 `STOCK_16` 快取 → LLM 整理 |
| `time_query` | 時間, 幾點, 日期, 今天 | 內建 | Python `datetime.now()` |
| `general_chat` | 其他 | 閒聊 | LLM 一般對話 |

## 6. 資料模型

### order_preorders（主表）

```json
{
  "_key": "PO-20260507-0001",
  "preorder_id": "PO-20260507-0001",
  "user_id": "line:U1234567890",
  "user_name": "王小明",
  "source": "line",
  "status": "OPEN",
  "notes": "客戶急件",
  "created_at": "2026-05-07T10:00:00Z",
  "updated_at": "2026-05-07T10:00:00Z"
}
```

### order_preorder_items（明細表）

```json
{
  "_key": "PO-20260507-0001-001",
  "preorder_id": "PO-20260507-0001",
  "line_no": 1,
  "product_name": "A001 原料",
  "quantity": 15.0,
  "unit": "箱",
  "spec": "XX規格",
  "notes": ""
}
```

### 狀態列舉

| 值 | 說明 | 可操作 |
|----|------|--------|
| `OPEN` | 開立（剛從 LINE 建立） | 取消、確認訂購 |
| `CONFIRMING` | 預購確認中（業務跟客戶確認中） | 轉正式立單 |
| `ORDERED` | 已正式立單（已在 Ragic 建立正式單） | 唯讀 |
| `DONE` | 已完成（訂單結案） | 唯讀 |
| `CANCEL` | 已取消 | 唯讀 |
| `ERROR` | 異常 | 重新處理 |

## 8. 確認機制重點

| 階段 | 條件 | Agent 行為 |
|------|------|-----------|
| **摘要** | LLM 解析出訂購內容後 | 以結構化格式呈現品項明細，要求使用者確認 |
| **確認** | 使用者回覆「確認/OK/Y/是」 | 執行寫入，回傳預購單編號 |
| **修改** | 使用者提供修改內容 | 重新解析 → 更新摘要 → 再次要求確認 |
| **拒絕** | 使用者回覆「不用/取消」 | 放棄本次操作，回到 IDLE |
| **逾時** | 超過 30 分鐘無回應 | 放棄本次暫存（不寫入），等待下次輸入 |

## 9. 與前端整合

前端 `PreorderBoard.tsx`（路由 `/app/preorder`）可直接管理從 LINE 建立的預購單，提供完整的 CRUD、狀態流轉、明細編輯功能。

```
LINE 建立預購單 → order_preorders → PreorderBoard 顯示
                                      │
                                      ├── 狀態更新（開立→確認中→已立單）
                                      ├── 明細編輯
                                      └── 正式轉入 Ragic ERP
```
