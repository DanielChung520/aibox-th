# 03 — 庫存小幫手

> **Agent Key**: `inventory_assistant`
> **Endpoint**: `POST /inventory-assistant/chat`（建議）
> **Ragic 關聯**: STOCK_16（庫存表）、STOCK_17（倉儲庫存表）
> **前端對應**: QueryPlayground 的庫存查詢範例、Data Agent Schema 分類
> **狀態**: ⬜ 未實作

---

## 1. 概述

協助業務/倉管/生管透過 LINE 快速查詢即時庫存量與庫存異動記錄。全部為讀取操作，不需要確認機制。

### 負責業務邊界

```
各角色在 LINE 上的庫存查詢需求
  ├── A001 還有多少 → 查詢即時庫存量 + 倉儲位置
  └── A001 最近進出 → 查詢庫存異動記錄
```

### 不負責

- ❌ 建立調撥/盤點單
- ❌ 修改庫存數量
- ❌ 查詢訂單/採購單進度（由對應 Agent 負責）

## 2. 流程圖

### 2.1 庫存查詢流程

```
User                    Agent                        Data Agent
 │                       │                             │
 ├─「A001 還有多少？」─→│                             │
 │                       ├─ 判斷意圖: inv_query       │
 │                       ├─ 提取品名關鍵字: A001      │
 │                       ├─ Data Agent NL→SQL ───────→│
 │                       │  (查 STOCK_16 + STOCK_17)  │
 │                       │←─ return 庫存資料 ────────│
 │                       ├─ LLM 整理回應              │
 │←── 顯示庫存資訊 ──────┤                             │
 │   A001: 1,500 KG     │                             │
 │   倉庫A-01-03 儲位    │                             │
```

### 2.2 庫存異動查詢流程

```
User                    Agent                        Data Agent
 │                       │                             │
 ├─「A001 最近進出」─→│                             │
 │                       ├─ 判斷意圖: inv_movement    │
 │                       ├─ Data Agent NL→SQL ───────→│
 │                       │  (查調撥/入庫/出庫記錄)     │
 │                       │←─ return 異動明細 ────────│
 │                       ├─ LLM 整理為時間軸            │
 │←── 顯示異動記錄 ──────┤                             │
 │   05/06 入庫 +500    │                             │
 │   05/04 出庫 -200    │                             │
```

### 2.3 快取優先流程

```
User 查詢庫存
    │
    ▼
Agent 檢查 shared/ragic_cache（STOCK_16）
    │
    ├── Cache Hit (TTL < 3600s)
    │   └── 直接讀取快取 → LLM 整理 → 回覆
    │
    └── Cache Miss (TTL expired)
        └── 透過 Rust API 更新快取 → 讀取 → LLM 整理 → 回覆
```

## 3. 狀態機 (SEQ)

### 3.1 LINE 對話狀態機

```
  ┌────────────┐
  │    IDLE    │ ← 等待使用者輸入
  └─────┬──────┘
        │ 使用者提出庫存查詢
  ┌─────▼──────┐
  │   EXTRACT  │ ← 提取品名關鍵字
  │   ENTITY   │    去除疑問詞/語氣詞
  └─────┬──────┘
        │
  ┌─────▼──────┐
  │ CHECK CACHE│ ← 檢查 shared/ragic_cache
  └─────┬──────┘
        │
  ┌─────▼──────┐
  │ DATA AGENT │ ← 呼叫 Data Agent NL→SQL
  │   QUERY    │    或直接讀快取
  └─────┬──────┘
        │
  ┌─────▼──────┐
  │   FORMAT   │ ← LLM 整理為自然語言回應
  │  RESPONSE  │
  └─────┬──────┘
        │
  ┌─────▼──────┐
  │    IDLE    │
  └────────────┘
```

### 3.2 快取狀態

```
Ragic STOCK_16 資料
    │
    ▼
shared/ragic_cache (TTL: 3600s)
    │
    ├── 有效 → 直接回傳
    └── 過期 → read_or_refresh() → 更新快取 → 回傳
         │
         └── Ragic API 失敗 → 回傳舊快取 + 標示「資料可能不是最新」
```

## 5. 意圖分類

| 意圖 | 觸發關鍵字 | 類型 | 資料來源 |
|------|-----------|------|---------|
| `inv_query` | 庫存, 還有多少, 庫存量, 剩多少, stock, 還有貨嗎 | 讀取 | STOCK_16 cache / Data Agent |
| `inv_movement` | 異動, 進出, 調撥, 最近出入, 記錄, 歷史 | 讀取 | Data Agent（調撥/入庫/出庫表） |
| `general_chat` | 其他 | 閒聊 | LLM 一般對話 |

### 品名提取規則

```
使用者輸入 → 去除疑問關鍵字（庫存/還有多少/剩...）
           → 去除語氣詞（請問/我想查/幫我看）
           → 取剩餘字串（至少 2 字）作為品名關鍵字
           → 模糊比對 STOCK_16 品名欄位
```

## 8. 確認機制

本 Agent **所有操作皆為讀取**，不需要寫入確認機制。但需注意：

| 情境 | 處理方式 |
|------|---------|
| 查無品項 | 「查無 XX 資料，請確認品名是否正確」 |
| 庫存為 0 | 「XX 目前庫存為 0，建議安排採購」 |
| 低於安全庫存 | 顯示 ⚠️ 低庫存預警 |
| 快取過期 | 標示「資料可能不是最新」 |
| Data Agent 失敗 | 嘗試用快取資料回應 + 備註時間 |
