# 09 — 員工資料小幫手

> **Agent Key**: `employee_directory`
> **Endpoint**: `POST /employee-directory/chat`（建議）
> **Ragic 關聯**: CONFIGURATIONFILE_7（員工管理）、CONFIGURATIONFILE_2（組織部門）
> **狀態**: ⬜ 未實作
> **身份依賴**: ✅ 可選（需登入才能查詳細資料，但基本查詢可開放）

---

## 1. 概述

協助員工透過 LINE 查詢同事基本資料、部門組織架構。全部為讀取操作。

### 負責業務邊界

```
員工在 LINE 上的查人需求
  ├── 王小明是哪個部門 → 查詢員工基本資料
  └── 生產部有哪些人 → 查詢部門組織架構
```

### 不負責

- ❌ 修改員工資料
- ❌ 員工請假/出勤（由請假小幫手/出勤小幫手負責）
- ❌ 組織異動管理

## 3. 狀態機 (SEQ)

### 3.1 LINE 對話狀態機（純讀取）

```
  ┌────────────┐
  │    IDLE    │
  └─────┬──────┘
        │ 使用者查詢
  ┌─────▼──────┐
  │  INTENT    │ ← emp_query / org_chart
  │ CLASSIFY   │
  └─────┬──────┘
        │
  ┌─────▼──────┐
  │ RAGIC PROXY│ ← 直接讀取 Ragic Proxy
  │   QUERY    │    （不需 Data Agent）
  └─────┬──────┘
        │
  ┌─────▼──────┐
  │  RESPOND   │ ← LLM 整理回應
  └─────┬──────┘
        │
  ┌─────▼──────┐
  │    IDLE    │
  └────────────┘
```

### 3.2 部門樹遞迴查詢

```
使用者查詢「生產部」
    │
    ▼
查 CONFIGURATIONFILE_2 → 找到「生產部」的部門編號
    │
    ▼
查該部門下的子部門（如有）→ 製造課、品管課
    │
    ▼
查各部門員工（CONFIGURATIONFILE_7 子表格）
    │
    ▼
彙整部門樹 + 人數統計 → LLM 整理回應
```

## 5. 意圖分類

| 意圖 | 觸發關鍵字 | 類型 | 資料來源 |
|------|-----------|------|---------|
| `emp_query` | 在哪個部門, 分機, 員工資料, 誰是, 同事, 通訊錄 | 讀取 | Ragic Proxy（CONFIGURATIONFILE_7） |
| `org_chart` | 組織, 部門, 有哪些人, 部門成員, 成員列表 | 讀取 | Ragic Proxy（CONFIGURATIONFILE_2 + 7） |
| `general_chat` | 其他 | 閒聊 | LLM 一般對話 |

## 6. API 端點

| 方法 | 路徑 | 說明 |
|------|------|------|
| POST | `/employee-directory/chat` | 主要對話端點 |

內部呼叫：
| 方法 | 目標 | 用途 |
|------|------|------|
| GET | `/api/v1/da/ragic/proxy/CONFIGURATIONFILE_7/data` | 查員工資料 |
| GET | `/api/v1/da/ragic/proxy/CONFIGURATIONFILE_2/data` | 查部門組織 |

---

## 7. 確認機制

本 Agent **所有操作皆為讀取**，不需要寫入確認機制。

| 情境 | 處理方式 |
|------|---------|
| 查無此人 | 「查無「XXX」，請確認姓名是否正確」 |
| 同名多人 | 「有 2 位同名員工：生產部王小明、採購部王小明，請問是哪位？」 |
| 查無部門 | 「查無「XXX」部門，請確認部門名稱」 |
