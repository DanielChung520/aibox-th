## 1. 系統定位

### 1.1 與現有系統的關係

```
┌─────────────────────────────────────────────────────────────┐
│                    意圖管理系統總覽                            │
├─────────────┬──────────────┬──────────────┬────────────────┤
│ 意圖管理     │ Top          │ Data Agent   │ 艾企意圖預測    │
│ 系統規格書   │ Orchestrator │ 意圖規格書   │ 與學習（本文件） │
│ (共用基礎)   │ 意圖規格書   │              │                │
│              │              │              │                │
│ intent_catalog│ 路由匹配     │ NL→SQL       │ 頁面行為模板    │
│ CRUD / 同步  │ ActionPlan   │ 匹配流程     │ 偵測 → 預測     │
│ Scope 分離   │ Graph 節點   │ Qdrant       │ 確認 → 學習     │
└─────────────┴──────────────┴──────────────┴────────────────┘
```

**本文件** 聚焦於艾企助手如何：

1. **偵測**使用者在頁面上的操作行為
2. **預測**使用者可能的意圖，每個預測綁定一個 `intent_id`
3. **確認**使用者選擇的意圖，記錄為意圖日誌
4. **學習**從累積的意圖日誌中分析模式，自動建議新意圖或更新現有意圖

### 1.2 核心原則

| 原則 | 說明 |
|------|------|
| **預測即綁定** | 每個意圖猜測（IntentGuess）必須綁定一個 `intent_id`，無匿名猜測 |
| **確認即記錄** | 使用者選擇某個猜測後，該次互動記錄到 `intent_logs` |
| **記錄即學習素材** | 累積的意圖日誌是學習器的唯一輸入來源 |
| **模板先行** | 預先為每種頁面類型定義意圖模板，減少冷啟動問題 |
| **漸進增強** | 靜態模板 → 規則匹配 → 小模型推理 → 學習器演進 |

### 1.3 與 03-對話與頁面感知 的分工

| 面向 | 03-對話與頁面感知 | 05-意圖預測與學習（本文件） |
|------|------------------|--------------------------|
| **範疇** | 頁面感知機制（A/B/C/D 四方案） | 意圖全生命週期管理 |
| **關注點** | 如何收集操作上下文 | 如何從上下文產生可執行的意圖 |
| **資料流向** | 操作 → ActionTrail → 上下文 | 上下文 → 意圖猜測 → 確認 → 學習 |
| **產出物** | PageContext、ActionTrail | IntentGuess（含 intent_id）、IntentLog |

方案 D（主動意圖推測）的操作軌跡收集與 Ontology 定義在 03 規格書。本文件定義**意圖預測管線**如何消費這些資料，以及後續的確認、記錄、學習機制。


## 4. 意圖偵測層

### 4.1 觸發源

意圖偵測的輸入來自三個觸發源（與 03 規格書方案 A/B/D 對應）：

| 觸發源 | 事件類型 | 資料 | 延遲 |
|--------|---------|------|------|
| 頁面切換 | `page_navigate` | pathname, pageName | 即時 |
| 操作軌跡 | `table_open`, `cell_click`, `field_click`, `modal_open` | entity, entityType, metadata | 即時 |
| API 攔截 | `api_activity` | method, path, status, dataHint | 即時 |

### 4.2 偵測流程

```
觸發源事件
    │
    ├── page_navigate ──▶ 載入該頁面的意圖模板（Level 1）
    │
    ├── table_open ─────▶ 累積 ActionTrail + 規則匹配（Level 2）
    │   cell_click
    │   field_click
    │
    └── api_activity ───▶ 背景感知（不主動觸發預測）
```

### 4.3 事件到意圖的映射規則


## 5. 意圖預測層

### 5.1 IntentGuess 資料結構（擴展）

```typescript
/**
 * 意圖猜測 — 每個猜測必須綁定 intent_id
 */
export interface IntentGuess {
  /** 猜測的顯示文字 */
  text: string;

  /** 信心度 0.0 ~ 1.0 */
  confidence: number;

  /** 猜測來源 */
  source: 'template' | 'rule' | 'llm';

  /** 綁定的意圖 ID（必填，來自 intent_catalog） */
  intent_id: string;

  /** 對策路由策略 */
  strategy: ResponseStrategy;

  /** 副作用等級（用於決定是否需要澄清） */
  side_effect: 'none' | 'reversible' | 'destructive';

  /** 上下文參數（來自觸發事件的元資料） */
  context?: Record<string, unknown>;
}

type ResponseStrategy =
  | 'direct_llm'             // 直接用 LLM 回答
  | 'tool_execute'           // 呼叫工具/Agent 執行
  | 'confirm_then_execute'   // 確認後執行
  | 'handoff_bpa'            // 交給 BPA 流程
  | 'navigate';              // 頁面導航
```

### 5.2 Level 1：靜態模板匹配

頁面切換時，根據 `page_type` 從 `intent_catalog` 拉取對應模板，轉為 IntentGuess 展示：

```typescript
async function loadPageTemplates(pathname: string): Promise<IntentGuess[]> {
  const pageTypes = PAGE_TYPE_MAP[pathname] || [];
  // 1. 查詢 intent_catalog 中 agent_scope="page_action" 且 page_type in pageTypes
  const templates = await intentCatalogApi.list({
    agent_scope: 'page_action',
    page_types: pageTypes,
    status: 'enabled',
  });

  // 2. 加入通用意圖（pa_common_*）
  const commonTemplates = await intentCatalogApi.list({
    agent_scope: 'page_action',
    page_type: 'common',
    status: 'enabled',
  });

  // 3. 轉為 IntentGuess
  return [...templates, ...commonTemplates]
    .sort((a, b) => b.priority - a.priority)
    .slice(0, 5)  // 最多顯示 5 個
    .map(t => ({
      text: t.suggested_text || t.nl_examples?.[0] || t.name,
      confidence: 0.5,    // 靜態模板預設信心度
      source: 'template' as const,
      intent_id: t.intent_id,
      strategy: t.response_strategy as ResponseStrategy,
      side_effect: t.side_effect || 'none',
    }));
}
```

### 5.3 Level 2：規則引擎匹配

操作事件觸發時，結合 ActionTrail 序列和頁面 Ontology 的 IntentPattern 做模式匹配：

```typescript
function matchByRules(
  trail: ActionTrailEntry[],
  patterns: IntentPattern[],
  templates: IntentCatalogEntry[],
): IntentGuess[] {
  const recentActions = trail.slice(-5).map(e => e.action);
  const matches: IntentGuess[] = [];

  for (const pattern of patterns) {
    if (isSubsequence(pattern.trail, recentActions) && pattern.confidence >= 0.7) {
      // 找到匹配的模板
      const template = templates.find(t => t.intent_id === pattern.intent_id);
      if (template) {
        matches.push({
          text: contextualizeText(pattern.suggestedActions[0], trail),
          confidence: pattern.confidence,
          source: 'rule',
          intent_id: template.intent_id,
          strategy: template.response_strategy as ResponseStrategy,
          side_effect: template.side_effect || 'none',
          context: extractContext(trail),
        });
      }
    }
  }
  return matches.slice(0, 3);  // 規則匹配最多 3 個
}
```

### 6.3 記錄邏輯

```typescript
// intentEngine.ts 擴展

/** 使用者選擇猜測時呼叫 */
function acceptGuess(guess: IntentGuess): void {
  // 1. 標記為待確認
  pendingGuessRef.current = guess;

  // 2. 填入輸入框
  intentSelectRef.current?.(guess.text);

  // 3. 提高信心度記錄
  actionTrail.record('intent_accepted', {
    intent_id: guess.intent_id,
    confidence: guess.confidence,
    source: guess.source,
  });
}

/** 使用者發送訊息時呼叫 */
async function confirmGuess(sentText: string): Promise<void> {
  const pending = pendingGuessRef.current;
  if (!pending) return;

  const isModified = sentText.trim() !== pending.text.trim();

  const log: IntentLog = {
    _key: generateId(),
    user_id: authStore.getState().user?._key || 'anonymous',
    intent_id: pending.intent_id,
    action: isModified ? 'modified' : 'confirmed',
    original_text: pending.text,
    modified_text: isModified ? sentText : undefined,
    confidence: pending.confidence,
    source: pending.source,
    page_route: location.pathname,
    page_type: PAGE_TYPE_MAP[location.pathname]?.[0] || 'unknown',
    trigger: lastTriggerRef.current,
    context: pending.context,
    created_at: new Date().toISOString(),
  };

  // 寫入後端
  await intentLogApi.create(log);

  // 清除待確認
  pendingGuessRef.current = null;
}

/** 使用者清除輸入框時呼叫 */
function rejectGuess(): void {
  const pending = pendingGuessRef.current;
  if (!pending) return;

  const log: IntentLog = {
    _key: generateId(),
    user_id: authStore.getState().user?._key || 'anonymous',
    intent_id: pending.intent_id,
    action: 'rejected',
    original_text: pending.text,
    confidence: pending.confidence,
    source: pending.source,
    page_route: location.pathname,
    page_type: PAGE_TYPE_MAP[location.pathname]?.[0] || 'unknown',
    trigger: lastTriggerRef.current,
    created_at: new Date().toISOString(),
  };

  intentLogApi.create(log);
  pendingGuessRef.current = null;
}
```

## 7. 意圖學習器

### 7.1 定位

意圖學習器是**下一階段**的功能，但本節先定義完整規格，確保前面的偵測/預測/記錄機制為學習器做好資料準備。

### 7.2 學習觸發條件

| 條件 | 閾值 | 說明 |
|------|------|------|
| 單一意圖累積確認數 | ≥ 30 筆 | 足夠統計分析 |
| 新頁面操作模式出現 | ≥ 10 筆相同序列 | 可能需要新意圖 |
| 意圖被修改比例 | > 40% | 模板描述需要更新 |
| 意圖被拒絕比例 | > 60% | 模板可能不適用 |
| 未匹配任何意圖 | ≥ 20 筆 | 缺少對應意圖模板 |

### 7.3 學習模式

```
┌──────────────────────────────────────────────────────┐
│                  意圖學習器                            │
│                                                       │
│  輸入：intent_logs（累積的意圖日誌）                    │
│                                                       │
│  分析維度：                                            │
│  ├── 頻率分析：哪些意圖被頻繁確認？                      │
│  ├── 修正分析：使用者怎麼修改猜測文字？                   │
│  ├── 拒絕分析：哪些意圖頻繁被拒絕？                      │
│  ├── 缺口分析：哪些操作序列沒有對應意圖？                 │
│  └── 聚類分析：相似的修正文字是否指向新意圖？              │
│                                                       │
│  產出：                                                │
│  ├── 建議更新：修改現有意圖的 nl_examples / description   │
│  ├── 建議新增：建立新的意圖模板                          │
│  ├── 建議停用：停用低效的意圖模板                        │
│  └── 信心度校正：調整 confidence_threshold               │
```

### 7.4 分析任務詳細設計

#### 7.4.1 頻率分析

```python
# 統計每個意圖的確認次數
FOR log IN intent_logs
  FILTER log.action == 'confirmed'
  FILTER log.created_at >= @since
  COLLECT intent_id = log.intent_id WITH COUNT INTO cnt
  SORT cnt DESC
  RETURN { intent_id, confirmed_count: cnt }
```

產出：高頻意圖的 `priority` 應提升，低頻意圖考慮降序或停用。

#### 7.4.2 修正分析

```python
# 收集被修正的猜測，分析修正方向
FOR log IN intent_logs

  FILTER log.intent_id == @target_intent_id
  RETURN {
    original: log.original_text,
    modified: log.modified_text,
    context: log.context
  }
```

產出：
- 修正後的文字可追加到意圖的 `nl_examples`
- 如果修正方向一致（如都把「搜尋」改成「篩選」），更新 `suggested_text`

## 8. 對策路由

### 8.1 對策定義

每個意圖綁定一個 `response_strategy`（對策），決定艾企如何回應：

| 對策 | 說明 | 範例 |
|------|------|------|
| `direct_llm` | 直接用 LLM 回答，無副作用 | 「這個功能怎麼用？」 |
| `tool_execute` | 呼叫工具/Agent 執行，可能有副作用 | 「幫我查詢訂單數據」 |
| `confirm_then_execute` | 先確認再執行，有副作用 | 「匯出這些資料為 CSV」 |
| `handoff_bpa` | 交給 BPA 流程處理 | 「啟動採購審批流程」 |
| `navigate` | 頁面導航 | 「帶我去用戶管理」 |

### 8.2 對策執行流程

```
使用者確認意圖猜測
    │
    ▼
判斷 response_strategy
    │
    ├── direct_llm ──────────▶ 注入 intent context 到 System Prompt → LLM 回答
    │
    ├── tool_execute ────────▶ 檢查 side_effect
    │                            ├── none ──▶ 直接執行
    │                            └── reversible ──▶ 輕量確認（「確定要搜尋嗎？」）→ 執行
    │
    ├── confirm_then_execute ─▶ 顯示確認對話框 → 使用者確認 → 執行
    │
    ├── handoff_bpa ─────────▶ 路由到 BPA Agent → 流程引導
    │
    └── navigate ────────────▶ router.push(target_path)
```

### 8.3 意圖上下文注入

## 9. 澄清機制

### 9.1 何時需要澄清

| 條件 | 動作 | 範例 |
|------|------|------|
| `side_effect = "none"` | 直接執行 | 「查詢資料」 |
| `side_effect = "reversible"` | 輕量確認（底部 toast） | 「搜尋 active 客戶？」[確認] [取消] |
| `side_effect = "destructive"` | 明確確認（Modal） | 「確定要刪除這筆記錄嗎？此操作無法復原。」 |
| 信心度 < 0.5 | 詢問澄清 | 「您是想搜尋記錄，還是匯出資料？」 |
| 多個意圖信心度相近（差距 < 0.1） | 列出選項 | 「您可能想：① 搜尋記錄 ② 統計分析 ③ 匯出資料」 |
