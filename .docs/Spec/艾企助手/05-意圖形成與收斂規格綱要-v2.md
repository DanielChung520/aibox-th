# 05 — 意圖形成與收斂規格綱要 v2

> 艾企的意圖不是一句話被猜中，而是從語言、操作、頁面、結構、脈絡等多維訊號中逐步形成與收斂。

---

## 1. 文件定位

本文件取代舊有「意圖預測與學習」的單中心描述方式，重新定義艾企的意圖系統。

v2 的核心觀點是：

> **意圖不是一個 query 對應一個 label，而是一個隨著互動、操作、結構與證據逐步形成的動態過程。**

更精確地說：

> **意圖是可被證據支持、也可被證據反駁的工作假設（working hypothesis），不是固定答案。**

因此，本規格不再以「模板 → 猜測 → 記錄」作為中心，而是以：

- 意圖形成（Intent Formation）
- 意圖收斂（Intent Narrowing）
- 意圖承諾（Intent Commitment）
- 意圖學習（Intent Learning）

作為新的主軸。

---

## 2. 為何需要重寫意圖規格

原始 `05-意圖預測與學習.md` 的優點在於：

- 已有完整生命週期概念
- 已引入 actionTrail 與 page template
- 已設想 feedback / learning loop

但其核心假設仍偏向：

> 「先猜一個 intent，再由使用者確認。」

這種模式的限制是：

1. 仍然過度依賴 intent_catalog
2. 容易把未知問題硬塞進既有 intent label
3. 無法充分利用操作軌跡與隱性訊號
4. 無法處理使用者尚未說清楚、但已經透過操作逐步表露方向的情況

因此 v2 必須從「意圖預測」升級為「意圖形成與收斂」。

---

## 3. 新的核心主張

### 3.1 意圖不是單點猜測，而是多維形成

意圖來源至少包含以下五類訊號：

| 訊號類型 | 說明 |
|----------|------|
| 語言訊號 | 使用者輸入的自然語言、問句、補充說明 |
| 結構訊號 | 當前頁面、table、field、record、anchor |
| 行為訊號 | click、dwell、filter、modal_open、page_navigate、操作序列 |
| 語境訊號 | 當前任務、前後對話、最近工作集、已開啟內容 |
| 隱性訊號 | 語氣、猶豫、模糊表達、未說出口但已操作的方向 |

### 3.2 意圖系統的角色不是分類，而是收斂

艾企的意圖系統不應只做：

- intent guess
- confidence score
- accept / reject

而應回答：

- 使用者現在正在接近哪個問題空間？
- 目前最可能的幾個方向是什麼？
- 還差什麼訊號可以繼續縮小範圍？
- 現在應該走 SQL path、Graph path、RAG path，還是 Clarification path？

因此，意圖系統的輸出不應只是一組 guess list，而應逐步轉向：

- **意圖假設**（intent hypothesis）
- **證據摘要**（evidence summary）
- **不確定性**（uncertainty）
- **邊界判定**（boundary status）
- **下一步建議**（next inquiry / next action）

### 3.3 Rule 與 Intent LLM 必須交替使用

v2 不採用純 rule，也不採用純 LLM。

正確模式是：

1. **Rule 先收斂**：利用頁面類型、操作序列、anchor、結構上下文快速縮小範圍
2. **Intent LLM 補語意**：補足模糊、隱性、玄外之音與省略表達
3. **再回到可驗證結構**：將 LLM 的判斷拉回到可被驗證的 evidence / structure / boundary 上

---

## 4. 意圖系統的新四階段模型

### 4.1 Phase 1：Pre-Intent（前意圖）

使用者尚未明確說出口，但系統已可從以下資料感知問題空間：

- 目前頁面位置
- 最近點擊與停留
- 活躍 table / row / field
- 活躍 anchor
- 最近查過的值

輸出：

- current attention zone
- candidate anchors
- possible problem space

### 4.2 Phase 2：Intent Narrowing（意圖收斂）

當使用者開始輸入、詢問或持續操作時，系統逐步縮小範圍。

輸出：

- ranked intent directions
- confidence bands
- missing evidence list
- recommended next clarification / retrieval action

### 4.3 Phase 3：Intent Commitment（意圖承諾）

當 evidence 足夠時，系統才做出當前輪次的 intent commitment。

此時系統應決定的是：

- 這一輪該走哪一條 execution path
- 需不需要 user confirmation
- 需不需要補充查詢或澄清

若下列條件成立，系統必須升級回人類決策或澄清，而不是自行推進：

- 證據互相衝突
- 知識邊界不明
- 需要跨權限或跨知識庫
- 行為與語言訊號指向不同方向
- commitment 可能導向不可逆副作用

### 4.4 Phase 4：Intent Learning（意圖學習）

每次成功互動後，系統學習的不是單一 label，而是：

- 哪組多維訊號最終形成了這個 intent
- 哪種 rule 最有幫助
- 哪種澄清問題最有效
- 哪種 next-step prior 最常成功

## 5. 與現行代碼的重新對齊

### 5.1 已有基礎

目前系統中已有以下基礎能力：

- `src/services/actionTrail.ts`：收集行為事件並上報
- `src/services/intentEngine.ts`：三層猜測（template / catalog / LLM）與 accept/reject/confirm 回饋
- `intentLogApi`：記錄 confirmed / rejected intent
- `data_agent/query/nl2sql/intent_classifier.py`：Qdrant 相似度 intent matching
- `data_agent/intent_rag/router.py`：intent embedding sync 與 scope-based collections

### 5.2 必須重新定位

| 現有元件 | 舊定位 | 新定位 |
|----------|--------|--------|
| actionTrail | 操作記錄 | 多維意圖形成的一級輸入 |
| intentEngine | 猜測引擎 | 前端收斂與提示層 |
| intent_catalog | 模板中心 | 經驗先驗與冷啟動支援 |
| intent logs | 確認紀錄 | 學習素材的一部分 |
| intent_classifier | top-1 匹配器 | 某些子場景的候選生成器 |

## 6. v2 規格主題綱要

後續完整意圖規格，至少應包含以下章節：

1. **系統定位與邊界**
2. **多維訊號模型**
3. **Pre-Intent / Narrowing / Commitment / Learning 四階段流程**
4. **Rule Engine 與 Intent LLM 的協作模型**
5. **ActionTrail 與 Working Set 的關係**
6. **Intent Evidence / Intent State 的資料結構**
7. **確認、拒絕、澄清、改寫的事件流**
8. **學習與回放機制**
9. **與 Inquiry Controller / HybridRAG / Knowledge Management 的接口**
10. **驗收指標與觀測面板**

其中第 6 章至少應定義：

- `intent_hypothesis`
- `intent_evidence`
- `boundary_status`
- `uncertainty_band`
- `prediction_id`（供回饋與學習對齊）
- `recommended_next_step`

---

## 7. 明確拒絕的舊假設

v2 應明確拒絕以下舊假設：

1. 一句 query 一定能對應一個 intent label
2. intent catalog 越完整，系統就越聰明
3. accept / reject log 足以代表完整學習材料
4. 意圖主要來自語言，而不是來自行為與結構上下文
5. LLM 只要猜得準，就不需要 rule / boundary / structure 驗證
6. 預測到意圖，就可以直接推進動作
7. 知識邊界與意圖判斷無關

---

## 8. 本文件結論

艾企未來的意圖系統，不應再被理解為「意圖猜測器」，而應被理解為：

> **一套從多維訊號中逐步形成、收斂、承諾並學習意圖的系統。**

其核心價值不在於猜中一個 label，而在於：

- 在 user 尚未說清楚前，已能逐步接近其真正問題
- 在證據不足時知道如何繼續收斂，而不是硬猜
- 在成功互動後沉澱可重用的收斂經驗，而不是只增加更多模板
