# 03 — 對話與頁面感知

> 艾企助手的頁面感知三階段方案（A/B/C）、對話行為、上下文注入、快捷建議機制

---

## 1. 總覽

頁面感知讓艾企能根據使用者所在的功能頁面，提供更貼切的回應與引導。分四個階段逐步實作：

| 階段 | 名稱 | 狀態 | 核心能力 |
|------|------|------|---------|
| A | 路由感知 | ✅ 已完成 | 辨識當前頁面，靜態快捷建議 |
| B | 上下文上報 | 🔄 進行中 | API 攔截（廣度）+ 操作級上報（深度） |
| B.1 | 全系統埋點監控 | ✅ 已完成 | 前端事件佇列 + Rust API 接收 + Python 結構化日誌 |
| B.2 | Entity 感知鉤子 | ✅ 已完成 | useEntityPerception + entity_interact 事件 |
| B.3 | FloatingAssistant 整合 | ✅ 已完成 | 監聽 entity_interact 事件，同步至 fullPageContext |
| C | RAG 動態建議 | 📋 待實作 | 知識庫 + 小模型生成建議 |
| D | 主動意圖推測 | 📋 待實作 | 操作軌跡 + 異步預載 + 延伸分析 |

> **方案 D 是本系統的核心創新**：不等用戶問，艾企透過操作軌跡主動推斷意圖，異步預載上下文，讓用戶開口時秒答，並提供表格 UI 無法實現的聚合、統計、跨表分析能力。

## 2. 方案 A：路由感知（✅ 已完成）

### 2.1 原理

```
useLocation() → pathname → resolvePageContext(pathname) → PageContext
                                                            ↓
                                              { name, description, suggestions }
```

`FloatingAssistant/index.tsx` 使用 React Router 的 `useLocation()` 取得當前路徑，透過 `resolvePageContext()` 查找對照表，將結果以 `pageContext` prop 傳遞給 `ChatModal`。

### 2.2 PageContext Interface

```typescript
export interface PageContext {
  name: string;          // 頁面名稱（例如「Schema 管理」）
  description: string;   // 頁面描述（例如「資料庫結構瀏覽與管理」）
  suggestions: string[]; // 快捷提問建議（2-3 條）
}
```

### 2.4 路由匹配邏輯

```typescript
export function resolvePageContext(pathname: string): PageContext {
  // 1. 精確匹配
  const exact = PAGE_CONTEXT_MAP[pathname];
  if (exact) return exact;

  // 2. 前綴匹配（最長匹配優先）
  const match = Object.keys(PAGE_CONTEXT_MAP)
    .filter((key) => pathname.startsWith(key))
    .sort((a, b) => b.length - a.length)[0];

  return match ? PAGE_CONTEXT_MAP[match] : defaultPageContext;
}
```

支持動態路由參數：例如 `/app/task-session/chat/abc123` 會匹配到 `/app/task-session/chat`。

### 2.5 前端行為

#### 歡迎訊息

開啟聊天窗時，初始訊息包含當前頁面資訊：

```
你好！我是艾企——您的 AI 企業好助手！
📍 您目前在「Schema 管理」— 資料庫結構瀏覽與管理
```

#### 頁面切換通知

當使用者在不同頁面間切換時，自動在聊天記錄中插入通知：

```
📍 您已切換到「查詢遊樂場」— 自然語言轉 SQL 查詢測試
```

實作細節：
- 使用 `useRef(lastPageNameRef)` 記錄上一個頁面名稱
- 透過 `useEffect` 監聽 `pageContext` 變化
- 頁面名稱不同時才插入通知（避免同頁面 re-render 重複插入）

#### 快捷按鈕動態切換

`suggestions` 區域的按鈕隨 `pageContext` 即時更新，無需重新開啟聊天窗。

### 2.6 限制

- 快捷建議為**靜態硬編碼**，無法動態調整（待方案 C 解決）
- 僅感知「在哪個頁面」，不知道「在頁面上做什麼」（待方案 B 解決）

## 3. 方案 B：上下文上報 — 混合方案（📋 待實作）

### 3.1 目標

讓艾企不只知道「使用者在哪個頁面」，還能知道「使用者在頁面上做了什麼」。

### 3.2 設計理念：廣度 + 深度

方案 B 採用**混合方案**，結合兩種上報機制互補：

| 機制 | 角色 | 覆蓋範圍 | 精準度 | 開發成本 |
|------|------|---------|--------|---------|
| **API 攔截**（Layer 1） | 廣度 — 背景感知 | 全部頁面（自動） | 低 — 只知道呼叫了什麼 API | 極低 — 改一處 interceptor |
| **操作級上報**（Layer 2） | 深度 — 精準感知 | 重點頁面（手動） | 高 — 知道用戶意圖 | 中 — 每個頁面都要加 |

```
┌─────────────────────────────────────────────────────────────┐
│ Layer 1：API 攔截（全域 Axios interceptor）                   │
│  自動記錄最近 N 筆 API 請求摘要                                │
│  GET /api/v1/users → 「正在瀏覽用戶列表」                      │
│  PUT /api/v1/users/admin → 「正在更新用戶 admin」              │
├─────────────────────────────────────────────────────────────┤
│ Layer 2：操作級上報（重點頁面 CustomEvent）                     │
│  Schema 頁面：「正在查看 customers 表的欄位結構」               │
│  查詢遊樂場：「剛執行了 SELECT * FROM orders WHERE ...」       │
│  知識庫管理：「正在向量化『產品手冊』知識庫」                    │
└─────────────────────────────────────────────────────────────┘
                            ↓
              FloatingAssistant 合併兩層資訊
                            ↓
                  艾企提供情境化回應
```

### 3.3 Layer 1：API 攔截（全域自動感知）

#### 3.3.1 原理

在 `src/services/api.ts` 的 Axios response interceptor 中，自動記錄每次 API 請求的摘要資訊，並透過 CustomEvent 通知艾企。

#### 3.3.2 攔截器設計

```typescript
// src/services/api.ts — 新增 response interceptor

/** 最近 API 活動記錄（環形緩衝區） */
interface ApiActivity {
  method: string;          // GET, POST, PUT, DELETE
  path: string;            // /api/v1/users
  status: number;          // 200, 404, 500
  timestamp: number;       // Date.now()
  dataHint?: string;       // 簡要資料描述（如 "3 筆記錄"）
}

const API_ACTIVITY_BUFFER_SIZE = 10;
const apiActivityBuffer: ApiActivity[] = [];

api.interceptors.response.use(
  (response) => {
    const activity: ApiActivity = {
      method: response.config.method?.toUpperCase() || 'GET',
      path: response.config.url || '',
      status: response.status,
      timestamp: Date.now(),
      dataHint: summarizeResponse(response.data),
    };

    // 環形緩衝區
    apiActivityBuffer.push(activity);
    if (apiActivityBuffer.length > API_ACTIVITY_BUFFER_SIZE) {
      apiActivityBuffer.shift();
    }

    // 通知艾企
    window.dispatchEvent(new CustomEvent('api-activity', { detail: activity }));

    return response;
  },
  (error) => {
    // 錯誤也記錄（艾企可感知操作失敗）
    if (error.response) {
      const activity: ApiActivity = {
        method: error.config?.method?.toUpperCase() || 'GET',
        path: error.config?.url || '',
        status: error.response.status,
        timestamp: Date.now(),
        dataHint: error.response.data?.message || `Error ${error.response.status}`,
      };
      apiActivityBuffer.push(activity);
      if (apiActivityBuffer.length > API_ACTIVITY_BUFFER_SIZE) {
        apiActivityBuffer.shift();
      }
      window.dispatchEvent(new CustomEvent('api-activity', { detail: activity }));
    }
    return Promise.reject(error);
  }
);
```

#### 3.3.3 回應摘要函數

```typescript
function summarizeResponse(data: unknown): string | undefined {
  if (!data || typeof data !== 'object') return undefined;
  const d = data as Record<string, unknown>;

  // { data: [...] } → "N 筆記錄"
  if (Array.isArray(d.data)) return `${d.data.length} 筆記錄`;

  // { data: { ... } } → "1 筆記錄"
  if (d.data && typeof d.data === 'object' && !Array.isArray(d.data)) return '1 筆記錄';

  // { message: "..." } → 訊息內容
  if (typeof d.message === 'string') return d.message;

  return undefined;
}
```

#### 3.3.4 過濾規則

不是所有 API 都有意義，需過濾噪音：

| 排除條件 | 原因 |
|---------|------|
| `GET /api/v1/system-params` | 每次頁面載入都會呼叫，噪音過高 |
| `GET /health` | 健康檢查，無業務意義 |
| `GET /api/v1/auth/me` | 認證檢查，頻率高 |
| SSE / WebSocket | 長連線，不適合逐次記錄 |

```typescript
const IGNORED_PATHS = [
  '/api/v1/system-params',
  '/health',
  '/api/v1/auth/me',
  '/api/v1/sse/',
  '/api/v1/ws/',
];

function shouldTrackApi(path: string): boolean {
  return !IGNORED_PATHS.some(ignored => path.startsWith(ignored));
}
```

#### 3.3.5 艾企消費 API 活動

```typescript
// FloatingAssistant/index.tsx
const [recentApiActivity, setRecentApiActivity] = useState<ApiActivity[]>([]);

useEffect(() => {
  const handler = (e: CustomEvent<ApiActivity>) => {
    setRecentApiActivity(prev => {
      const next = [...prev, e.detail];
      return next.slice(-API_ACTIVITY_BUFFER_SIZE);
    });
  };
  window.addEventListener('api-activity', handler as EventListener);
  return () => window.removeEventListener('api-activity', handler as EventListener);
}, []);
```

#### 3.3.6 API 路徑 → 人類可讀描述對照

```typescript
const API_PATH_DESCRIPTIONS: Record<string, string> = {
  '/api/v1/users': '用戶',
  '/api/v1/roles': '角色',
  '/api/v1/functions': '功能選單',
  '/api/v1/agents': 'AI Agent',
  '/api/v1/tools': '工具',
  '/api/v1/chat/sessions': '對話',
  '/api/v1/knowledge/roots': '知識庫',
  '/api/v1/ontologies': '知識本體',
  '/api/v1/leads': '客戶線索',
};

function describeApiActivity(activity: ApiActivity): string {
  const resource = Object.entries(API_PATH_DESCRIPTIONS)
    .find(([path]) => activity.path.startsWith(path))?.[1] || '資源';

  const actions: Record<string, string> = {
    GET: '查看', POST: '新增', PUT: '更新', DELETE: '刪除', PATCH: '修改',
  };
  const action = actions[activity.method] || activity.method;

  return `${action}${resource}` + (activity.dataHint ? `（${activity.dataHint}）` : '');
}
```

### 3.4 Layer 2：操作級上報（重點頁面精準感知）

#### 3.4.1 原理

在**高價值頁面**的關鍵操作點，手動 dispatch `CustomEvent('page-context-detail')` 提供精準的操作上下文。

#### 3.4.2 擴展 PageContext

```typescript
export interface PageContextDetail {
  // 方案 A 的基礎資訊（自動從路由解析）
  name: string;
  description: string;
  suggestions: string[];

  // 方案 B Layer 2 擴展的上下文
  detail?: {
    entity?: string;        // 當前操作的實體（如表名、知識庫名）
    entityType?: string;    // 實體類型（如 'table', 'knowledge_base'）
    action?: string;        // 當前操作（如 'view', 'edit', 'create'）
    metadata?: Record<string, unknown>;  // 額外元資料
  };
}
```

#### 3.4.3 各頁面上報內容規劃

| 優先級 | 頁面 | 上報內容 | 觸發時機 |
|--------|------|---------|---------|
| P0 | Schema 管理 | `{ entity: 'customers', entityType: 'table', action: 'view_columns' }` | 點擊「查看欄位」時 |
| P0 | Schema 管理 | `{ entity: 'orders', entityType: 'table', action: 'view_data' }` | 點擊「查看資料」時 |
| P0 | 查詢遊樂場 | `{ entity: 'SELECT * FROM orders', entityType: 'query', action: 'execute' }` | 執行查詢時 |
| P0 | 查詢遊樂場 | `{ entity: '查詢結果', entityType: 'query_result', action: 'view', metadata: { rowCount: 150 } }` | 查詢結果返回時 |
| P1 | 知識庫管理 | `{ entity: '產品手冊', entityType: 'knowledge_base', action: 'vectorize' }` | 進行向量化時 |
| P1 | 知識庫管理 | `{ entity: '產品手冊', entityType: 'knowledge_base', action: 'upload', metadata: { filename: 'spec.pdf' } }` | 上傳文件時 |
| P1 | 用戶管理 | `{ entity: 'admin', entityType: 'user', action: 'edit' }` | 編輯用戶時 |
| P2 | AI 對話 | `{ entity: 'session_abc', entityType: 'chat_session', action: 'chatting' }` | 對話進行中 |
| P2 | 意圖編排 | `{ entity: '訂單查詢', entityType: 'intent', action: 'edit' }` | 編輯意圖時 |

### 3.7 隱私與安全

| 風險 | 防範措施 |

| 上報內容注入 System Prompt | 上報內容經過格式化，不直接拼接原始字串 |

## 5. 方案 D：主動意圖推測（📋 待實作）

> **核心理念**：不等用戶問，艾企透過觀察操作軌跡，主動推斷意圖、異步預載上下文，並提供表格 UI 無法實現的延伸分析能力。

### 5.1 問題：表格 UI 的能力斷層

用戶在表格頁面看到資料後，能做的事很有限：

| 表格 UI 能做 | 表格 UI 不能做 |
|-------------|--------------|
| 查看原始資料 | 聚合統計（COUNT, SUM, AVG） |
| 單欄篩選 | 複雜條件查詢（多欄 + 時間範圍） |
| 翻頁瀏覽 | 趨勢分析（同比、環比） |
| 單筆查看詳情 | 跨表關聯（JOIN 查詢） |
| 排序 | 排名（TOP N、異常值偵測） |

**艾企的價值**：填補表格 UI 和資料分析之間的鴻溝，成為頁面的**延伸能力層**。

### 5.2 核心架構：操作軌跡 → 意圖推斷 → 異步預載


### 5.3 Action Trail（操作軌跡）

#### 5.3.1 資料結構

```typescript
interface ActionTrailEntry {
  action: string;              // 操作類型
  entity?: string;             // 操作對象
  entityType?: string;         // 對象類型
  metadata?: Record<string, unknown>;  // 額外資訊
  timestamp: number;           // 時間戳
}

interface ActionTrail {
  pageRoute: string;           // 當前頁面路由
  pageName: string;            // 頁面名稱
  entries: ActionTrailEntry[]; // 操作序列（環形緩衝區，最多 20 筆）
  startedAt: number;           // 進入頁面的時間
```

#### 5.3.2 操作類型清單

| 操作類型 | 說明 | 意圖信號 |
|---------|------|---------|

| `create` | 新增操作 | 要新增資料 |
| `delete` | 刪除操作 | 要移除資料 |

### 5.5 Intent Inference Engine（意圖推斷引擎）

#### 5.5.1 推斷流程

```
Action Trail + Page Ontology
  ↓
Step 1：規則匹配（快速、本地）
  將操作序列與 intentPatterns 做模式匹配
  若命中 confidence ≥ 0.7 → 直接使用
  ↓
Step 2：小模型推理（異步、遠端）— 僅在規則未命中時
  將操作軌跡 + 頁面 Ontology + 知識庫摘要 → 送入小模型
  生成意圖描述 + 建議操作
  ↓
Step 3：更新快捷建議
  將推斷結果轉為快捷按鈕，即時顯示在艾企 ChatModal
```

#### 5.5.2 規則匹配（Step 1）

```typescript
function matchIntentPattern(
  trail: ActionTrailEntry[],
  patterns: IntentPattern[],
): IntentPattern | null {
  const recentActions = trail.slice(-5).map(e => e.action);

  for (const pattern of patterns) {
    if (isSubsequence(pattern.trail, recentActions) && pattern.confidence >= 0.7) {
      return pattern;
    }
  }
  return null;
}

function isSubsequence(pattern: string[], actions: string[]): boolean {
  let pi = 0;
  for (const action of actions) {
    if (pi < pattern.length && (pattern[pi] === action || pattern[pi] === '*')) {
      pi++;
    }
  }
  return pi === pattern.length;
}
```

```typescript
// 防抖 2 秒：操作停頓 2 秒後才觸發推斷
const debouncedInferIntent = useMemo(
  () => debounce((trail: ActionTrail) => {
    // Step 1：規則匹配
    const matched = matchIntentPattern(trail.entries, currentOntology.intentPatterns);
    if (matched) {

    });
  }, 2000),
```

### 5.6 異步預載上下文

當意圖推斷完成後，艾企**提前載入**用戶可能需要的資料，這樣用戶真正提問時可以秒答：

```
意圖推斷：「用戶在找 active 客戶」
  ↓ 異步預載（不阻塞 UI）：
  
  1. 預查詢 active 客戶總數
     → SELECT COUNT(*) FROM customers WHERE status = 'active'
  
  2. 預查詢分布統計
     → SELECT region, COUNT(*) FROM customers WHERE status = 'active' GROUP BY region
  
  3. 預載知識庫中關於 customers 表的說明文件
  
  ↓ 快取預載結果
  
  用戶提問：「active 客戶有多少？」
  → 直接從快取回答，< 200ms
```

#### 5.6.1 預載策略


#### 5.6.2 預載觸發條件

| 條件 | 說明 |
|------|------|
| 意圖信心度 ≥ 0.7 | 只在有足夠信心時才預載，避免浪費資源 |
| 用戶停留 > 5 秒 | 排除快速瀏覽（路過不預載） |
| 同一實體未預載過 | 避免重複預載（有快取就跳過） |
| 預載快取 TTL 5 分鐘 | 過期後下次觸發重新預載 |

### 5.7 延伸分析能力：表格 UI 的能力延伸

當用戶透過艾企提問時，艾企根據已預載的上下文 + Data Agent 能力，提供表格 UI 做不到的分析：

#### 5.7.1 能力對照表

| 用戶想做的 | 表格 UI | 艾企 + Data Agent |
|-----------|---------|------------------|
| 「active 客戶有幾個？」 | ❌ 手動數 | ✅ `SELECT COUNT(*) WHERE status='active'` → 「共 150 位」 |
| 「按地區統計」 | ❌ 無法做 | ✅ `GROUP BY region` → 表格 + 圓餅圖描述 |
| 「平均訂單金額」 | ❌ 無法做 | ✅ `SELECT AVG(amount) FROM orders JOIN customers` |
| 「跟上個月比？」 | ❌ 無法做 | ✅ 自動產生同比查詢 |
| 「哪些客戶 email 是空的？」 | ❌ 只能篩選 | ✅ `WHERE email IS NULL` → 列表 + 數量 |
| 「TOP 10 高價值客戶」 | ❌ 只能排序 | ✅ `ORDER BY total_amount DESC LIMIT 10` |

#### 5.7.2 對話流程範例

```
[操作軌跡]
  用戶選擇 customers 表 → 查看資料 → 篩選 status=active → 翻到第 3 頁

[艾企推斷]
  意圖：在大量 active 客戶中搜尋
  預載：active 客戶總數 = 150、地區分布已查詢

  | 地區   | 客戶數 | 占比   |
  |--------|--------|--------|
  | 台北   | 52     | 34.7%  |
  | 高雄   | 38     | 25.3%  |
  | 台中   | 28     | 18.7%  |
  | 其他   | 32     | 21.3%  |

  需要進一步分析嗎？例如：
  → 「各地區的平均訂單金額？」
```


### 5.10 Action Trail 作為 LangGraph Pipeline 精準度放大器

方案 D 的價值不僅在於「更好的快捷建議」，Action Trail 注入後，整個 LangGraph AI Pipeline 的每個節點都獲得更好的輸入，形成**全鏈路精準度提升**：

#### 5.10.1 各節點精準度對比

| LangGraph 節點 | 無 Action Trail | 有 Action Trail |
|---------------|----------------|-----------------|
| `classify_intent` | 「幫我查一下」→ 不確定意圖 | 「幫我查一下」+ 軌跡：在 customers 表篩選 active → 高信心度 `data_query` |
| `matcher` | 模糊匹配多個意圖 | 精準匹配「資料查詢 > 表內篩選」 |
| `route_by_action` | 可能路由錯誤 | 確定路由到 `da_query`（Data Agent） |
| `da_query` | 「查什麼？哪個表？」→ 需 2-3 輪釐清 | 自動帶入 customers 表 + status=active 條件 → 一輪完成 |
| `ka_search` | 搜尋整個知識庫 → 結果散亂 | 限定在「customers 表」「資料查詢」相關文件 → 精準命中 |
| `chat_responder` | 通用回答 | 帶上下文的情境化回答 |
| `tool_executor` | 工具參數需用戶提供 | 工具參數從軌跡自動預填 |
| `memory_manager` | 記憶模糊的對話 | 記憶精準的意圖鏈，下次對話可延續 |

#### 5.10.2 注入方式

Action Trail 在兩個層面注入 Pipeline：

**層面一：System Prompt 注入**

```
你是「艾企」，AIBox 管理系統的 AI 助手。

## 當前情境
- 頁面：Schema 管理
- 操作軌跡：
  1. 選擇 customers 表
  2. 查看資料
  3. 篩選 status=active
  4. 翻到第 3 頁（仍在搜尋）
- 推斷意圖：用戶在大量 active 客戶中搜尋特定記錄

## 可用能力
- nl2sql：自然語言轉 SQL 查詢
- schema_analysis：表結構分析
- data_profiling：資料概況分析
```

**層面二：TopState 擴展**

```python
class TopState(TypedDict):
    # ... 現有欄位 ...

    # 方案 D 擴展
    action_trail: list[dict[str, object]]      # 操作軌跡序列
    page_ontology: Optional[dict[str, object]]  # 當前頁面 Ontology
    inferred_intent: Optional[str]              # 推斷的意圖
    intent_confidence: float                    # 意圖信心度
    preloaded_context: Optional[dict[str, object]]  # 預載的上下文
```

#### 5.10.3 衍生的三大精準度提升

**1. 工具調用精準度**

```
無 Trail：用戶說「幫我統計」→ 不知道呼叫哪個工具、什麼參數
有 Trail：操作軌跡含 customers + status=active
  → 自動選擇 Data Agent
  → 自動組裝 SQL：SELECT COUNT(*) FROM customers WHERE status='active'
  → 直接回傳結果
```

**2. 知識探索精準度**

```
無 Trail：用戶說「這個怎麼用？」→ RAG 搜整個知識庫
有 Trail：在知識庫管理 → 選了「產品手冊」→ 點擊向量化
  → RAG 限定搜尋：「向量化操作」「常見問題」
  → 精準命中相關文件
```

**3. 內容生成精準度**

```
無 Trail：用戶說「幫我寫個查詢」→ 通用範例 SQL
有 Trail：customers 表 + 看了欄位結構 + 篩選 status
  → 生成貼合場景的 SQL：
    SELECT * FROM customers
    WHERE status = 'active' AND created_at > '2026-03-01'
    ORDER BY created_at DESC
```
