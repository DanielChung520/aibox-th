# EEA 官網規格書（Static Website Spec）

## 1. 產品定位

**EEA — Edge Enterprise AI**  
企業智能代理服務平台（Enterprise Intelligence Agent Platform）

### 產品定位語（Tagline）

> **「企業主權資料 × 混合智能 × 流程自動化」**  
> 以企業自有資料為核心，融合本地化大模型與雲端模型，打造可解釋、可控制、全自動化的企業 AI 平台。

### 目標受眾

| 對象 | 痛點 | EEA 如何解決 |
|------|------|------------|
| 企業決策者 | 資料孤島、AI 幻覺、資料外洩疑慮 | 企業本地化部署，資料不出防火牆 |
| IT 主管 | 多系統整合困難、維運複雜 | 多 Agent 框架 + 標準 API |
| 業務/知識工作者 | 找資料慢、跨系統查詢困難 | NL→SQL + Hybrid RAG |
| 資料分析師 | SQL 門檻高、查詢效率低 | 自然語言驅動，零學習曲線 |
| 流程管理者 | 重複性作業多、審核流程繁瑣 | BPA 自動化 + MCP 工具鏈 |

## 2. 系統核心能力（與官網功能模組對照）

### 2.1 混合模型架構（Hybrid Model Hub）

**說明**：同時接入本地 Ollama / LM Studio 與雲端大模型（OpenAI、阿里 DashScope 等），企業可依資料敏感度選擇模型部署位置。

| 模型類型 | 部署位置 | 適用場景 |
|---------|---------|---------|
| 本地模型 | 企業機房 / VPC | 高敏感資料、內部流程 |
| 雲端模型 | 公有雲 | 通用對話、創意生成 |

- **實作依據**：`ai-services/` 各 Agent 支援 `OLLAMA_BASE_URL`、`LM_STUDIO_URL` 環境變數切換，Embedder 為 Pluggable Provider 設計

### 2.2 知識庫管理（Knowledge Hub）

**說明**：企業文件的智能化攝取、索引與檢索系統。

**核心功能**：
- 文件上傳 → 自動 Chunk → Embedding → 雙軌索引
- 支援 PDF、Word、Excel、Markdown、TXT 等格式
- 向量索引（Qdrant）+ 結構化圖譜索引（ArangoDB）同步維護
- 圖譜抽取：自動從文件中識別實體與關係，構成企業知識圖譜

**實作依據**：
- `ai-services/knowledge_agent/` — 知識庫管理服務
- `ai-services/kb_pipeline/` — 攝取管線（chunking → embedding → indexing → graph extraction）
- `ai-services/kb_pipeline/chunker.py` — 文件分割
- `ai-services/kb_pipeline/embedder.py` — 向量嵌入
- `ai-services/kb_pipeline/qdrant_ops.py` — 向量庫操作
- `ai-services/kb_pipeline/graph.py` — 圖譜三元組抽取
- `ai-services/kb_pipeline/arango_ops.py` — ArangoDB 圖寫入

### 2.3 Hybrid RAG（雙軌檢索增強生成）

**說明**：結合向量語意檢索（Vector RAG）與知識圖譜檢索（Graph RAG），大幅降低 AI 幻覺，提升回答精確性與可解釋性。

**雙軌工作原理**：
```
使用者查詢
    ├── 軌道 A：向量相似度檢索（Qdrant）
    │           → 抓取最相關文本片段
    │           → 提供語意豐富的回答素材
    │
    └── 軌道 B：知識圖譜檢索（ArangoDB）
                → 結構化事實查詢（實體、關係、屬性）
                → 提供可溯源、精確的資料支撐

兩軌結果 → LLM Context → 生成最終回答
```

**與傳統 RAG 比較**：

| 維度 | 傳統 Vector RAG | EEA Hybrid RAG |
|------|----------------|--------------|
| 語意理解 | ✅ 強 | ✅ 強 |
| 事實精確性 | ⚠️ 中等（有幻覺風險） | ✅ 高（圖譜事實支撐） |
| 關係推理 | ❌ 弱 | ✅ 強（Graph Traversal） |
| 可解釋性 | ⚠️ 弱 | ✅ 強（可回溯實體與關係） |
| 部署複雜度 | 簡單 | 中等（本系統已完整實現） |

**實作依據**：`.docs/Spec/知識庫管理/AI-Box-雙軌RAG解析規格書.md`

### 2.4 Data Agent（自然語言資料查詢）

**說明**：將使用者的自然語言轉換為 SQL 查詢，直接對接企業資料庫，無需 SQL 知識。

**Pipeline**：
```
自然語言查詢
    │
    ├── Intent Classification（意圖分類）
    │       └── 判斷：資料查詢 / 知識檢索 / 任務執行
    │
    ├── Intent-RAG（意圖增強）
    │       └── 檢索相似查詢範例，提升生成準確性
    │
    ├── Schema Retrieval（結構還原）
    │       └── 動態獲取資料庫表結構與關係
    │
    ├── NL→SQL Generation（語意轉 SQL）
    │
    ├── SQL Validation（安全驗證）
    │       └── 語法檢查 + 破壞性操作攔截 + 權限過濾
    │
    └── Execution & Rerank（執行 + 排序）
            └── 安全執行，回傳格式化結果
```

**特色**：
- 支援企業多資料來源（ArangoDB Document + Graph Collections）
- 完整的 SQL 安全審查機制
- 查詢意圖分類，避免錯誤路由

**實作依據**：
- `ai-services/data_agent/` — Data Agent 服務
- `ai-services/data_agent/query/nl2sql/orchestrator.py` — NL→SQL 流程
- `ai-services/data_agent/query/nl2sql/sql_generator.py` — SQL 生成
- `ai-services/data_agent/query/nl2sql/validator.py` — 安全驗證
- `ai-services/data_agent/intent_rag/router.py` — Intent-RAG 路由

### 2.5 Knowledge Agent（知識管理 Agent）

**說明**：專門負責企業知識庫的生命週期管理，包括文件上傳、知識圖譜建構、向量索引維護、知識更新與版本管理。

**核心能力**：
- 文件智慧攝取（自動解析、分類、Chunk）
- 雙軌索引維護（Qdrant + ArangoDB 同步更新）
- 圖譜抽取（Entity Extraction + Relation Detection）
- 知識品質監控
- 非同步向量化任務（Celery + SSE 進度追蹤）

**實作依據**：`ai-services/knowledge_agent/main.py`

### 2.6 MCP Tools（微能力工具平台）

**說明**：Micro Capability Platform — 可擴展的工具註冊與執行框架，讓 Agent 能動態呼叫企業內外部工具。

**工具類型**：
| 類型 | 範例 |
|------|------|
| 系統工具 | 檔案操作、系統指令 |
| Web 工具 | 網頁搜尋、API 呼叫 |
| 企業工具 | ERP、CRM、資料庫查詢 |
| 自定義工具 | 企業自建 API、微服務 |

**實作依據**：
- `ai-services/mcp_tools/main.py` — MCP Tools 服務
- `src/pages/BrowseTools.tsx` — 前端工具管理介面

### 2.7 BPA（企業流程自動化）

**說明**：Business Process Automation — 將複雜的企業流程（如：物料管理、審批流程、資料同步）自動化執行。

**目前實現**：
- **物料管理 BPA Agent**（MM Agent）：自動化物料查詢、入庫、出庫、庫存預警流程
- 可串接 MCP Tools 呼叫外部系統
- LLM 輔助決策（自動生成審批意見、流程摘要）

**實作依據**：
- `ai-services/bpa/main.py` — BPA Orchestrator
- `ai-services/bpa/mm_agent/main.py` — 物料管理 Agent

### 2.8 企業資料主權保障

**核心原則**：企業資料為企業自有，Tauri 桌面殼確保本地端無縫整合。

| 安全層面 | 實現方式 |
|---------|---------|
| 資料隔離 | 全本地化部署，零資料外流 |
| 傳輸加密 | HTTPS / WSS 全端 TLS |
| 存取控制 | JWT + RBAC（角色權限管理） |
| AI 輸出審查 | Knowledge Agent + Data Agent 雙重授權把關 |
| 審計追蹤 | 所有資料操作均留存日誌 |

**實作依據**：
- `api/src/middleware/auth.rs` — JWT 鑑權中介層
- `api/src/db/` — ArangoDB 操作層含權限過濾
- `src/stores/auth.ts` — 前端 Token 管理
