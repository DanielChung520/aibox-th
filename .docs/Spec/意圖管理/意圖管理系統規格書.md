## 1. 系統概述

### 1.1 什麼是「意圖」

意圖（Intent）是自然語言輸入與系統動作之間的映射。當使用者說「列出所有採購單」時，系統需要：

1. **辨識意圖**：判斷使用者想做什麼（查詢採購單列表）
2. **定位目標**：知道資料在哪張表（`ERP_13`、sheet_key `1018457`）
3. **產生動作**：生成對應的 AQL 查詢或 Ragic API 呼叫

### 1.2 設計原則

| 原則 | 說明 |
|------|------|
| **Single Source of Truth** | ArangoDB `intent_catalog` 是唯一主資料來源 |
| **識別符統一** | 表單使用 `table_id`（如 `ERP_13`）+ `sheet_key`（如 `1018457`），與 Schema Graph 一致 |
| **向量搜尋副本** | Qdrant 僅作為向量搜尋的同步副本，不可直接寫入 |
| **可學習** | 支援從 AI 對話中學習新增意圖（feedback 機制） |

### 1.3 涵蓋範圍（Agent Scope）

| Agent Scope | 用途 | 意圖數量 |
|---|---|---|
| `data_agent` | NL→AQL 資料查詢（Ragic 表單）| ~155 筆（合併後） |
| `orchestrator` | BPA 任務路由（工作流程） | ~21 筆 |
| `knowledge` | 知識庫 RAG 查詢 | ~10 筆 |

                    │   ArangoDB              │

                             │
                    ┌────────▼────────────────┐
                    │   同步端點              │
                    │   POST /intent-rag/     │
                    │   {scope}/embed-sync    │
                    └────────┬────────────────┘
                             │

### 2.2 資料流方向

```
寫入端（唯一）          →  ArangoDB intent_catalog

查詢端（讀取）          ←  Qdrant（向量相似度搜尋）
管理端（CRUD）          ↔  ArangoDB（前端 / API）
學習端（feedback）      →  ArangoDB（追加 nl_examples）
```

### 3.3 table_id 與 sheet_key 映射來源

表單識別符映射存放在 ArangoDB `da_table_info_ragic` 集合（262 筆）：

```aql
-- 建構映射表
FOR t IN da_table_info_ragic
  LET table_key = CONCAT(t.tab, "/", t.sheet_number)
  RETURN {
    table_key: table_key,       -- "erp/52"
    table_id:  t.table_id,      -- "ERP_13"
    sheet_key: t.sheet_key,     -- "1018457"
    table_name: t.table_name    -- "採購單"
  }
```

| 來源 | 格式 | 範例 |
|------|------|------|

| 自動生成 | `rgc_{tab}_{sheet}_{action}_{lang}` | `rgc_erp_52_list_zh_tw` |
| Orchestrator | `orch_{domain}_{動作}` | `orch_query_intent` |

## 4. 意圖生命週期

### 4.1 意圖來源

```
┌─────────────────┐
│ 1. 手動 Seed    │ → seed_ragic_intents.py → ArangoDB intent_catalog
│    (初始化)      │   粗粒度，含 AQL 模板
└─────────────────┘

┌─────────────────┐
│ 2. MD 匯入      │ → IntentGenerator → ArangoDB intent_catalog
│    (Schema 匯入) │   細粒度，3 action × 3 lang = 9 筆/表
└─────────────────┘

┌─────────────────┐
│ 3. AI 對話學習   │ → feedback API → ArangoDB intent_catalog
│    (增量新增)    │   追加 nl_examples 到既有意圖
└─────────────────┘

┌─────────────────┐
│ 4. 前端 CRUD    │ → Rust API → ArangoDB intent_catalog
│    (人工管理)    │   新增 / 編輯 / 啟停用
└─────────────────┘
```

### 4.2 三級信心度系統

NL Parser 使用三級信心度決定處理策略：

| 等級 | 分數閾值 | 處理方式 |
|------|---------|---------|
| **High** | ≥ 0.65 | 直接使用模板翻譯（最快） |
| **Medium** | 0.45–0.65 | 呼叫 Small LLM 輔助翻譯 |
| **Low** | < 0.45 | 回傳預設參數，請使用者釐清 |

### 4.3 意圖匹配流程

```
使用者輸入
    │
    ▼
RagicNLParser.parse()
    │
    ├─► RagicIntentStore.search() ──► Qdrant 向量搜尋
    │                                   │
    │                          ┌────────┘
    │                          ▼
    │                   top-3 候選意圖
    │                          │
    │              ┌───────────┼───────────┐
    │              ▼           ▼           ▼
    │           score≥0.65  0.45≤s<0.65  s<0.45
    │           (High)      (Medium)     (Low)
    │              │           │           │
    │              ▼           ▼           ▼
    │         template    LLM fallback  default
    │         translate    translate    params
    │              │           │           │
    └──────────────┴───────────┴───────────┘
                        │
                        ▼
                  ParseResult {
                    table_key, translated_params,
                    confidence, intent_matched
                  }
```

## 5. 同步機制

### 5.1 ArangoDB → Qdrant 同步

同步透過 `POST /intent-rag/{scope}/embed-sync` 端點執行：

```
觸發方式：前端「同步到 Qdrant」按鈕
     │
     ▼
Rust API (proxy_sync_qdrant)
     │
     ▼
Python Data Agent (embed-sync endpoint)
     │
     ├─ 1. fetch_intents_from_arango(scope)
     │      → AQL: FOR doc IN intent_catalog
     │        FILTER doc.agent_scope == @scope
     │
     ├─ 2. 對每筆意圖生成向量嵌入
     │      → Ollama /api/embed
     │
     ├─ 3. 重建 Qdrant collection
     │      → PUT /collections/{collection}
     │
     └─ 4. 批次寫入所有 points
            → PUT /collections/{collection}/points
```

### 5.2 Scope 與 Qdrant Collection 映射

```python
SCOPE_QDRANT_MAP = {
    "data_agent":   "data_agent_intents",
    "orchestrator": "orchestrator_intents",
}
```

> **註**：遷移完成後，Pipeline B 的 `ragic_intents` collection 將統一使用 `data_agent_intents`，或在 SCOPE_QDRANT_MAP 中加入對應映射。

### 5.3 同步策略：全量重建

目前採用**全量重建**策略（清除後重新寫入），原因：

- 意圖數量不大（< 200 筆），全量重建耗時 < 30 秒
- 避免增量同步的複雜度（刪除偵測、更新偵測）
- 嵌入向量在模型切換時需完整重新生成

未來若意圖數量超過 1000 筆，可考慮增量同步。

### 5.4 嵌入文本建構

```python
def _intent_to_embed_text(intent):
    parts = list(intent.nl_patterns)        # NL 樣板句
    if intent.description:
        parts.append(intent.description)     # 描述
    parts.append(intent.intent_id.replace("_", " "))  # ID 可讀化
    return " ".join(parts)
```

嵌入模型由 `system_params` 的 `da.embedding_model` 參數控制。

## 8. 現況分析與遷移計劃

### 8.1 現況問題

目前存在**兩條平行且互不相通的 Pipeline**：

#### Pipeline A：統一 Intent Catalog（粗粒度，44 筆 data_agent）

| 環節 | 元件 |
|------|------|
| 寫入 | `seed_ragic_intents.py` → ArangoDB `intent_catalog` |
| 識別符 | `tables: ["ERP_13"]`（正規化 `table_id`） |
| 同步 | 前端按鈕 → Rust proxy → Python `embed-sync` → Qdrant `data_agent_intents` |
| 用途 | NL2SQL pipeline（`orchestrator.py`） |

#### Pipeline B：Ragic Intent Store（細粒度，111 筆）

| 環節 | 元件 |
|------|------|
| 寫入 | MD 匯入 → `IntentGenerator` → `RagicIntentStore.upsert()` → **直接寫入 Qdrant `ragic_intents`**（不經 ArangoDB） |
| 識別符 | `table_key: "erp/52"`（Ragic URL 格式），無 `table_id` |
| 用途 | Query Playground（`POST /ragic/query`）、`nl_parser.py` |

#### 問題總結

1. **兩套識別符不統一**：Pipeline A 用 `table_id`（`ERP_13`），Pipeline B 用 `table_key`（`erp/52`），前端 Schema Graph 顯示 `table_id`，造成對照困難
2. **Pipeline B 繞過 ArangoDB**：IntentGenerator 直接寫 Qdrant，無法從前端管理
3. **兩個 ArangoDB collection**：`intent_catalog`（44 筆 DA）與 `da_ragic_intents`（111 筆），管理負擔
4. **意圖完全不重疊**：兩套 pipeline 的 intent_id 零交集

### 8.2 遷移目標

| # | 目標 | 說明 |
|---|------|------|
| 1 | 統一資料來源 | ArangoDB `intent_catalog` 為唯一 intent collection |
| 2 | 合併意圖 | 將 111 筆 `da_ragic_intents` 合併到 `intent_catalog` |
| 3 | 統一識別符 | 所有意圖補上 `table_id` + `sheet_key`（用 `da_table_info_ragic` 映射） |
| 4 | 統一同步 | 所有 Qdrant 同步走 `embed-sync` 端點 |
| 5 | 修改寫入路徑 | IntentGenerator 改寫 ArangoDB，不再直寫 Qdrant |
| 6 | 廢棄冗餘 | 移除 `da_ragic_intents` collection |

### 8.3 遷移步驟

#### 步驟 1：建立遷移腳本

建立 `ai-services/datalake/migrate_intents_to_catalog.py`，執行以下邏輯：

1. 從 `da_table_info_ragic` 建構 `table_key → table_id + sheet_key` 映射表（262 筆，100% 覆蓋率已驗證）
2. 讀取 `da_ragic_intents` 全部 111 筆
3. 對每筆意圖：
   - 用映射表將 `table_key`（如 `erp/52`）轉換為 `table_id`（如 `ERP_13`）+ `sheet_key`（如 `1018457`）
   - 設定 `tables: [table_id]`
   - 設定 `agent_scope: "data_agent"`
   - 保留 `action`、`nl_patterns`、`description` 等原有欄位
4. 批次 upsert 到 `intent_catalog`（已確認 intent_id 無衝突）
5. 輸出遷移報告

#### 步驟 2：修改 IntentGenerator

修改 `ai-services/data_agent/ragic/intent_generator.py`：

- `table_key` 欄位保留（向下相容）
- 新增 `table_id` 和 `sheet_key` 欄位（從 `da_table_info_ragic` 查詢）

#### 步驟 3：修改 ImportOrchestrator

## 9. 未來擴展

### 9.1 AI 對話學習

透過 `feedback` API，使用者在 AI 對話中確認某個意圖正確時，可自動追加 `nl_examples`：

```
POST /api/v1/intents/catalog/{intent_id}/feedback
{
  "action": "thumbs_up",
  "nl_query": "使用者的原始問句"
}
```

系統將該問句追加到意圖的 `nl_examples` 陣列，下次同步到 Qdrant 後即可增強匹配精度。

### 9.2 自動意圖建議

未來可在 AI 對話中，當意圖匹配信心度 < 0.45 時：
1. 觸發 LLM 分析使用者意圖
2. 建議新增或修改現有意圖
3. 經使用者確認後自動寫入 `intent_catalog`

### 9.3 意圖版本控制

目前意圖更新為直接覆蓋，未來可考慮：
- 新增 `version` 欄位
- 保留歷史版本（audit trail）
- 支援回滾到特定版本
