## 1. 系統概述

### 1.1 什麼是「意圖」

意圖（Intent）是自然語言輸入與系統動作之間的映射。當使用者說「列出所有採購單」時，系統需要：

1. **辨識意圖**：判斷使用者想做什麼（查詢採購單列表）
2. **定位目標**：知道資料在哪張表（`ERP_13`、sheet_key `1018457`）
3. **產生動作**：生成對應的 AQL 查詢或 Ragic API 呼叫

### 1.2 設計原則

| 原則 | 說明 |
|------|------|
| **Single Source of Truth** | ArangoDB `intent_catalog` 是唯一主資料來源 |
| **識別符統一** | 表單使用 `table_id`（如 `ERP_13`）+ `sheet_key`（如 `1018457`），與 Schema Graph 一致 |
| **向量搜尋副本** | Qdrant 僅作為向量搜尋的同步副本，不可直接寫入 |
| **可學習** | 支援從 AI 對話中學習新增意圖（feedback 機制） |

### 1.3 涵蓋範圍（Agent Scope）

| Agent Scope | 用途 | 意圖數量 |
|---|---|---|
| `data_agent` | NL→AQL 資料查詢（Ragic 表單）| ~155 筆（合併後） |
| `orchestrator` | BPA 任務路由（工作流程） | ~21 筆 |
| `knowledge` | 知識庫 RAG 查詢 | ~10 筆 |

## 2. 架構設計

### 2.1 目標架構（統一 Intent Catalog）

```
                    ┌─────────────────────────┐
                    │   ArangoDB              │
                    │   intent_catalog        │
                    │   (Single Source of      │
                    │    Truth)                │
                    └────────┬────────────────┘
                             │
                    ┌────────▼────────────────┐
                    │   同步端點              │
                    │   POST /intent-rag/     │
                    │   {scope}/embed-sync    │
                    └────────┬────────────────┘
                             │
               ┌─────────────┼──────────────┐
               │                            │
      ┌────────▼──────┐           ┌─────────▼─────────┐
      │ Qdrant        │           │ Qdrant            │
      │ data_agent_   │           │ orchestrator_     │
      │ intents       │           │ intents           │
      └───────────────┘           └───────────────────┘
```

> **Data Agent 的 NL 查詢路由**（B+C 混合架構、Path A/B 分流）詳見 [Data Agent 意圖規格書 §3](../NL%20Data%20Query/意圖規格書.md#3-意圖匹配流程)。

### 2.2 資料流方向

```
寫入端（唯一）          →  ArangoDB intent_catalog
同步端（唯讀副本）      →  Qdrant collections（按 scope 分開）
查詢端（讀取）          ←  Qdrant（向量相似度搜尋）
管理端（CRUD）          ↔  ArangoDB（前端 / API）
學習端（feedback）      →  ArangoDB（追加 nl_examples）
```

### 2.3 相關服務

| 服務 | Port | 角色 |
|------|------|------|
| Rust API Gateway | 6500 | 意圖 CRUD、同步代理 |
| Data Agent (Python) | 8003 | embed-sync、intent match、NL 解析 |
| Qdrant | 6333 | 向量搜尋引擎 |
| ArangoDB | 8529 | 主資料儲存 |
| Ollama | 11434 | 向量嵌入模型 |

## 4. 意圖生命週期

### 4.1 意圖來源

```
┌─────────────────┐
│ 1. 手動 Seed    │ → seed_ragic_intents.py → ArangoDB intent_catalog
│    (初始化)      │   粗粒度，含 AQL 模板
└─────────────────┘

┌─────────────────┐
│ 2. MD 匯入      │ → IntentGenerator → ArangoDB intent_catalog
│    (Schema 匯入) │   細粒度，3 action × 3 lang = 9 筆/表
└─────────────────┘

┌─────────────────┐
│ 3. AI 對話學習   │ → feedback API → ArangoDB intent_catalog
│    (增量新增)    │   追加 nl_examples 到既有意圖
└─────────────────┘

┌─────────────────┐
│ 4. 前端 CRUD    │ → Rust API → ArangoDB intent_catalog
│    (人工管理)    │   新增 / 編輯 / 啟停用
└─────────────────┘
```

### 4.2 意圖匹配

各 Agent 的意圖匹配流程由各自專屬規格定義：

- **Data Agent**：三級信心度系統（High/Medium/Low）+ B+C 混合路由（Path A Tool-Calling / Path B Pandas/DuckDB）→ 見 [Data Agent 意圖規格書 §3](../NL%20Data%20Query/意圖規格書.md#3-意圖匹配流程)
- **Orchestrator**：向量匹配 + confidence_threshold → 路由到對應 Agent（待建立規格）

## 5. 同步機制

### 5.1 ArangoDB → Qdrant 同步

同步透過 `POST /intent-rag/{scope}/embed-sync` 端點執行：

```
觸發方式：前端「同步到 Qdrant」按鈕
     │
     ▼
Rust API (proxy_sync_qdrant)
     │
     ▼
Python Data Agent (embed-sync endpoint)
     │
     ├─ 1. fetch_intents_from_arango(scope)
     │      → AQL: FOR doc IN intent_catalog
     │        FILTER doc.agent_scope == @scope
     │
     ├─ 2. 對每筆意圖生成向量嵌入
     │      → Ollama /api/embed
     │
     ├─ 3. 重建 Qdrant collection
     │      → PUT /collections/{collection}
     │
     └─ 4. 批次寫入所有 points
            → PUT /collections/{collection}/points
```

### 5.2 Scope 與 Qdrant Collection 映射

```python
SCOPE_QDRANT_MAP = {
    "data_agent":   "data_agent_intents",
    "orchestrator": "orchestrator_intents",
}
```

### 5.3 同步策略與實作細節

目前採用**全量重建**策略（清除後重新寫入）。嵌入文本建構、模型配置等實作細節見 [Data Agent 意圖規格書 §5](../NL%20Data%20Query/意圖規格書.md#5-embed-sync-同步行為)。

## 6. API 端點

### 6.1 Rust API Gateway（Port 6500）

| 方法 | 端點 | 說明 |
|------|------|------|
| GET | `/api/v1/intents/catalog` | 列表查詢（分頁、篩選） |
| POST | `/api/v1/intents/catalog` | 新增意圖 |
| PUT | `/api/v1/intents/catalog/{intent_id}` | 更新意圖 |
| DELETE | `/api/v1/intents/catalog/{intent_id}` | 刪除意圖 |
| POST | `/api/v1/intents/catalog/{intent_id}/feedback` | 回饋學習（thumbs_up 追加 nl_examples） |
| POST | `/api/v1/intents/sync-qdrant` | 同步到 Qdrant（代理轉發） |
| GET | `/api/v1/intents/models` | 列出 Ollama 模型（代理轉發） |

#### 列表查詢參數

| 參數 | 類型 | 說明 |
|------|------|------|
| `agent_scope` | string | **必填**，`data_agent` / `orchestrator` |
| `page` | number | 頁碼，預設 1 |
| `page_size` | number | 每頁筆數，預設 20 |
| `status` | string | 篩選狀態 |
| `intent_type` | string | 篩選意圖類型 |
| `group` | string | 篩選群組 |
| `generation_strategy` | string | 篩選策略 |
| `search` | string | 全文搜尋（description / intent_id / name） |

#### 回應格式

```json
{
  "code": 0,
  "data": {
    "records": [ /* IntentCatalogEntry[] */ ],
    "total": 155,
    "page": 1,
    "page_size": 20
  }
```

### 9.2 AI 對話學習

透過 `feedback` API，使用者在 AI 對話中確認某個意圖正確時，可自動追加 `nl_examples`：

```
POST /api/v1/intents/catalog/{intent_id}/feedback
{
  "action": "thumbs_up",
  "nl_query": "使用者的原始問句"
}
```

系統將該問句追加到意圖的 `nl_examples` 陣列，下次同步到 Qdrant 後即可增強匹配精度。

### 9.3 自動意圖建議

未來可在 AI 對話中，當意圖匹配信心度 < 0.45 時：
1. 觸發 LLM 分析使用者意圖
2. 建議新增或修改現有意圖
3. 經使用者確認後自動寫入 `intent_catalog`

### 9.4 意圖版本控制

目前意圖更新為直接覆蓋，未來可考慮：
- 新增 `version` 欄位
- 保留歷史版本（audit trail）
- 支援回滾到特定版本
