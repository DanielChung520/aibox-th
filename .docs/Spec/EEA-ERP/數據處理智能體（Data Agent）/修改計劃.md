# Data Agent 修改計劃

## 修改歷程

| 日期 | 版本 | 更新者 | 變更內容 |
|------|------|--------|----------|
| 2026-04-16 | 1.0.0 | Daniel Chung | 初始版本 |

---

## 1. 修改目標

將 Data Agent 從「全自主 NL→SQL over S3」遷移為「接收艾企精準指令的結構化查詢執行器」，同時整合本地 SQL 專用模型（duckdb-nsql / sqlcoder）。

### 1.1 核心變更

| 項目 | 現狀 | 目標 |
|------|------|------|
| 意圖判斷 | Data Agent 自己用 Qdrant 猜 | 艾企已判斷好，Data Agent 不猜 |
| Schema 檢索 | Data Agent 從 ArangoDB 查 schema | 艾企已附帶 fields，可跳過 |
| SQL 生成模型 | 通用 LLM (qwen3-coder) | 專用 SQL 模型 (duckdb-nsql) |
| 資料源 | S3 parquet (httpfs) | Server DuckDB Cache / ArangoDB |
| 呼叫方式 | 純自然語言輸入 | 結構化指令（帶 table/fields/filters） |

### 1.2 不變的部分

- SQL 驗證器（`validator.py`）— 三層驗證保留
- 錯誤解釋器（`error_explainer.py`）— 保留
- 日期工具（`date_utils.py`）— 保留
- Ragic 子模組（`ragic/`）— 保留不動
- Intent RAG 子模組（`intent_rag/`）— 保留不動
- 現有端點（`/query/query`, `/query/plan`, `/query/explain`）— 保留相容

## 2. 實作階段

### Phase 1：結構化查詢端點 + SQL 模型整合（P0）

**預計工時**：2-3 天

#### Step 1.1：新增 Pydantic 模型

**檔案**：`ai-services/data_agent/query/nl2sql/models.py`

新增以下模型（不修改現有模型）：

```python
class StructuredFilter(BaseModel):
    """結構化查詢過濾條件。"""
    field: str
    op: str = "eq"  # eq, ne, gt, lt, gte, lte, like, in, between
    value: str | list[str] = ""

class StructuredSort(BaseModel):
    """結構化查詢排序。"""
    field: str
    order: str = "asc"  # asc, desc

class StructuredQueryRequest(BaseModel):
    """結構化查詢請求 — 艾企 Agent 呼叫。"""
    table: str
    table_id: str = ""
    intent: str = "list"  # count, list, aggregate, filter, top_n, trend, detail
    fields: list[str] = Field(default_factory=list)
    filters: list[StructuredFilter] = Field(default_factory=list)
    aggregations: list[str] = Field(default_factory=list)
    group_by: list[str] = Field(default_factory=list)
    sort: StructuredSort | None = None
    limit: int = 100
    source: str = "server_cache"

class NLQueryRequest(BaseModel):
    """帶 hints 的自然語言查詢請求。"""
    natural_language: str
    table_hint: str = ""
    table_id_hint: str = ""
    field_hints: list[str] = Field(default_factory=list)
    source: str = "server_cache"

class StructuredQueryResult(BaseModel):
    """結構化查詢結果。"""
    success: bool
    generated_sql: str = ""
    execution_result: SQLResult | None = None
    model_used: str = ""
    fallback_model_used: str = ""
    attempts: int = 0
    error: str = ""
    total_time_ms: float = 0.0
```

**預計工時**：1 天

```python

    if getattr(config, "query_source", "") == "server_cache":
        return await execute_on_server_cache(sql)
    # 保留原有 S3 httpfs 邏輯作為 fallback
    ...
```

#### Step 2.2：修改 sql_generator.py 的 Prompt

## 5. 風險與緩解

| 風險 | 影響 | 緩解 |
|------|------|------|
| duckdb-nsql 生成不正確的 DuckDB SQL | 查詢失敗 | 三層驗證 + sqlcoder fallback + 重試機制 |
| Server DuckDB Cache 中表不存在 | 查詢失敗 | 回傳明確錯誤，艾企可引導用戶先載入資料 |
| 舊端點使用者（如果有） | 相容性問題 | 保留所有舊端點，僅標記 DEPRECATED |
| 本地模型推理速度慢 | 延遲高 | duckdb-nsql 3.8GB 小模型，推理 <2s |
| Prompt 注入 | 安全性 | validator.py 三層驗證 + SELECT-only 執行層 |
