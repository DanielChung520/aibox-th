## §1 範式總論

### 1.1 命題

AI-SCM（AI-Enabled Supply Chain Intelligence）是一個將 AI 智能層疊加在既有 ERP 系統之上的供應鏈架構範式。

**核心命題**：

```
┌────────────────────────────────────────────────────┐
│                                                    │
│  企業已有完整的 Ragic ERP 交易系統。               │
│  不需要另一個系統來取代它。                        │
│                                                    │
│  AI Agent 的價值不在「取代交易」，                │
│  而在「交易之上的 intelligence」。                 │
│                                                    │
│  Ragic 管交易（Transaction Layer）                │
│  AI 管智能（Intelligence Layer）                  │
│                                                    │
│  不重疊、不取代、不競爭。                          │
│  疊加、增值、進化。                                │
│                                                    │
└────────────────────────────────────────────────────┘
```

### 1.2 設計原則

| 原則                                             | 說明                                                                                                                          |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| **Boundary First（邊界優先）**             | 先釐清「AI 不做什麼」再決定「AI 做什麼」。Ragic 的交易/流程/簽核不動，AI 只做預測、建議、異常、跨系統推理                     |
| **Intelligence Gradient（智能梯度）**      | 不是所有 Agent 都需要強 AI。資料層以規則為主（20% AI），策略層以分析為主（60% AI），根據需求配置適當的 AI 濃度                |
| **Value Chain Vertical（價值鏈垂直整合）** | 每個 Agent 不是孤立的，而是沿著供應鏈價值傳遞：請購→採購→交期→生產→客戶，Agent 間的資料流需明確設計                       |
| **Read-Only to Ragic（唯讀原則）**         | AI Agent 對 Ragic 的交易資料僅讀取不寫入。所有寫入操作仍由 Ragic Workflow 或人員手動完成，AI 只產出「建議」與「決策支援資訊」 |

### 1.3 適用範圍

本範式適用於：

- **產業**：以 BOM 展開 + 工單生產為核心的製造業（特別是車輛改裝、設備製造等）
- **ERP 基礎**：已導入 Ragic 或類似低程式碼平台作為交易層的企業
- **AI 成熟度**：已有或可取得 12B 等級本地 LLM（如 Qwen2.5 14B）
- **組織規模**：中型企業（20-200 人），採購/倉管/品管/生產/財務角色分工明確

## §2 六點 AI 價值矩陣

### 2.1 價值定義

以下六點構成 AI-SCM 範式的核心價值主張。每一個 AI Agent 的設計，都必須回答「我在這六點中貢獻哪幾點」。

```
┌────────────────────────────────────────────────────────────┐
│  AI-SCM 六點 AI 價值                                       │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  P1 🧠 預測（Prediction）                                  │
│     需求預測、價格趨勢、風險預警                            │
│     範例：「下季採購預算需增加 12%，主要來自升降機成本」    │
│                                                            │
│  P2 ⚡ 異常偵測（Anomaly Detection）                       │
│     跨維度異常（品質趨勢、合規缺口、價格偏離）              │
│     範例：「C 供應商報價偏離歷史均價 22%，建議確認規格」    │
│                                                            │
│  P3 💬 自然語言查詢（NL Query）                            │
│     7 個角色隨時提問，跨表查詢                              │
│     範例：「這台福特旅行車還差哪些料沒到？」                │
│                                                            │
│  P4 🎯 決策建議（Decision Support）                        │
│     TCO 建議、替代方案、供應商推薦                          │
│     範例：「建議優先考慮 A 供應商，交期準確率 98%」         │
│                                                            │
│  P5 📡 自動溝通（Automated Communication）                 │
│     LINE/Email 催貨、異常通報、供應商互動                   │
│     範例：「PO-2026-0123 已逾期 3 天，自動發送催貨通知」    │
│                                                            │
│  P6 🔗 跨系統串聯（Cross-system Orchestration）            │
│     採購→生產→財務→客戶，全鏈路關聯                         │
│     範例：「這批延遲將影響張三的車，交車延後 5 天」          │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

### 2.2 與 Ragic 的分工邊界

這六點價值正好對應 Ragic 做不好（或根本不做）的領域：

| AI 價值點       | Ragic 現有能力                        | AI-SCM 補足                                                    |
| --------------- | ------------------------------------- | -------------------------------------------------------------- |
| P1 預測         | ❌ 無：只能查歷史資料，無法預測       | ✅ 需求預測、價格趨勢、風險預警                                |
| P2 異常偵測     | ⚠️ 基本比對：僅能做到同表單數值比對 | ✅ 跨維度異常：品質趨勢、合規缺口、跨表價格偏離                |
| P3 自然語言查詢 | ❌ 無：僅能透過表單欄位篩選           | ✅ 7 個角色隨時提問，一句話跨表查詢                            |
| P4 決策建議     | ⚠️ 基本公式：TCO 公式、IF 判斷      | ✅ 綜合分析 + 語言生成：TCO 建議、替代方案推薦、供應商評價說明 |
| P5 自動溝通     | ⚠️ 基本通知：僅系統內通知           | ✅ 多渠道溝通：LINE 催貨、Email 報告、供應商互動、異常通報     |
| P6 跨系統串聯   | ❌ Ragic 表單孤島：需人工關聯         | ✅ 全鏈路追溯：採購→生產→財務→客戶，自動關聯分析            |

### 2.3 各價值點的 AI 技術需求

| 價值點          | AI 難度 | 建議模型            | 技術實作                                 |
| --------------- | :-----: | ------------------- | ---------------------------------------- |
| P1 預測         |   中   | 12B+ LLM + 統計模型 | 時間序列分析 + LLM 解讀                  |
| P2 異常偵測     |  低-中  | 規則引擎 + 小模型   | 門檻邏輯 + LLM 異常描述                  |
| P3 自然語言查詢 |   中   | 12B LLM + NL2Query  | Intent Classification + Query Generation |
| P4 決策建議     |   中   | 12B LLM             | 結構化數據 + LLM 綜合評述生成            |
| P5 自動溝通     |   低   | 模板引擎 + 小模型   | 條件觸發 + 語言模板 + LLM 個人化         |
| P6 跨系統串聯   |  中-高  | 12B+ LLM            | 知識圖譜 + LLM 推理鏈                    |

## §3 四層智能架構

### 3.1 架構總覽

AI-SCM 的 Agent 按其在供應鏈中的職責與 AI 濃度，分為四個層級：

```
┌────────────────────────────────────────────────────────────┐
│                   AI-SCM 四層智能架構                       │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  Layer 4 ─ 治理與策略層（AI 濃度 60%）                    │
│  ┌──────────────────────────────────────────────────┐     │
│  │  🅲 供應商治理官    🅳 供應鏈指揮官   🅴 合規監察官 │     │
│  │  策略分析 | 評鑑管理 | 儀表板 | 審計             │     │
│  └──────────────────────────────────────────────────┘     │
│                                                            │
│  Layer 3 ─ 協同與異常層（AI 濃度 40%）                    │
│  ┌──────────────────────────────────────────────────┐     │
│  │  🅱 採購智能助理（跟催+變更+品管模組）              │     │
│  │  跨部門協調 | 異常處理 | 影響評估                 │     │
│  └──────────────────────────────────────────────────┘     │
│                                                            │
│  Layer 2 ─ 執行與決策層（AI 濃度 20%）                    │
│  ┌──────────────────────────────────────────────────┐     │
│  │  🅱 採購智能助理（請購+詢價+驗收模組）              │     │
│  │  日常決策支援 | 數據驅動建議                     │     │
│  └──────────────────────────────────────────────────┘     │
│                                                            │
│  Layer 1 ─ 資料與感知層（AI 濃度 10%）                    │
│  ┌──────────────────────────────────────────────────┐     │
│  │  🅰 供應鏈 Data Agent                             │     │
│  │  Ragic 唯讀橋接 | 跨表查詢 | NL2Query           │     │
│  └──────────────────────────────────────────────────┘     │
│                                                            │
├────────────────────────────────────────────────────────────┤
│  ⚡ 橫向支撐層（所有 Agent 共用）                          │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────────┐ │
│  │ 通知引擎  │ │ 知識庫   │ │ 安全層   │ │ LLM 網關     │ │
│  │ LINE/Email│ │ SOP+FAQ  │ │ RBAC審計 │ │ 12B本地+雲端 │ │
│  └──────────┘ └──────────┘ └──────────┘ └──────────────┘ │
└────────────────────────────────────────────────────────────┘
```

### 3.2 Layer 1：資料與感知層

**定位**：整個 AI-SCM 的資料底座。唯一能直接查詢 Ragic 的層級，所有上層 Agent 的資料需求都經由這一層。

**負責 Agent**：🅰 **供應鏈 Data Agent**

| 面向     | 說明                                              |
| -------- | ------------------------------------------------- |
| 核心能力 | NL2Query（自然語言→AQL/SQL）、跨表關聯、快取加速 |
| 資料來源 | Ragic API（唯讀）+ ArangoDB（快取/彙總）          |
| 使用者   | 上層所有 Agent + 人員直接查詢                     |
| AI 濃度  | 10%（主要靠規則，特殊查詢用 LLM）                 |
| 關鍵設計 | 唯讀原則：不寫入 Ragic，不修改交易資料            |

### 3.3 Layer 2：執行與決策層

**定位**：日常採購作業的 AI 輔助層。協助人員做判斷，但不取代人的決策。

**負責 Agent**：🅱 **採購智能助理**（模組化設計）

|   模組   | 功能                                     |  對應原需求  |
| :------: | ---------------------------------------- | :----------: |
| 請購規劃 | BOM 展開→庫存比對→需求預測→請購建議   | PA-01, PA-02 |
|  詢比價  | 供應商匹配→TCO 比較→異常標記→推薦說明 | PA-03, PA-04 |
| 驗收比對 | 進貨比對→檢驗分流→不合格建議→庫存更新 |    PA-07    |
| 品質監控 | 品檢趨勢分析→供應商品質評分→特採建議   |    PA-08    |

### 3.4 Layer 3：協同與異常層

**定位**：需要跨部門協調的異常處理與影響評估。AI 濃度較高，需要推理能力。

**負責 Agent**：🅱 **採購智能助理**（進階模組）

|   模組   | 功能                                   | 對應原需求 |
| :------: | -------------------------------------- | :--------: |
| 跟單催貨 | 交期監控→分級提醒→影響評估→自動催貨 |   PA-05   |
| 變更評估 | 變更影響鏈追蹤→成本差異→替代方案     |   PA-06   |

### 3.5 Layer 4：治理與策略層

**定位**：管理層的策略分析與決策支援。AI 濃度最高，需要綜合分析與預測能力。

**負責 Agent**：

|          Agent          | 功能                                               |   AI 價值點   |   對應原需求   |
| :----------------------: | -------------------------------------------------- | :------------: | :------------: |
| 🅲**供應商治理官** | 供應商評鑑自動化、績效趨勢、風險預警、策略建議     | P1, P2, P4, P6 |     PA-09     |
| 🅳**供應鏈指揮官** | 跨流程儀表板、異常摘要、預算預測、Why 分析         | P1, P2, P3, P6 |     PA-10     |
|  🅴**合規監察官**  | 比價合規檢查、授權差異偵測、SOP 偏離預警、審計追蹤 |   P2, P4, P6   | **全新** |

> 🅴 **合規監察官** 是原需求（Excel 的 10 個 Agent + 規劃的 5 個 Agent）皆未涵蓋的新 Agent。理由是：企業供應鏈越成熟，合規與審計的需求越高。AI 在此處的價值是「自動化檢查原本靠人力翻查的合規事項」。

### 3.6 橫向支撐層

所有 Agent 共用的基礎設施：

| 元件               | 說明                              | 採用技術                        |
| ------------------ | --------------------------------- | ------------------------------- |
| **通知引擎** | 多渠道訊息發送                    | LINE Messaging API / Email SMTP |
| **知識庫**   | QP 系列作業標準、FAQ、歷史案例    | Knowledge Agent（RAG）          |
| **安全層**   | 身份驗證、權限檢查、審計日誌      | EEA Security Agent 模式         |
| **LLM 網關** | 模型路由、Prompt 管理、Token 計費 | 既有 LLM Gateway                |

```
│              🅱 採購智能助理                             │
│                     │                                   │
│                     │ Layer 1-2 結構化資料               │
│                     ▼                                   │
│              🅰 供應鏈 Data Agent                       │
│                     │                                   │
│                     │ Ragic API（唯讀）                  │
│                     ▼                                   │
│              🗄️ Ragic ERP（交易層）                     │
└─────────────────────────────────────────────────────────┘

觸發流方向（從上往下 + 事件驅動）：
  🅱 異常事件 → 🅲 供應商評分更新 + 🅳 儀表板更新 + 🅴 合規檢查
  🅳 策略決策 → 🅱 採購策略調整
  🅴 違規事件 → 🅱 採購流程修正 + 🅲 供應商評分扣減
```

## §5 35 題 QA 全覆蓋對應

### 5.1 覆蓋率分析

Excel 中 7 個角色 × 5 題 = 35 題 QA，經重新分類後：

| 問題類型    | 題數 | 佔比 |   AI 需求   |       主要負責 Agent       |
| ----------- | :--: | :--: | :----------: | :-------------------------: |

## §7 實作建議

### 7.1 導入順序

```
Phase 1 ─ 立即有感（2-3 週）
  🅱 採購智能助理（跟催模組 + 驗收模組）
  → 倉管/採購每天用，規則為主，立即見效

Phase 2 ─ 核心價值（3-4 週）
  🅰 供應鏈 Data Agent（NL2Query 底座）
  🅱 採購智能助理（請購規劃模組 + 詢比價模組）
  → 建立資料查詢能力 + 前端採購作業 AI 化

Phase 3 ─ 管理優化（4-6 週）
  🅲 供應商治理官
  🅳 供應鏈指揮官
  🅱 採購智能助理（變更評估模組 + 品質監控模組）
  → 管理層決策支援

Phase 4 ─ 治理強化（3-4 週）
  🅴 合規監察官
  → 成熟企業必備的合規自動化
```

### 7.2 Dashboard 規劃

AI-SCM Dashboard 作為 ABC Desktop 中的一個新頁面，提供：

1. **六點 AI 價值可視化**：展示每個價值點的當前狀態與覆蓋率
2. **Agent 狀態總覽**：各 Agent 的運作狀態、事件摘要
3. **供應鏈健康度**：關鍵 KPI（逾期率、合格率、金額趨勢）
4. **快速查詢入口**：自然語言查詢框 + 常用查詢快捷鍵
