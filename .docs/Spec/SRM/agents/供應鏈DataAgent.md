## §1 定位與職責

### 1.1 定位

供應鏈 Data Agent 是 AI-SCM 體系中唯一的資料基礎層 Agent，位於 Layer 1 資料與感知層。它不直接參與供應鏈業務決策，而是為所有上層 Agent（採購智能助理、供應商治理官、供應鏈指揮官、合規監察官）提供統一且一致的結構化資料查詢能力。

```
┌─────────────────────────────────────────────────────────┐
│  上層 Agent                                             │
│  🅱 採購智能助理  🅲 供應商治理官                        │
│  🅳 供應鏈指揮官  🅴 合規監察官                          │
│         ↑               ↑               ↑               │
│         └───────────┬───┴───────────────┘               │
│                     │ Layer 1-2 結構化資料               │
│                     ▼                                   │
│              🅰 供應鏈 Data Agent                        │
│                     │                                   │
│                     │ NL2Query + Ragic API（唯讀）       │
│                     ▼                                   │
│              🗄️ Ragic ERP（交易層）                     │
└─────────────────────────────────────────────────────────┘
```

### 1.2 職責範圍

| 項目 | 說明 |
|------|------|
| 核心功能 | 自然語言轉 AQL/SQL 查詢、跨表關聯查詢、結果快取加速 |
| 資料來源 | Ragic API（唯讀）+ ArangoDB（快取/彙總） |
| 服務對象 | 上層所有 Agent + 人員直接查詢 |
| AI 濃度 | 10%（主要靠規則匹配，特殊查詢用 LLM 補充） |
| 查詢類型 | 結構化資料查詢、彙總統計、趨勢資料、狀態查詢 |

### 1.3 非職責範圍

| 不處理項目 | 原因 |
|-----------|------|
| 交易資料寫入 | RAGIC 邊界原則：AI 不寫入交易資料 |
| 決策建議生成 | 屬於 L2/L4 Agent 的職責 |
| 異常偵測 | 屬於 L3/L4 Agent 的職責 |
| 自動溝通發送 | 屬於 L3 Agent 的職責 |
| 合規檢查判斷 | 屬於 L4 Agent 的職責 |
| 供應商評分計算 | 屬於 L4 Agent 的職責 |

## §2 AI 價值對應

### 2.1 價值貢獻

供應鏈 Data Agent 貢獻六點 AI 價值中的兩點：

| AI 價值 | 貢獻程度 | 說明 |
|:-------:|:--------:|------|
| P1 預測 | - | 不直接參與預測，但提供預測所需的歷史資料 |
| P2 異常偵測 | - | 不直接偵測異常，但提供異常比對所需的基準資料 |
| **P3 自然語言查詢** | **主要** | 核心價值：將自然語言問題轉換為結構化查詢，讓非技術人員也能查詢 Ragic 資料 |
| **P6 跨系統串聯** | **主要** | 提供一致的查詢介面，讓上層 Agent 無需各自對接 Ragic，實質實現跨 Agent 的資料串聯 |
| P4 決策建議 | - | 不產生建議，但提供建議所需的數據基礎 |
| P5 自動溝通 | - | 不直接溝通，但提供溝通所需的資料查詢 |

### 2.2 橫向支撐依賴

| 支撐元件 | 用途 |
|---------|------|
| LLM 網關 | NL2Query 轉換需要 LLM 協助解析自然語言 |
| 快取層（ArangoDB） | 快取頻繁查詢結果，降低 Ragic API 呼叫頻率 |
| 安全層（RBAC） | 控制查詢權限，確保使用者只能查詢授權範圍內的資料 |

## §3 RAGIC 邊界

### 3.1 唯讀原則

供應鏈 Data Agent **嚴格遵守唯讀原則**：

```
✅ 允許的操作：
   - 讀取 Ragic 表單資料（GET API）
   - 查詢彙總統計資訊
   - 快取查詢結果到 ArangoDB
   - 格式化查詢結果回傳

❌ 禁止的操作：
   - 建立/更新/刪除 Ragic 表單記錄
   - 執行 Ragic Workflow 觸發
   - 修改 Ragic 表單結構或欄位定義
   - 寫入任何交易資料到 Ragic
```

### 3.2 讀取表單清單

供應鏈 Data Agent 可讀取的 Ragic SCM 相關表單：

| 供應商分類 | 廠商類別設定 | — | 供應商分類查詢 |
| 產品主檔 | PLM-產品主檔維護 | — | BOM/物料查詢 |
| 採購需求 | 採購需求估算 | — | MRP 需求查詢 |
| 採購建議 | 採購建議書 | — | 採購建議查詢 |
| 詢價單 | 詢價單 / 詢價憑單 | — | 詢價記錄查詢 |
| 採購單 | 採購單 / 採購憑單 | — | PO 查詢 |

### 3.3 資料快取策略

| 快取類型 | 適用情境 | TTL | 儲存位置 |
|---------|---------|:---:|---------|
| 查詢結果快取 | 重複性高的查詢（如供應商清單） | 5 分鐘 | ArangoDB |
| 彙總快取 | 統計數據（如各供應商品質統計） | 15 分鐘 | ArangoDB |
| Schema 快取 | Ragic 表結構定義 | 1 小時 | ArangoDB |
| 不適用快取 | 即時狀態查詢（如當日到貨） | 無快取 | 直接查詢 Ragic |

## §4 核心能力

### 4.1 NL2Query 橋接

將使用者的自然語言問題轉換為 Ragic 可執行的查詢：

```
使用者輸入：                       🅰 Data Agent:
"這台福特旅行車還缺哪些料？"       → 意圖識別：物料短缺查詢
                                   → 參數萃取：車型=福特旅行車
                                   → 表單定位：採購單 + 收貨單 + BOM
                                   → 查詢生成：AQL 跨表 JOIN
                                   → 結果格式化：短缺清單 + 數量
```

轉換流程：

| 步驟 | 說明 | AI 需求 |
|:----:|------|:-------:|
| 1. 意圖分類 | 判斷查詢類型（庫存/訂單/品質/交期...） | 規則 + LLM（10%） |
| 2. 參數萃取 | 從自然語言中萃取關鍵參數（車型/日期/供應商...） | LLM（30%） |
| 3. 表單定位 | 根據意圖與參數決定查詢哪些 Ragic 表單 | 規則（90%） |
| 4. 查詢生成 | 產生對應的 AQL 查詢語句 | 模板 + 規則（95%） |
| 5. 結果回傳 | 執行查詢並格式化回傳 | 規則（100%） |

### 4.2 跨表關聯查詢

支援三種跨表查詢模式：

| 模式 | 說明 | 範例 |
|:----:|------|------|
| 垂直查詢 | 單一表單的條件篩選 | 「查詢 A 供應商所有未結訂單」 |
| 水平查詢 | 跨表單的關聯查詢 | 「查詢 B 工單對應的採購單與到貨狀態」 |
| 彙總查詢 | 跨表單的統計彙總 | 「統計本月各供應商交貨遲延天數」 |

### 4.3 查詢快取加速

| 機制 | 說明 |
|------|------|
| 基於查詢簽章的快取 | 對查詢語句 + 參數進行 hash 作為快取鍵 |
| 分級 TTL | 根據資料變動頻率設定不同的過期時間 |
| 主動失效 | 當上層 Agent 通知資料變更時主動清除相關快取 |
| 冷熱分離 | 高頻查詢結果保留在記憶體，低頻查詢從 ArangoDB 讀取 |

### 4.4 結果格式化

| 輸出格式 | 適用情境 | 說明 |
|:--------:|---------|------|
| 表格（Markdown） | 人員直接查詢 | 以可讀性高的 Markdown 表格呈現 |
| JSON | Agent 間呼叫 | 結構化資料供上層 Agent 進一步處理 |
| 摘要文字 | 快速查詢 | 彙總關鍵數據以自然語言呈現 |
| 圖表資料 | Dashboard | 提供圖表渲染所需的數值資料 |

## §5 輸入輸出規格

### 5.1 查詢請求

| 欄位 | 型別 | 必填 | 說明 |
|:----:|:----:|:----:|------|
| query | string | ✅ | 自然語言查詢內容 |
| source | string | ❌ | 請求來源（agent_key / user_id），預設為 direct |
| format | enum | ❌ | 輸出格式：table / json / summary / chart，預設 table |
| cache | boolean | ❌ | 是否啟用快取，預設 true |
| context | object | ❌ | 上下文資訊（當前頁面、最近查詢等） |

請求範例：

```json
{
  "query": "這台福特旅行車還缺哪些料？",
  "source": "user-abc-123",
  "format": "table",
  "cache": true,
  "context": {
    "page": "production-dashboard",
    "recent_queries": ["工單 FO-2026-0042 的進度"]
  }
}
```

### 5.2 查詢回應

| 欄位 | 型別 | 必填 | 說明 |
|:----:|:----:|:----:|------|
| status | string | ✅ | ok / error |
| data | array | ✅ | 查詢結果陣列（每筆記錄一個物件） |
| format | string | ✅ | 實際回傳格式 |
| summary | string | ❌ | 人工可讀的摘要說明 |
| meta | object | ✅ | 查詢詮釋資料 |
| meta.tables_used | array | ✅ | 本次查詢涉及的 Ragic 表單 |
| meta.rows_returned | integer | ✅ | 回傳筆數 |
| meta.cache_hit | boolean | ✅ | 是否為快取結果 |
| meta.query_time_ms | integer | ✅ | 查詢耗時 |

回應範例：

```json
{
  "status": "ok",
  "data": [
    {
      "物料編號": "BRK-001",
      "物料名稱": "煞車鼓總成",
      "需求數量": 2,
      "已採購": 1,
      "已到貨": 0,
      "短缺數量": 1,
      "預計交期": "2026-06-20"
    },
    {
      "物料編號": "SUS-004",
      "物料名稱": "後懸吊彈簧",
      "需求數量": 2,
      "已採購": 0,
      "已到貨": 0,
      "短缺數量": 2,
      "預計交期": null
    }
  ],
  "format": "table",
  "summary": "福特旅行車 FO-2026-0042 工單目前短缺 2 項物料，共 3 件。",
  "meta": {
    "tables_used": ["生產製令單", "採購單", "收貨單", "PLM-產品主檔維護"],
    "rows_returned": 2,
    "cache_hit": false,
    "query_time_ms": 342
  }
}
```

### 5.3 錯誤回應

| 錯誤類型 | HTTP 狀態碼 | 說明 |
|:--------:|:----------:|------|
| 意圖無法識別 | 400 | 查詢內容無法對應任何已知意圖 |
| 參數不足 | 400 | 查詢缺少必要參數（如未指定車型） |
| 表單無法存取 | 403 | 請求來源無權限查詢特定表單 |
| 資料來源錯誤 | 502 | Ragic API 連線失敗或回應異常 |
| 查詢逾時 | 504 | 查詢超過 10 秒仍未回傳 |

## §7 實作筆記

### 7.1 技術選型

| 元件 | 建議技術 | 說明 |
|:----:|---------|------|
| NL2Query 引擎 | LLM + 規則引擎 | 12B 本地 LLM 處理複雜查詢，規則引擎處理 80% 標準查詢 |
| 快取層 | ArangoDB | 專用快取集合，設定 TTL index |
| Ragic 橋接 | Ragic API Client | 既有 DA 的 Ragic 連線模組 |
| API 端點 | /api/v1/da/scm/query | 由 Rust Gateway 轉發 |
| 輸出格式化 | 模板引擎 | Jinja2 風格模板，支援多種輸出格式 |

### 7.2 查詢管線

```
使用者 / Agent
    │
    ▼
┌─────────────────────────────┐
│ Step 1: 意圖分類            │
│ 規則引擎匹配 → LLM fallback │
└──────────┬──────────────────┘
           ▼
┌─────────────────────────────┐
│ Step 2: 參數萃取            │
│ 正則 + NER → LLM 補充       │
└──────────┬──────────────────┘
           ▼
┌─────────────────────────────┐
│ Step 3: 表單定位 + 查詢生成 │
│ 查詢模板 → 參數填入         │
└──────────┬──────────────────┘
           ▼
┌─────────────────────────────┐
│ Step 4: 快取檢查            │
│ Hash 比對 → 命中則直接回傳  │
└──────────┬──────────────────┘
           ▼
┌─────────────────────────────┐
│ Step 5: 執行 Ragic 查詢     │
│ 非同步呼叫 → 逾時控制      │
└──────────┬──────────────────┘
           ▼
┌─────────────────────────────┐
│ Step 6: 結果格式化 + 回傳   │
│ 模板渲染 → 寫入快取        │
└─────────────────────────────┘
```

### 7.3 快取設計

| 面向 | 設計決策 |
|:----:|---------|
| 快取鍵 | sha256(query_normalized + params_sorted) |
| TTL 策略 | 預設 5 分鐘，可依表單變動頻率調整 |
| 失效機制 | 支援主動失效 API（POST /cache/invalidate） |
| 儲存上限 | ArangoDB 集合大小限制 500MB，LRU 淘汰 |
| 監控指標 | 快取命中率、平均查詢時間、Ragic API 呼叫次數 |

### 7.4 安全考量

| 考量 | 措施 |
|:----:|------|
| 資料權限 | 採用 RBAC，控制不同角色可查詢的表單範圍 |
| 查詢稽核 | 所有查詢記錄留存 90 天，包含查詢內容與結果摘要 |
| 注入防護 | 查詢參數化，不使用字串拼接產生 AQL |
| rate limit | 每使用者每分鐘 30 次查詢，防止 API 過度呼叫 |
| 敏感資料 | 供應商價格、合約條款等敏感欄位需額外權限 |
