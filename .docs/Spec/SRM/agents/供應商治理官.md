## §1 定位與職責

### 1.1 定位

供應商治理官是 AI-SCM 體系中 Layer 4 治理與策略層的三大 Agent 之一，專注於供應商全生命週期的治理。它不參與日常採購作業（那是採購智能助理的領域），而是站在管理層視角，自動化執行供應商評鑑、分析績效趨勢、預警供應商風險並提出策略性採購建議。

```
供應商治理官的治理範圍：

供應商全生命週期：
入門 → 試用 → 合格 → 定期評鑑 → 改善/升級 → 降級/淘汰
 │                           │                      │
 │   供應商治理官介入點：     │                      │
 │   ← 初次評分             │                      │
 │                          ← 季度/年度自動評鑑    │
 │                                                ← 風險預警 + 策略建議
```

### 1.2 職責範圍

| 項目 | 說明 |
|:----:|------|
| 所屬層級 | Layer 4 治理與策略層 |
| AI 濃度 | 60%（需要綜合分析與預測能力） |
| 對應原需求 | PA-09 |
| 服務對象 | 總經理、管理部主管、品管主管、採購主管 |
| 核心功能 | 自動化評鑑、績效趨勢、風險預警、策略建議 |
| 作業模式 | 定期自動執行 + 人員手動查詢 |

### 1.3 非職責範圍

| 不處理項目 | 原因 |
|-----------|------|
| 日常採購作業（詢價、下單、跟催） | 屬於採購智能助理（🅱） |
| 供應商品質的日常監控 | 屬於採購智能助理的品質監控模組 |
| 跨流程策略分析與儀表板 | 屬於供應鏈指揮官（🅳） |
| 合規檢查與審計追蹤 | 屬於合規監察官（🅴） |
| 直接與供應商溝通催貨 | 屬於採購智能助理的跟單催貨模組 |

## §3 RAGIC 邊界

### 3.1 讀取邊界

供應商治理官讀取以下 Ragic 表單：

| 表單名稱 | 讀取用途 | 評鑑維度對應 |
|---------|---------|:-----------:|
| 廠商資料設定 | 供應商基本資料、分類、等級 | 基本資料驗證 |
| 採購單 / 採購憑單 | PO 歷史資料、採購金額、交期紀錄 | 交期準確率 |
| 進貨檢驗紀錄(IQC) | 品檢結果、合格率、不良項目 | 品質評分 |
| 收貨單 | 到貨紀錄、到貨數量 | 交期準確率 |
| 供應商資格評估表 (TB-S09) | 資格評估記錄 | 資格驗證 |
| 供應商評比分析表 (TB-S10) | 歷史評比記錄 | 歷史趨勢 |
| 特採單 | 特採申請與核准記錄 | 品質配合度 |

### 3.2 寫入邊界

供應商治理官是唯一被授權寫入特定 Ragic 表單的 AI Agent，但寫入範圍嚴格限定於評鑑/分析資料，而非交易資料：

```
✅ 允許寫入的 Ragic 表單：
   - 供應商評鑑紀錄（建立新的評鑑記錄）
   - 供應商評比分析表（更新評分數據）

   寫入的資料類型：
   - 評鑑分數（數值，如 82.5 分）
   - 評鑑等級（A/B/C/D）
   - 評鑑評語（文字摘要）
   - 風險等級（低/中/高/嚴重）

❌ 禁止寫入的 Ragic 表單：
   - 廠商資料設定（供應商主檔）
   - 採購單 / 採購憑單（交易資料）
   - 庫存表（庫存資料）
   - 任何交易性質的資料
```

### 3.3 邊界原則說明

供應商治理官之所以被允許寫入評鑑資料，是因為評鑑資料屬於分析層資料而非交易層資料：

```
交易資料（Ragic 專屬）:
  PO 建立/修改、庫存異動、收貨確認、付款執行
  → AI 一律不得寫入

分析資料（AI 可寫入）:
  供應商評鑑分數、績效評語、風險分級、改善建議
  → AI 可以產出並寫入，作為後續查閱與追溯的依據
```

## §4 核心功能

### 4.1 自動化供應商評鑑（QP-S06）

對應 QP-S06 供應商評鑑管理作業標準，自動執行評鑑流程：

```
評鑑執行流程：

定時觸發（每季/每年）
    │
    ▼
Step 1: 資料彙整
    │ 從 🅰 Data Agent 取得評鑑所需資料
    │ 包含 PO 資料、IQC 資料、交期紀錄
    ▼
Step 2: 多維度評分 (P4)
    │ 品質維度（40%）：合格率、不良嚴重度
    │ 交期維度（30%）：準時交貨率、延遲天數
    │ 價格維度（20%）：價格競爭力、價格穩定性
    │ 配合維度（10%）：異常配合度、改善速度
    ▼
Step 3: 評鑑結果生成 (P4)
    │ 總分計算 → 等級判定（A/B/C/D）
    │ 優缺點分析 → 改善建議
    ▼
Step 4: 結果寫入與通知 (P5)
    │ 評鑑結果寫入 Ragic 評鑑紀錄表
    │ 通知採購主管 + 管理部主管
    ▼
輸出：供應商評鑑報告
```

### 4.2 績效趨勢分析

跨多期評鑑結果的趨勢分析：

| 分析維度 | 方法 | 輸出 |
|:--------:|------|------|
| 單一供應商趨勢 | 將歷次評分繪製為折線圖，計算移動平均 | 趨勢圖 + 趨勢判斷（持續改善 / 穩定 / 惡化） |
| 同類供應商比較 | 同類別供應商的評分分布分析 | 同類排名 + 分布圖 |
| 維度權重調整建議 | 根據歷史資料分析各維度的區辨力 | 權重調整建議報告 |

### 4.3 風險預警

主動偵測供應商風險並發出預警：

| 風險類型 | 偵測條件（P2） | 預警等級 | 通知對象 |
|:--------:|:-------------:|:--------:|:--------:|
| 品質急遽惡化 | 連續 2 季品質分數下降 > 10% | 高 | 品管主管 + 採購主管 |
| 交期持續延遲 | 連續 3 個月交期準確率 < 80% | 中 | 採購人員 + 採購主管 |
| 財務風險訊號 | 異常大量催款 / 付款條件變更 | 高 | 財務主管 + 採購主管 |
| 評級驟降 | 單季評分下降 > 20 分 | 嚴重 | 總經理 + 管理部主管 |
| 交易量異常 | 採購量突然大幅增加或減少 | 低 | 採購人員 |

### 4.4 策略採購建議

基於評鑑結果與趨勢分析，提出策略性建議（P4）：

| 建議類型 | 觸發條件 | 建議內容 |
|:--------:|---------|---------|
| 供應商升級 | 連續 2 季 A 級評鑑 | 建議提升為策略夥伴等級，增加採購配額 |
| 供應商降級 | 連續 2 季 C 級評鑑 | 建議降級為觀察名單，減少採購量 |
| 供應商淘汰 | 連續 2 季 D 級評鑑 | 建議啟動替代供應商導入計畫 |
| 第二來源開發 | 單一供應商依賴度 > 70% | 建議開發第二供應商以分散風險 |
| 品項調整 | 特定品項品質持續不佳 | 建議將該品項移轉給其他供應商 |

## §5 評鑑模型

### 5.1 評鑑維度

| 維度 | 權重 | 細項指標 | 資料來源 |
|:----:|:----:|---------|:--------:|
| 品質 | 40% | 進貨合格率、不良嚴重度、改善速度、客訴率 | IQC 紀錄、特採紀錄 |
| 交期 | 30% | 準時交貨率、平均延遲天數、急單配合度 | PO、收貨單 |
| 價格 | 20% | 價格競爭力（vs 同類均價）、價格穩定性 | PO、詢價單 |
| 配合 | 10% | 異常處理配合度、文件完整度、溝通回應速度 | 評鑑紀錄、人員回饋 |

### 5.2 評分計算方式

```
評分計算公式：

品質分 = 合格率 × 60 + (1 - 不良嚴重度系數) × 40
  其中：合格率 = 合格批數 / 總檢驗批數
       不良嚴重度系數 = (關鍵不良 × 1.0 + 主要不良 × 0.5 + 次要不良 × 0.2) / 總檢驗數

交期分 = 準時交貨率 × 70 + 急單配合度 × 30
  其中：準時交貨率 = 準時到貨批數 / 總到貨批數

價格分 = (1 - |供應商單價 - 同類均價| / 同類均價) × 100
  限制：價格分低於 60 分時以 60 分計（避免單價低於均價反而扣分）

配合分 = 評鑑人員評分（0-100）

總分 = 品質分 × 0.4 + 交期分 × 0.3 + 價格分 × 0.2 + 配合分 × 0.1
```

### 5.3 評鑑週期與觸發

| 評鑑類型 | 週期 | 觸發方式 | 適用對象 |
|:--------:|:----:|:--------:|---------|
| 季度評鑑 | 每季 | 自動排程 | 所有活躍供應商 |
| 年度評鑑 | 每年 | 自動排程（Q4） | 所有合格供應商 |
| 新供應商評鑑 | 試用期滿 | 事件驅動 | 新導入供應商 |
| 異常觸發評鑑 | 依事件 | 風險預警觸發 | 發生重大異常的供應商 |
| 手動評鑑 | 隨需 | 人員要求 | 指定供應商 |

## §6 輸入輸出規格

### 6.1 評鑑請求

| 欄位 | 型別 | 必填 | 說明 |
|:----:|:----:|:----:|------|
| action | enum | ✅ | evaluate / trend / risk / strategy |
| supplier_id | string | ❌ | 指定供應商（不指定時回傳所有） |
| period | string | ❌ | 評鑑期間（如 2026-Q2） |
| include_detail | boolean | ❌ | 是否包含細項評分，預設 false |

### 6.2 評鑑回應

| 欄位 | 型別 | 說明 |
|:----:|:----:|------|
| status | string | ok / error |
| supplier | object | 供應商基本資訊 |
| score | object | 各維度評分 + 總分 |
| grade | string | A(>=90) / B(>=75) / C(>=60) / D(<60) |
| trend | string | improving / stable / declining |
| summary | string | 評鑑摘要（自然語言） |
| recommendations | array | 改善建議清單 |

回應範例：

```json
{

  },
  "score": {

        "delivery": 72,
        "price": 80,
        "cooperation": 75,
        "total": 80.2,
        "grade": "B"
  },
  "trend": "declining",

```

### 7.2 角色 × 問題矩陣

| 角色 | 題數 | 常見問題 |
|:----:|:----:|---------|
| 總經理 | 1 | 哪些供應商需要關注？ |

## §8 實作筆記

### 8.1 評鑑引擎設計

| 元件 | 說明 |
|:----:|------|
| 評鑑規則引擎 | 負責標準化評分計算，純規則（100%），無需 LLM |
| 評語生成器 | 根據評分數據 + 趨勢產生自然語言評語，需 LLM（60%） |
| 趨勢分析器 | 時間序列分析，規則 + 統計模型（80% 規則） |
| 預警判斷器 | 門檻邏輯 + 趨勢判斷，規則為主（90%） |
| 建議產生器 | 根據評鑑結果 + 規則庫產生策略建議，需 LLM（50%） |

### 8.2 與其他 Agent 協作

```
觸發其他 Agent 的情境：

供應商治理官評鑑結果
    │
    ├── 供應商評級變更 → 🅳 供應鏈指揮官儀表板更新
    │
    ├── 高風險供應商預警 → 🅱 採購智能助理跟單催貨模組（加強監控）
    │
    ├── 評級降級至 D → 🅴 合規監察官（啟動合規檢查）
    │
    └── 策略建議通知 → 通知相關主管人員
```

### 8.3 排程與通知

| 排程 | 執行內容 | 通知對象 |
|:----:|---------|:--------:|
| 每日 | 風險掃描（檢查預警條件） | 觸發預警時通知對應人員 |
| 週一 | 上週供應商品質摘要 | 品管主管 |
| 每月 | 月度供應商績效簡報 | 採購主管 + 管理部主管 |
| 每季末 | 季度評鑑執行 | 所有供應商對應的採購人員 |
| 每年 Q4 | 年度總評鑑 + 策略建議 | 總經理 + 管理部主管 |

### 8.4 安全與權限

| 考量 | 措施 |
|:----:|------|
| 評鑑檢視 | 總經理、管理部主管可查看所有供應商評鑑；採購主管可查看負責範圍 |
| 評鑑執行 | 僅系統自動執行，人員不可手動修改評分結果 |
| 評鑑覆核 | 管理部主管可對評鑑結果提出覆核要求 |
| 風險預警 | 嚴重預警（critical）自動通知到總經理層級 |
| 資料保留 | 評鑑記錄保留 5 年，不得刪除 |
