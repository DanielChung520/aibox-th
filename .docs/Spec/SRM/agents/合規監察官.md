# 合規監察官規格書

> 文件定位：本文件定義合規監察官（Compliance Officer）的完整規格，屬於 AI-SCM 四層架構中的 Layer 4 治理與策略層。
>
> 對應上層文件：AI-SCM-範式.md（§3.5 Layer 4）
>
> 核心角色：供應鏈作業的合規自動化守門員，確保採購流程符合內部規範與外部法規要求。
>
> 設計依據：原需求 Excel 未涵蓋此 Agent，但基於供應鏈成熟度提升後對合規自動化的實際需求而增設。

## §1 定位與職責

### 1.1 定位

合規監察官是 AI-SCM 體系中 Layer 4 治理與策略層的新增 Agent，專注於供應鏈作業的合規性自動化檢查。它像一位不眠不休的內部稽核員，持續監控採購流程中的每一個環節，確保所有作業符合內部規範（QP 系列標準）、授權制度與外部法規要求。

```
合規監察官的監控範圍：

採購流程全環節：
請購 → 詢價 → 比價 → 採購 → 變更 → 驗收 → 付款
 │      │      │      │      │      │      │
 ▼      ▼      ▼      ▼      ▼      ▼      ▼
合規    合規    合規    合規    合規    合規    合規
檢查    檢查    檢查    檢查    檢查    檢查    檢查
(授權)  (比價)  (比價)  (授權)  (程序)  (驗收)  (付款
        原則)  原則)          )             條件)
```

### 1.2 職責範圍

| 項目 | 說明 |
|:----:|------|
| 所屬層級 | Layer 4 治理與策略層 |
| AI 濃度 | 60%（需要推理判斷與文件比對能力） |
| 對應原需求 | **全新 Agent**（原需求未涵蓋） |
| 服務對象 | 管理部主管、財務主管、採購主管、總經理（重大違規） |
| 作業模式 | 被動監控（事件驅動）+ 主動通報（定期報告） |
| 核心價值 | 將原本靠人力的合規抽查轉變為系統化的自動持續監控 |

### 1.3 非職責範圍

| 不處理項目 | 原因 |
|-----------|------|
| 供應商評鑑與評分 | 屬於供應商治理官（🅲） |
| 日常採購建議 | 屬於採購智能助理（🅱） |
| 供應鏈 KPI 儀表板 | 屬於供應鏈指揮官（🅳） |
| 人員績效考核 | 非供應鏈範疇 |
| 法律訴訟或仲裁 | 超出系統範圍，需由法務人員處理 |

## §3 RAGIC 邊界

### 3.1 讀取邊界

合規監察官讀取以下 Ragic 表單以進行合規檢查：

| 表單名稱 | 用途 |
|---------|------|
| 採購單 / 採購憑單 | 檢查採購金額、供應商、品項合理性 |
| 請購單 / 請購憑單 | 檢查請購程序完整性 |
| 採購變更單 | 檢查變更程序合規性 |
| 詢價單 / 詢價憑單 | 檢查比價記錄完整性 |
| 詢價回覆單 | 檢查供應商報價記錄 |
| 進貨檢驗紀錄(IQC) | 檢查驗收程序合規性 |
| 特採單 | 檢查特採程序合規性 |
| 供應商資格評估表 (TB-S09) | 檢查供應商資格有效性 |
| 廠商資料設定 | 檢查供應商狀態 |
| 進貨憑單 | 檢查付款條件合規性 |

### 3.2 寫入邊界

合規監察官被授權寫入合規相關的記錄與標記：

```
✅ 允許寫入：
   - 合規檢查記錄表（每筆檢查的結果記錄）
   - 違規事件標記（在相關單據上附加違規標記，不修改原始資料）
   - 審計日誌（合規監察官自己的操作記錄）

   寫入地點：
   - ArangoDB 合規記錄集合（主要）
   - Ragic 合規標記欄位（僅附加標記，不修改交易資料）

❌ 禁止寫入：
   - 修改採購單內容
   - 修改供應商主檔資料
   - 修改任何交易資料或流程狀態
   - 刪除或修改既有記錄
```

### 3.3 邊界比較

與其他 Layer 4 Agent 的邊界差異：

| Agent | 讀取範圍 | 寫入權限 |
|:-----:|---------|:--------:|
| 🅲 供應商治理官 | 供應商 + 品管 + PO | 評鑑記錄寫入 |
| 🅳 供應鏈指揮官 | 全流程（最廣） | 無寫入 |
| 🅴 合規監察官 | 全流程 + SOP 知識庫 | 合規記錄與標記寫入 |

## §4 核心功能

### 4.1 比價合規檢查（三報價原則）

檢查採購作業是否遵循「一定金額以上需取得三家報價」的內控原則：

| 檢查條件 | 規則 | 違規判定 |
|:--------:|:----:|:--------:|
| 採購金額 >= $50,000 | 需取得至少 3 家供應商報價 | 報價家數 < 3 → 違規 |
| 採購金額 >= $200,000 | 需取得至少 3 家報價 + 書面比價記錄 | 缺書面記錄 → 違規 |
| 特殊情況（獨家供應） | 需附獨家供應說明 + 主管核准 | 缺說明或核准 → 違規 |
| 緊急採購 | 需於 24 小時內補齊比價程序 | 未補齊 → 違規 |

檢查流程：

```
Step 1: 事件觸發
    PO 建立或變更時觸發（即時檢查）
    或定期掃描所有新 PO（批次檢查）

Step 2: 資料比對
    從 🅰 Data Agent 取得該 PO 的詢價記錄
    檢查詢價供應商家數
    檢查報價回覆完整性

Step 3: 規則判定
    符合規則 → 通過，記錄歸檔
    不符合規則 → 判定違規等級

Step 4: 違規處理
    輕度違規：標記違規 + 通知採購人員補正
    中度違規：標記違規 + 通知採購主管
    重度違規：標記違規 + 通知管理部主管 + 財務主管
```

### 4.2 授權差異偵測

檢查採購單的核准層級是否符合作業授權規範：

| 採購金額範圍 | 必要核准層級 | 檢查重點 |
|:-----------:|:-----------:|:--------:|
| < $20,000 | 採購人員 + 部門主管 | 部門主管簽核 |
| $20,000 - $100,000 | 部門主管 + 管理部主管 | 管理部主管簽核 |
| $100,001 - $500,000 | 部門主管 + 管理部主管 + 總經理 | 總經理簽核 |
| > $500,000 | 部門主管 + 管理部主管 + 總經理 + 董事會 | 董事會會議記錄 |
| 變更單 | 同上（依變更後金額） | 變更核准層級 |

偵測邏輯：

```
授權差異偵測規則：

    取得 PO 金額
        │
        ▼
    判斷應有核准層級
        │
        ▼
    比對實際核准記錄（從 Ragic 簽核歷程）
        │
        ├── 核准層級足夠 → 通過
        │
        └── 核准層級不足 → 判定差異等級
                │
                ├── 差一級：標記為警告
                │   範例：應經總經理核准，僅經管理部主管核准
                │
                └── 差兩級以上：標記為嚴重違規
                    範例：應經總經理核准，僅經部門主管核准
```

### 4.3 SOP 偏離預警

比對實際作業流程與 QP 系列標準作業程序的偏離：

| SOP 標準 | 檢查項目 | 偏離偵測方式 |
|:--------:|---------|:-----------:|
| QP-S05 採購流程 | 請購→詢價→採購→驗收 順序正確性 | 檢查時間戳記順序 |
| QP-S05 採購流程 | 緊急採購後補程序 | 檢查補件記錄 |
| QP-S06 供應商評鑑 | 定期評鑑是否執行 | 檢查評鑑記錄時效 |
| QP-S07 檢驗標準 | 檢驗項目完整性 | 檢驗記錄 vs 標準檢驗項目 |
| QP-S08 不合格品處理 | 不合格品處理程序 | 檢查退貨/特採記錄完整性 |

### 4.4 審計追蹤

提供可供內外部稽核使用的完整審計軌跡：

| 審計項目 | 記錄內容 | 保留期限 |
|:--------:|---------|:-------:|
| 違規事件記錄 | 時間、類型、等級、涉及單據、處理狀態 | 5 年 |
| 合規檢查日誌 | 每次檢查的輸入、判定過程、結果 | 3 年 |
| 授權差異記錄 | 差異詳情、核准層級比對 | 5 年 |
| SOP 偏離記錄 | 偏離項目、實際流程、建議改善 | 3 年 |
| 人員操作記錄 | 誰在何時查看了哪些合規資料 | 2 年 |

### 4.5 合規儀表板

提供管理層的合規狀態總覽：

| 儀表板區塊 | 內容 |
|:----------:|------|
| 合規評分 | 整體合規分數（0-100），根據違規率計算 |
| 違規統計 | 本月違規事件數、等級分布、趨勢 |
| 未結案件 | 尚未處理完畢的違規事件清單 |
| 高風險區域 | 違規率最高的流程環節與原因分析 |
| 改善進度 | 已改善事項與待改善事項 |

## §5 檢查規則詳表

### 5.1 強制規則（硬性違規）

違反即判定為違規，需立即處理：

| 規則 ID | 規則說明 | 違規等級 | 對應 QP |
|:-------:|---------|:--------:|:-------:|
| CMP-001 | 單筆採購金額 >= $50,000 未取得三家以上報價 | 中 | QP-S05 |
| CMP-002 | 單筆採購金額 >= $200,000 無書面比價記錄 | 中 | QP-S05 |
| CMP-003 | 核准層級低於應有層級（差一級） | 中 | QP-S05 |
| CMP-004 | 核准層級低於應有層級（差兩級以上） | 高 | QP-S05 |
| CMP-005 | 向不合格供應商下單（資格過期/暫停交易） | 高 | QP-S06 |
| CMP-006 | 採購變更未經重新核准 | 中 | QP-S05 |
| CMP-007 | 驗收程序未完成即入帳 | 中 | QP-S07 |
| CMP-008 | 不合格品未依程序處理（退貨/特採） | 中 | QP-S08 |

### 5.2 警示規則（軟性偏離）

偏離最佳實踐但尚未構成違規，發出警示通知：

| 規則 ID | 規則說明 | 警示等級 |
|:-------:|---------|:--------:|
| CMP-W01 | 同一供應商連續採購佔比 > 70% 未開發第二來源 | 低 |
| CMP-W02 | 報價供應商與過去 3 次完全相同無新增 | 低 |
| CMP-W03 | 採購單與請購單金額差異 > 20% 無說明 | 低 |
| CMP-W04 | 特採率超過該供應商供貨批次的 15% | 中 |
| CMP-W05 | 緊急採購比例超過當月採購筆數的 10% | 中 |

### 5.3 建議規則（最佳實踐）

不構成違規或警示，但記錄為合規改善建議：

| 規則 ID | 規則說明 |
|:-------:|---------|
| CMP-S01 | 建議定期輪換詢價供應商以確保競爭性 |
| CMP-S02 | 建議採購金額達 $30,000 以上即取得三家報價（優於法規） |
| CMP-S03 | 建議建立獨家供應商的定期價格審查機制 |

## §6 輸入輸出規格

### 6.1 違規事件輸出

違規事件為主動推播輸出：

| 欄位 | 型別 | 說明 |
|:----:|:----:|------|
| event_id | string | 違規事件編號 |
| rule_id | string | 違反的規則 ID |
| violation_level | string | low / medium / high |
| status | string | open / investigating / resolved / closed |
| related_doc | object | 相關單據類型與編號 |
| description | string | 違規說明 |
| detected_at | string | 偵測時間 |
| suggested_action | string | 建議處理方式 |
| reported_to | array | 通知對象清單 |

違規事件範例：

```json
{
  "event_id": "CMP-2026-00042",
  "rule_id": "CMP-001",
  "violation_level": "medium",
  "status": "open",
  "related_doc": {
    "type": "purchase_order",
    "id": "PO-2026-0582",
    "amount": 68000
  },
  "description": "PO-2026-0582 採購煞車鼓總成金額 $68,000，僅取得 2 家供應商報價（展裕、和泰），不符合三報價原則。",
  "detected_at": "2026-06-16T08:30:00Z",
  "suggested_action": "建議於 3 個工作日內補齊第三家報價，或附上獨家供應說明經主管核准。",
  "reported_to": ["採購單位主管", "採購人員-王小明"]
}
```

### 6.2 合規報告請求

| 欄位 | 型別 | 必填 | 說明 |
|:----:|:----:|:----:|------|
| view | enum | ✅ | dashboard / violations / audit_trail / rules |
| period | string | ❌ | 期間（如 2026-Q2），預設本月 |
| severity | array | ❌ | 過濾違規等級，預設全部 |
| status | string | ❌ | open / closed，預設全部 |

### 6.3 合規報告回應

| 欄位 | 型別 | 說明 |
|:----:|:----:|------|
| compliance_score | integer | 合規評分（0-100） |
| total_violations | integer | 違規事件總數 |

## §8 實作筆記

### 8.1 監控模式設計

合規監察官採用雙模式監控：

| 模式 | 說明 | 觸發方式 | 頻率 |
|:----:|------|:--------:|:----:|
| 即時模式 | 事件驅動，PO 建立/變更時立即檢查 | Ragic Webhook / API 通知 | 即時 |
| 批次模式 | 定期掃描，全面檢查所有交易 | 排程排程 | 每日 / 每週 |

即時模式適用於：

```
檢查項目：CMP-001 ~ CMP-008（強制規則）
回饋速度：即時（< 5 秒）
目的：在交易完成前即時攔截違規
```

批次模式適用於：

```
檢查項目：CMP-W01 ~ CMP-W05（警示規則）+ CMP-S01 ~ CMP-S03（建議規則）
回饋速度：批次（每日或每週彙總報告）
目的：發現趨勢性問題與改善機會
```

### 8.2 規則引擎架構

| 元件 | 說明 |
|:----:|------|
| 規則定義庫 | 以 JSON 或 YAML 定義的結構化規則，支援動態增刪修改 |
| 規則解析器 | 將規則定義轉換為可執行的檢查條件 |
| 檢查執行器 | 根據事件類型調用對應的規則集合進行檢查 |
| 結果判定器 | 根據規則的違規等級判定結果嚴重程度 |
| 通知分發器 | 根據違規等級與規則定義的通知對象發送通知 |

### 8.3 事件處理流程

```
合規事件處理完整流程：

來源事件（PO 建立 / 變更 / 定時排程）

    │
```

### 8.4 與其他 Agent 協作

```
合規監察官的協作模式：

發現違規事件
    │
    ├── 違規涉及供應商資格 → 通知 🅲 供應商治理官更新供應商狀態
    │
    ├── 違規嚴重影響採購作業 → 通知 🅱 採購智能助理調整作業提醒
    │
    ├── 違規影響 KPI 指標 → 通知 🅳 供應鏈指揮官更新儀表板異常摘要
    │
    └── 趨勢性違規 → 產出合規改善建議報告
         → 通知管理部主管與採購主管
```

### 8.5 安全與權限

| 考量 | 措施 |
|:----:|------|
| 檢查記錄存取的權限 | 管理部主管、財務主管可查看所有合規記錄；採購主管僅能查看所屬範圍 |
| 違規事件修改 | 違規事件記錄不可刪除或修改，僅可更新處理狀態 |
| 規則管理 | 規則定義僅系統管理員可修改，修改需記錄審計日誌 |
| 通知對象 | 高違規通知強制送達管理部主管與總經理 |
| 資料保留 | 違規事件記錄與審計日誌依規定保留 3-5 年 |
