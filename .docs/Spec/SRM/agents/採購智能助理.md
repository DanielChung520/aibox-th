## §1 定位與職責

### 1.1 定位

採購智能助理是 AI-SCM 體系中規模最大、功能最全面的 Agent，橫跨 Layer 2 執行與決策層（日常採購作業輔助）與 Layer 3 協同與異常層（跨部門異常處理）。它以模組化架構設計，涵蓋從請購需求發起到驗收品管的完整採購生命週期。

```
採購生命週期 vs 模組對應：

請購需求 → 詢價比價 → 採購下單 → 跟催交期 → 驗收進貨 → 品檢入庫
   │          │          │          │          │          │
   ▼          ▼          ▼          ▼          ▼          ▼
 模組一      模組二     (Ragic)    模組五      模組三      模組四
 請購規劃    詢比價      PO產生    跟單催貨    驗收比對    品質監控
                                    模組六
                                    變更評估
```

### 1.2 職責範圍

| 面向 | 說明 |
|:----:|------|
| 所屬層級 | Layer 2（模組一至四）+ Layer 3（模組五至六） |
| AI 濃度 | L2 模組 20%，L3 模組 40%，平均 30% |
| 對應原需求 | PA-01 至 PA-08，共 8 項需求 |
| 服務對象 | 採購人員、倉管人員、品管人員、生產人員、管理部主管 |
| 核心原則 | AI 產出建議與決策支援，最終由人員決定是否執行 |

### 1.3 非職責範圍

| 不處理項目 | 原因 |
|-----------|------|
| 直接在 Ragic 建立/修改訂單 | 交易操作屬於 Ragic 職責 |
| 供應商評鑑分數計算 | 歸屬於供應商治理官（🅲） |
| 跨流程策略分析 | 歸屬於供應鏈指揮官（🅳） |
| 合規與審計檢查 | 歸屬於合規監察官（🅴） |
| 直接對 Line/Email 發送訊息 | 需經由通知引擎元件處理 |

### 1.4 模組總覽

| # | 模組名稱 | 層級 | 對應原需求 | AI 濃度 | 核心 AI 價值 |
|:-:|:--------|:----:|:---------:|:-------:|:-----------:|
| 1 | 請購規劃 | L2 | PA-01, PA-02 | 20% | P1, P4 |
| 2 | 詢比價 | L2 | PA-03, PA-04 | 20% | P2, P4 |
| 3 | 驗收比對 | L2 | PA-07 | 20% | P2, P4 |
| 4 | 品質監控 | L2 | PA-08 | 20% | P2, P4 |
| 5 | 跟單催貨 | L3 | PA-05 | 40% | P1, P2, P5, P6 |
| 6 | 變更評估 | L3 | PA-06 | 40% | P1, P4, P6 |

## §2 AI 價值對應

### 2.1 全面覆蓋六點價值

採購智能助理是唯一覆蓋全部六點 AI 價值的 Agent：

| AI 價值 | 貢獻程度 | 說明 |
|:-------:|:--------:|------|
| **P1 預測** | 中等 | 請購規劃的需求預測、跟單催貨的延遲風險預測、變更評估的成本影響預測 |
| **P2 異常偵測** | 高 | 詢比價的價格偏離標記、驗收的數量/品質異常、品質監控的趨勢異常 |
| **P3 自然語言查詢** | 中等 | 人員可直接查詢模組狀態與結果，但複雜查詢會委託 Data Agent |
| **P4 決策建議** | 高 | 每個模組的核心輸出都是建議：請購建議、供應商推薦、品質判定、交期調整 |
| **P5 自動溝通** | 高 | 跟單催貨模組自動發送分級催貨通知，異常自動通報相關人員 |
| **P6 跨系統串聯** | 高 | 從 BOM 串到庫存再串到訂單，從延遲串到生產排程再串到客戶交期 |

## §3 RAGIC 邊界

### 3.1 讀取邊界

採購智能助理讀取以下 Ragic 表單：

| 表單名稱 | 用途 | 相關模組 |
|---------|------|:-------:|
| 請購單 / 請購憑單 | 請購需求來源 | ① |
| PLM-產品主檔維護 | BOM 結構查詢 | ① |
| 庫存表 | 庫存比對 | ① |
| 廠商資料設定 | 供應商主檔查詢 | ② ⑤ |
| 詢價單 / 詢價憑單 | 歷史詢價記錄 | ② |
| 採購單 / 採購憑單 | PO 資料查詢 | ② ⑤ ⑥ |
| 收貨單 | 到貨查詢 | ③ |
| 進貨檢驗紀錄(IQC) | 品檢結果查詢 | ③ ④ |
| 進貨憑單 | 入庫查詢 | ③ |
| 生產製令單 | 工單進度查詢 | ⑤ ⑥ |
| 生產排程單 | 排程查詢 | ⑤ |
| 特採單 | 特採記錄查詢 | ④ |

### 3.2 輸出邊界

採購智能助理的輸出嚴格限定為建議與報告，不直接寫入 Ragic 交易表單：

```
✅ 允許的輸出：
   - 請購建議書（文字報告）
   - 供應商比價分析表（文字報告）
   - 驗收比對結果標記（建議不合格/合格）
   - 品質趨勢報告
   - 催貨通知草稿（待人員確認發送）
   - 變更影響評估報告

❌ 禁止的輸出：
   - 直接在 Ragic 建立採購單
   - 修改庫存數據
   - 更新品質檢驗結果
   - 變更供應商主檔資料
   - 執行 Ragic Workflow
```

### 3.3 模組 × RAGIC 表單對應

| 模組 | 讀取表單 | 輸出產出 |
|:----:|---------|---------|
| ① 請購規劃 | 請購單、BOM、庫存表 | 請購建議書 |
| ② 詢比價 | 廠商資料、詢價單、PO 歷史 | 比價分析表 |
| ③ 驗收比對 | 收貨單、PO、IQC 紀錄 | 驗收比對報告 |
| ④ 品質監控 | IQC 紀錄、特採單 | 品質趨勢報告 |
| ⑤ 跟單催貨 | PO、工單、生產排程 | 催貨通知、影響評估 |
| ⑥ 變更評估 | PO、BOM、庫存表 | 變更影響評估報告 |

## §4 模組一：請購規劃模組

### 4.1 功能說明

對應原需求 PA-01 與 PA-02。核心功能是將業務需求（如客戶訂單、生產計劃）轉換為具體的採購建議，包含 BOM 展開、庫存比對、需求預測與請購建議。

### 4.2 處理流程

```
① 請購規劃模組處理流程：

輸入：生產計劃 / 客戶訂單
    │
    ▼
Step 1: BOM 展開
    │ 根據產品型號展開物料清單
    │ 取得所有子件料號 + 需求量
    ▼
Step 2: 庫存比對
    │ 查詢現有庫存量
    │ 查詢在途採購量
    │ 計算淨需求 = 總需求 - 庫存 - 在途
    ▼
Step 3: 需求預測 (P1)
    │ 根據歷史用量預測未來需求趨勢
    │ 標記異常用量項目
    ▼
Step 4: 請購建議產出 (P4)
    │ 產生採購建議清單
    │ 標註優先級（急迫/正常/可延後）
    │ 估算採購預算
    ▼
輸出：請購建議書（待人員確認轉採購單）
```

### 4.3 輸入輸出

| 項目 | 說明 |
|:----:|------|
| 輸入 | 生產計劃單號 / 客戶訂單編號 / 產品型號清單 |
| 輸出 | 請購建議書（物料清單、需求量、建議採購量、優先級、預估單價） |
| 觸發方式 | 人員手動查詢 / 排程自動執行（每日凌晨） |
| 依賴模組 | 🅰 Data Agent（查詢 BOM、庫存） |

## §5 模組二：詢比價模組

### 5.1 功能說明

對應原需求 PA-03 與 PA-04。核心功能是根據請購需求自動匹配合格供應商、進行 TCO 比較分析、標記異常報價並提出推薦說明。

### 5.2 處理流程

```
② 詢比價模組處理流程：

輸入：請購項目清單 / 物料編號
    │
    ▼
Step 1: 供應商匹配
    │ 根據物料類別篩選合格供應商
    │ 排除黑名單或暫停交易供應商
    ▼
Step 2: TCO 比較 (P4)
    │ 取得各供應商報價
    │ 計算總持有成本（單價 + 運費 + 交期風險成本）
    ▼
Step 3: 異常標記 (P2)
    │ 比對歷史均價，標記價格偏離 > 15% 的項目
    │ 比對同業報價，標記不合理組合
    ▼
Step 4: 推薦產出 (P4)
    │ 產生供應商推薦排序
    │ 附上 TCO 分析說明
    │ 標註注意事項（如品質風險、交期風險）
    ▼
輸出：比價分析建議書
```

### 5.3 輸入輸出

| 項目 | 說明 |
|:----:|------|
| 輸入 | 請購項目清單（料號、數量、需求日期） |
| 輸出 | 比價分析表（供應商排序、TCO 比較、異常標記、推薦說明） |
| 觸發方式 | 人員手動查詢 / 請購確認後自動觸發 |
| 依賴資源 | 🅰 Data Agent（供應商資料、歷史 PO）、LLM（TCO 說明生成） |

## §6 模組三：驗收比對模組

### 6.1 功能說明

對應原需求 PA-07。核心功能是比對到貨內容與 PO 的一致性，判斷檢驗分流路徑，處理不合格品的建議流程。

### 6.2 處理流程

```
③ 驗收比對模組處理流程：

輸入：收貨單號
    │
    ▼
Step 1: 到貨比對 (P2)
    │ 比對到貨數量 vs PO 數量
    │ 比對到貨品項 vs PO 品項
    │ 標記溢交、短交、錯料
    ▼
Step 2: QC 分流判斷
    │ 根據物料類別決定檢驗等級（全檢/抽檢/免檢）
    │ 根據供應商歷史品質決定加嚴/減量檢驗
    ▼
Step 3: 不合格建議 (P4)
    │ 若檢驗不合格 → 建議退貨/特採/讓步接收
    │ 附上歷史不合格紀錄供參考
    ▼
Step 4: 庫存更新建議
    │ 建議入庫數量與儲位
    ▼
輸出：驗收比對報告
```

### 6.3 輸入輸出

| 項目 | 說明 |
|:----:|------|
| 輸入 | 收貨單號 / 到貨通知 |
| 輸出 | 驗收比對報告（比對結果、QC 分流建議、不合格處理建議） |
| 觸發方式 | 收貨單建立時自動觸發 |
| 依賴資源 | 🅰 Data Agent（PO、庫存、IQC 資料） |

## §7 模組四：品質監控模組

### 7.1 功能說明

對應原需求 PA-08。核心功能是分析品檢趨勢、評估供應商品質分數、提出特採建議與品質改善追蹤。

### 7.2 處理流程

```
④ 品質監控模組處理流程：

輸入：供應商 ID / 物料類別 / 時間區間
    │
    ▼
Step 1: IQC 資料彙整
    │ 彙整指定區間內的進貨檢驗記錄
    │ 計算合格率、不良率、主要不良項目
    ▼
Step 2: 趨勢分析 (P2)
    │ 季度/月度品質趨勢圖
    │ 標記連續惡化趨勢
    │ 標記異常波動點
    ▼
Step 3: 供應商品質評分 (P4)
    │ 根據合格率 + 不良嚴重度 + 改善速度計算品質分數
    │ 分級：A級(優) / B級(可) / C級(需改善) / D級(警示)
    ▼
Step 4: 特採建議 (P4)
    │ 分析特採申請與歷史品質關聯
    │ 建議是否同意特採
    ▼
輸出：品質監控報告
```

### 7.3 輸入輸出

| 項目 | 說明 |
|:----:|------|
| 輸入 | 供應商 ID（可選）、物料類別（可選）、時間區間 |
| 輸出 | 品質監控報告（合格率統計、趨勢分析、供應商品質評分、特採建議） |
| 觸發方式 | 人員手動查詢 / 每月自動產出 |
| 依賴資源 | 🅰 Data Agent（IQC 資料）、LLM（趨勢解讀） |

## §8 模組五：跟單催貨模組

### 8.1 功能說明

對應原需求 PA-05。核心功能是監控 PO 交期、分級提醒、評估延遲影響、自動發送催貨通知。這是 Layer 3 協同層的代表性模組，需要跨部門資料串聯。

### 8.2 處理流程

```
⑤ 跟單催貨模組處理流程：

定期檢查所有進行中 PO
    │
    ▼
Step 1: 交期監控 (P2)
    │ 計算到期日 vs 今日差距
    │ 分級：正常 / 將逾期(<7天) / 逾期(<14天) / 嚴重逾期(>=14天)
    ▼
Step 2: 影響評估 (P6)
    │ 串聯對應工單進度
    │ 串聯客戶訂單交期
    │ 評估延遲對生產與出貨的影響
    ▼
Step 3: 分級催貨 (P5)
    │ Level 1 — 將逾期：系統內提醒採購人員
    │ Level 2 — 逾期 < 7 天：自動 LINE 通知供應商
    │ Level 3 — 逾期 >= 7 天：自動 LINE + Email 通知供應商主管
    │ Level 4 — 嚴重逾期：通知採購主管 + 啟動替代方案
    ▼
Step 4: 預測警示 (P1)
    │ 根據供應商歷史交期準確率預測未來風險
    │ 標記高風險供應商
    ▼
輸出：催貨通知 / 交期預警報告
```

### 8.3 輸入輸出

| 項目 | 說明 |
|:----:|------|
| 輸入 | 無（定期自動執行）/ 指定 PO 編號（手動查詢） |
| 輸出 | 催貨通知（分級觸發）、交期預警報告（含影響評估） |
| 觸發方式 | 每日定時排程 + 事件驅動（PO 到期前 7 天） |
| 依賴資源 | 🅰 Data Agent（PO、工單、排程）、通知引擎、LLM（催貨文案生成） |

## §9 模組六：變更評估模組

### 9.1 功能說明

對應原需求 PA-06。核心功能是評估採購變更的連鎖影響，包含變更影響鏈追蹤、成本差異計算與替代方案建議。

### 9.2 處理流程

```
⑥ 變更評估模組處理流程：

輸入：變更申請單 / 變更內容描述
    │
    ▼
Step 1: 變更影響鏈追蹤 (P6)
    │ 變更項目 → 影響哪些 BOM 子件
    │ → 影響哪些採購單
    │ → 影響哪些工單
    │ → 影響哪些客戶訂單
    ▼
Step 2: 成本差異計算 (P1)
    │ 計算變更前後的物料成本差異
    │ 計算衍生成本（已採購呆料、重工工時）
    │ 預估總影響金額
    ▼
Step 3: 替代方案建議 (P4)
    │ 提出可行的替代物料方案
    │ 評估替代方案的成本與交期影響
    ▼
Step 4: 決策建議
    │ 綜合評估建議（同意變更 / 替代方案 / 拒絕變更）
    ▼
輸出：變更影響評估報告
```

### 9.3 輸入輸出

| 項目 | 說明 |
|:----:|------|
| 輸入 | 變更申請單號 / 變更內容描述 |
| 輸出 | 變更影響評估報告（影響鏈、成本差異、替代方案、建議） |
| 觸發方式 | 變更申請建立時自動觸發 / 人員手動查詢 |
| 依賴資源 | 🅰 Data Agent（BOM、PO、工單、客戶訂單）、LLM（替代方案推理） |

## §11 實作筆記

### 11.1 架構設計

建議採用 BPA Agent 模式實作採購智能助理：

| 元件 | 說明 |
|:----:|------|
| Agent Identity | 單一 Agent（採購智能助理）對外提供統一介面 |

### 11.4 安全與權限

| 考量 | 措施 |
|:----:|------|
