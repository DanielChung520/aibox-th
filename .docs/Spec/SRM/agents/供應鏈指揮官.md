## §1 定位與職責

### 1.1 定位

供應鏈指揮官是 AI-SCM 體系中 Layer 4 治理與策略層的戰情中心 Agent，專為管理層（總經理、財務主管）設計。它不參與任何日常作業，而是彙整整個供應鏈的運作狀態，提供跨流程的全局視野、異常摘要、預算預測與深層原因分析。

```
供應鏈指揮官的管理視角：

                 ┌──────────────────────────────────┐
                 │       供應鏈指揮官 Dashboard       │
                 │                                    │
                 │  ┌──────┐ ┌──────┐ ┌──────┐       │
                 │  │採購   │ │生產   │ │庫存   │       │
                 │  │KPI    │ │KPI    │ │KPI    │       │
                 │  └──────┘ └──────┘ └──────┘       │
                 │                                    │
                 │  ⚠️ 異常摘要          📊 預算趨勢   │
                 │  🔍 Why 分析入口     💬 NL 問答    │
                 └──────────────────────────────────┘
                          ▲
                          │ 彙整自所有 Agent
          ┌───────────────┼───────────────┐
          ▼               ▼               ▼
     🅰 Data Agent   🅱 採購助理    🅲 治理官
```

### 1.2 職責範圍

| 項目 | 說明 |
|:----:|------|
| 所屬層級 | Layer 4 治理與策略層 |
| AI 濃度 | 60%（需要綜合分析、預測與推理能力） |
| 對應原需求 | PA-10 |
| 服務對象 | 總經理、財務主管、管理部主管 |
| 核心功能 | 跨流程儀表板、異常摘要、預算預測、Why 分析、自然語言問答 |

### 1.3 非職責範圍

| 不處理項目 | 原因 |
|-----------|------|
| 供應商評鑑與治理 | 屬於供應商治理官（🅲） |

| 合規與審計檢查 | 屬於合規監察官（🅴） |
| 資料層的原始查詢 | 需經由 Data Agent（🅰） |
| 自動催貨與溝通 | 屬於採購智能助理的跟單催貨模組 |

## §3 RAGIC 邊界

### 3.1 讀取邊界

供應鏈指揮官**僅讀取不寫入** Ragic。它讀取的資料範圍最廣，涵蓋供應鏈所有主要表單：

| 類別 | 表單名稱 | 用途 |
|:----:|---------|------|
| 採購 | 採購單 / 採購憑單 | 採購金額、PO 數量、交期數據 |
| 採購 | 請購單 | 請購需求趨勢 |
| 採購 | 詢價單 | 價格趨勢分析 |
| 庫存 | 庫存表 | 庫存水位、週轉率 |
| 庫存 | 進貨憑單 | 入庫統計 |
| 生產 | 生產製令單 | 工單進度、完工率 |
| 生產 | 生產排程單 | 排程達成率 |
| 品質 | 進貨檢驗紀錄(IQC) | 品質合格率統計 |
| 品質 | 特採單 | 特採率統計 |
| 財務 | 進貨憑單 | 應付帳款統計 |
| 供應商 | 廠商資料設定 | 供應商數量分布 |

### 3.2 輸出邊界

供應鏈指揮官的輸出嚴格限定為分析報告與視覺化資料：

```
✅ 允許的輸出：
   - 供應鏈 KPI 儀表板資料（JSON 供前端渲染）
   - 異常摘要報告
   - 預算預測報告
   - Why 分析結果（根因 + 影響鏈）
   - 自然語言問答回覆

❌ 禁止的輸出：
   - 任何 Ragic 表單的寫入操作
   - 直接修改供應商資料
   - 產出採購建議（屬於 🅱 採購助理）
   - 產出供應商評鑑結果（屬於 🅲 治理官）
```

## §4 核心功能

### 4.1 跨流程儀表板

彙整供應鏈各流程的關鍵 KPI，提供管理層一目了然的全局視野：

| KPI 類別 | 指標 | 資料來源 | 更新頻率 |
|:--------:|:----:|:--------:|:-------:|
| 採購 | 本月採購金額、PO 總數、平均交期 | PO 表單 | 每日 |
| 採購 | 逾期 PO 數、逾期金額佔比 | PO + 收貨 | 每日 |
| 庫存 | 庫存週轉天數、呆料金額佔比 | 庫存表 | 每日 |
| 生產 | 工單完工率、排程達成率 | 工單 + 排程 | 即時 |
| 品質 | 進貨合格率、特採率 | IQC + 特採單 | 每週 |
| 財務 | 應付帳款總額、已立帳未付金額 | 進貨憑單 | 每日 |
| 綜合 | 供應鏈整體健康度評分 | 彙總計算 | 每日 |

KPI 顯示規則：

```
正常（綠色）：指標在目標範圍內
警戒（黃色）：指標接近臨界值（如逾期率 > 5%）
異常（紅色）：指標超出警戒線（如逾期率 > 10%）
NA（灰色）：資料不足或無資料
```

### 4.2 異常摘要

自動彙總當前供應鏈中的異常事項，按影響程度排序：

```
異常摘要範例：

╔══════════════════════════════════════════════════════╗
║  🔴 嚴重異常（2 項）                                 ║
║  1. PO-2026-0582 煞車鼓總成已逾期 14 天              ║
║     影響：工單 FO-2026-0042（福特旅行車）停工待料   ║
║     建議：啟動替代供應商                               ║
║                                                       ║
║  2. 展裕企業連續 2 季品質評分下降 > 15%              ║
║     影響：涉及 12 項物料，本季採購金額 280 萬         ║
║     建議：減少採購量，開發第二來源                     ║
║                                                       ║
║  🟡 一般異常（5 項）                                 ║
║  ...                                                  ║
╚══════════════════════════════════════════════════════╝
```

### 4.3 預算預測

基於歷史資料與當前趨勢，預測未來採購預算需求（P1）：

| 預測項目 | 方法 | 預測週期 |
|:--------:|:----:|:-------:|
| 下月採購金額 | 移動平均 + 季節性調整 | 月度 |
| 季度預算需求 | 時間序列 + 趨勢迴歸 | 季度 |
| 年度採購總額 | 累計推估 + 管理層調整 | 年度 |

預測輸出範例：


### 4.4 Why 分析與鑽取

管理層最常問的問題就是「為什麼」，供應鏈指揮官提供結構化的 Why 分析能力：

```
Why 分析範例：

問題：「為什麼本季採購金額比預算高出 15%？」

Step 1: 確認事實
   本季實際採購金額：1,850 萬
   本季預算金額：1,608 萬
   差異：+242 萬（+15.1%）

Step 2: 拆解維度
   ┌──────────┬──────────┬──────────┬──────────┐
   │ 物料類別 │ 實際     │ 預算     │ 差異     │
   ├──────────┼──────────┼──────────┼──────────┤
   │ 底盤零件 │ 720 萬   │ 560 萬   │ +160 萬  │ ← 主因
   │ 電裝零件 │ 480 萬   │ 460 萬   │ +20 萬   │
   │ 車體鈑金 │ 380 萬   │ 388 萬   │ -8 萬    │
   │ 內裝配件 │ 270 萬   │ 200 萬   │ +70 萬   │
   └──────────┴──────────┴──────────┴──────────┘

Step 3: 深入根因（P2）
   底盤零件超支 160 萬：
     - 原因 A：升降機訂單增加（+90 萬，已確認）
     - 原因 B：鋼材漲價（+50 萬，供應商調價通知）
     - 原因 C：緊急採購溢价（+20 萬，原供應商產能不足）

Step 4: 影響鏈追蹤（P6）
   升降機訂單增加 → 底盤零件需求增加
   → 供應商產能吃緊 → 緊急採購溢价
   → 部分訂單延遲 → 生產排程調整
   → 預計影響 2 台車交期延後 3-5 天

Step 5: 建議
   建議提前下 Q4 底盤零件訂單，鎖定價格與產能
```

### 4.5 自然語言問答

提供管理層最直覺的互動方式：直接問問題（P3）。

| 問題類型 | 範例 | 處理方式 |
|:--------:|------|:--------:|
| 狀態查詢 | 目前供應鏈整體狀況如何？ | 回傳儀表板摘要 |
| 比較查詢 | 本月採購金額跟去年同期比？ | 趨勢比較 + 差異分析 |
| 異常查詢 | 有哪些急迫的問題需要處理？ | 回傳異常摘要 |
| 預測查詢 | 下半年採購預算會增加嗎？ | 預算預測 + 驅動因素說明 |
| 根因查詢 | 為什麼最近交期一直延遲？ | Why 分析 + 影響鏈 |

## §7 實作筆記

### 7.1 儀表板引擎設計

| 元件 | 說明 |
|:----:|------|
| KPI 計算器 | 從彙總資料計算各項 KPI，純規則引擎 |
| 異常分類器 | 根據 KPI 門檻值自動分類正常/警戒/異常 |
| 摘要生成器 | 將異常事項彙整為優先級排序的摘要列表 |
| 儀表板資料 API | 提供 JSON 格式資料供前端 Dashboard 渲染 |

### 7.2 Why 分析推理管線

```
Why 分析管線（深度 3 層）：

問題："為什麼 A 發生？"

Level 1: 直接原因
  分析：A 的直接觸發因素 → 列出所有可能的直接原因
  輸出：原因清單 + 貢獻度排序

Level 2: 間接原因（P2）
  分析：針對貢獻度最高的直接原因，進一步追蹤
  方法：資料關聯分析（列出相關數據變化）
  輸出：因果鏈

Level 3: 根本原因（P6）
  分析：跨流程追蹤最終根因
  方法：從採購→生產→銷售全鏈路追溯
  輸出：根因 + 影響鏈 + 建議
```

### 7.3 預算預測模型

| 元件 | 方法 | 依賴 |
|:----:|:----:|:----:|
| 短期預測（月） | 指數平滑法 + 季節性指數 | 歷史 12 個月資料 |
| 中期預測（季） | 線性迴歸 + 外部因子（訂單、物價） | 歷史 8 季資料 |
| 長期預測（年） | 累計推估 + 管理層調整 | 年度目標資料 |
| LLM 解讀 | 將預測數據轉換為自然語言說明 | LLM 網關 |

### 7.4 與其他 Agent 協作

```
供應鏈指揮官的協作模式：

接收到管理層問題
    │
    ├── 問題需要原始資料？→ 🅰 Data Agent 查詢
    │
    ├── 問題涉及供應商評鑑？→ 🅲 供應商治理官取得評鑑資料
    │
    ├── 問題需要採購作業詳情？→ 🅱 採購智能助理取得模組資料
    │
    ├── 問題涉及合規？→ 🅴 合規監察官取得合規檢查結果
    │
    └── 問題屬於純分析 → 自行處理（儀表板/Why 分析/預測）
```

### 7.5 安全與權限

| 考量 | 措施 |
|:----:|------|
| 儀表板存取 | 總經理、財務主管、管理部主管可查看完整儀表板 |
| 部門主管 | 僅能查看所屬範圍的 KPI（如生產主管僅看生產 KPI） |
| Why 分析範圍 | 總經理可跨流程分析；部門主管限於所屬流程 |
| 預算預測 | 僅總經理與財務主管可查看預算預測 |
| 資料彙整 | 儀表板資料彙整時進行去識別化，不顯示供應商細節 |
