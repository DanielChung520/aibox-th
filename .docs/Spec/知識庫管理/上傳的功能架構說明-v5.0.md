## 概述

本文檔詳細說明 AI-Box 系統中文件上傳功能的完整架構，包括前端觸發、API 調用、後端處理、異步任務執行，以及 Ontology 在知識圖譜提取中的應用。

v5.0 版本為**重大架構升級**，新增多模態文件處理管線，使系統能夠理解和處理 PDF、DOCX 等文件中嵌入的圖片、圖表、截圖，並將其轉化為可供向量化與知識圖譜抽取的文字描述。

### 主要功能

- 多文件上傳（支持拖拽和點擊選擇）
- **會員分級上傳限制**（general 5MB / vip 50MB / super_vip 500MB）
- 文件類型驗證（PDF, Word, Excel, Markdown, CSV, TXT, 圖片等）
- **兩階段文件分類**（規則判斷：TextOnly / Mixed / ImageBased）
- 自動任務創建（首次上傳時）
- **多模態處理**：文字提取 + 圖片抽取 + VLM 描述
- **Timeline Spans**：文字與圖片描述依頁/位置交錯整合
- 異步處理流程（分塊、向量化、知識圖譜提取、知識資產編碼）
- **Ontology 自動選擇和應用**
- **知識資產編碼**：所有上傳統一進行 Ontology 對齊與 KNW-Code 生成
- 實時進度追蹤

## 文件存放位置與文件樹架構

### 2.1 概述

文件上傳後，會存放在任務的「任務工作區」（Workspace）。文件樹採用 **工作區 + 自訂資料夾** 的層級結構，由 `file_metadata` 和 `folder_metadata` 兩張表動態生成。

### 2.2 系統資料夾

每個任務自動創建以下系統資料夾：

| 資料夾 ID | 名稱 | 類型 | 說明 |
|-----------|------|------|------|
| `temp-workspace` | 任務工作區 | workspace | **前端預設 ID**，顯示為「任務工作區」 |
| `{task_id}_workspace` | 任務工作區 | workspace | **後端預設存放位置** |
| `{task_id}_scheduled` | 排程任務 | scheduled | 系統預留 |

**規則**：

- 系統資料夾不可刪除
- 系統資料夾不可移動
- 系統資料夾的 `folder_type` 不可更改

### 2.3 文件存放邏輯

```
文件上傳
    │
    ▼
┌─────────────────────────────────────────────────────┐
│ 1. 檢查是否指定 target_folder_id                     │
│ 2. 驗證會員分級上傳限制（tier → max_size）           │
└─────────────────────────────────────────────────────┘
                         │
        ┌───────────────┴───────────────┐
        ▼                               ▼
┌─────────────────────┐     ┌─────────────────────────────┐
│ 有指定 folder_id     │     │ 未指定 folder_id（預設）    │
│                     │     │                             │
│ 存放到指定資料夾     │     │ 存放到 temp-workspace       │
│ folder_id = 設置值   │     │ folder_id = null            │
└─────────────────────┘     └─────────────────────────────┘
```

### 2.4 file_metadata 與 fileTree 的關聯

**file_metadata 關鍵欄位**：

| 欄位 | 類型 | 說明 |
|------|------|------|
| `folder_id` | string (可選) | 所屬資料夾 ID，若為 `null` 表示在任務工作區 |
| `task_id` | string | 所屬任務 ID |

**API 回應格式** (`GET /api/v1/files/tree`)：

```json
{
  "success": true,
  "data": {
    "tree": {
      "temp-workspace": [ /* 默認工作區檔案 */ ],
      "{folder_id}": [
        {
          "file_id": "uuid",
          "filename": "檔案名稱.md",
          "file_type": "text/markdown",
          "file_size": 12345,
          "upload_time": "2026-01-21T12:00:00Z"
        }
      ]
    },
    "folders": {
      "{folder_id}": {
        "folder_name": "目錄名稱",
        "parent_task_id": null,
        "task_id": "task_id",
        "folder_type": "custom"
      }
    },
    "total_files": 5
  }
}
```

### 2.5 文件樹結構示意圖

```
任務文件區
└── 任務工作區 (workspace) ← 預設存放位置
    ├── 子目錄 A

## 會員分級上傳限制（v5.0 新增）

### 3.1 概述

系統依據用戶的會員等級（tier）實施分級上傳大小限制，防止資源濫用並保障系統穩定性。

### 3.2 分級配置

上傳限制值存放於 `system_params` 資料庫，動態可調，無需重啟服務或修改代碼：

| 參數鍵 | 預設值 | 說明 |
|--------|--------|------|
| `upload_max_size_general` | `5242880`（5 MB） | 一般用戶上限 |
| `upload_max_size_vip` | `52428800`（50 MB） | VIP 上限 |
| `upload_max_size_super_vip` | `524288000`（500 MB） | 系統硬上限（防 DoS） |

### 3.3 限制邏輯

```
上傳請求
    │
    ▼
解析 JWT Token → 取得 user.tier
    │
    ▼
查詢 system_params（upload_max_size_{tier}）
    │
    ▼
Content-Length Header 初步檢查（early reject）
    │
    ▼
串流寫入磁碟（chunks）→ 即時計數
    │
    ├─ 計數 < 限制 → 繼續寫入
    └─ 計數 ≥ 限制 → 中止連線、刪除 partial 檔案、回傳 413
```

**特點**：
- **串流寫入磁碟**：`bytes().await` 改為 `chunks().await` 逐塊讀取，不將整個檔案載入記憶體
- **真實大小驗證**：以實際接收的 bytes 計數，非信任 Client 的 Content-Length Header
- **資源清理**：超限時自動刪除已寫入的 partial 檔案

### 3.4 API 回應

超限時回傳 HTTP 413 Payload Too Large：

```json
{
  "success": false,
  "error": "FILE_TOO_LARGE",
  "message": "上傳檔案大小超過會員限制（5 MB）。請升級至 VIP 以獲得 50 MB 上限。",
  "tier": "general",
  "max_size_bytes": 5242880
}
```

### 3.5 前端體驗

- 上傳前根據用戶 tier 顯示可用大小
- 超限檔案在選擇時即時提示（不走上傳流程）
- 提供「升級會員」引導連結

## 帳戶會員等級系統（v5.0 新增）

### 4.1 概述

系統新增會員等級（tier）欄位，用於區分一般用戶與 VIP 用戶，並作為上傳限制、內容訪問等分級策略的依據。

### 4.2 等級定義

| 等級 | 鍵值 | 說明 |
|------|------|------|
| 一般用戶 | `general` | 預設值，所有新建用戶預設此等級 |
| VIP | `vip` | 可升級，解鎖更大上傳額度 |

### 4.3 資料結構

**users collection 新增欄位**：

| 欄位 | 類型 | 說明 |
|------|------|------|
| `tier` | `string` (可選) | 會員等級：`general` 或 `vip`，舊用戶無此欄位時回退 `general` |

**Login Response（`UserInfo`）新增欄位**：

```json
{
  "success": true,
  "data": {
    "token": "eyJ...",
    "user": {
      "_key": "admin",
      "username": "admin",
      "name": "管理員",
      "role_keys": ["admin"],
      "role_names": ["系統管理員"],
      "tier": "vip"
    }
  }
}
```

### 4.4 管理操作

- **新增用戶**：預設 `tier = general`
- **編輯用戶**：管理者可在 UserManagement 頁面切換 `general` ↔ `vip`
- **設計原則**：使用 `Option<String>` 而非 enum，確保未來可擴展至 `super_vip` / `enterprise` 等新等級

### 5.2 兩階段文件分類

#### 設計原則

**分類在重處理前做第一階段，用輕量規則而非 LLM**，確保快速、可解釋、可控。

#### Phase A：檔頭/MIME 初步分流

根據副檔名和 MIME Type 初步判斷：

| MIME 類型 | 初步分類 | 說明 |
|-----------|----------|------|
| `text/*`, `application/pdf` (可選文字) | 待 Phase B 確認 | 可能是 TextOnly 或 Mixed |
| `image/*` | `image_based` | 直接跳轉 OCR 流程 |
| `video/*` | `video` | 未來擴展預留 |
| `application/pdf` (掃描特徵) | 待 Phase B 確認 | 需抽樣檢測 |

#### Phase B：頁面抽樣統計分類

對 PDF/DOCX 等文件，抽樣前 3–5 頁計算指標：

| 指標 | 計算方式 | 閾值 |
|------|----------|------|
| `text_coverage` | 非空文字字元數 / 頁面面積 | > 70% → TextOnly |
| `image_coverage` | 圖片 bbox 面積總和 / 頁面面積 | > 30% → Mixed |
| 圖片數量 | 圖片數 / 頁數 | > 2/頁 → Mixed |

**分類結果**：

| 分類 | 定義 | 後續流程 |
|------|------|----------|
| `text_only` | 文字覆蓋率高，圖片少或無 | 直接進入 Stage 2（跳過圖片處理） |
| `mixed` | 文字與圖片共存 | 進入完整圖片處理 → TimelineBuilder |
| `image_based` | 以圖片為主（掃描件、截圖） | 頁面渲染 → OCR → TextSpan → TimelineBuilder |

### 5.3 Timeline Spans 資料模型

#### 核心概念

**Timeline Spans** 是多模態管線的統一資料抽象：將文件的各種內容（純文字、圖片描述、OCR 文字、影片截圖描述）統一封裝為帶有位置與順序資訊的片段。

#### 統一資料結構

```python
from enum import Enum
from typing import Optional
from pydantic import BaseModel


class SpanKind(str, Enum):
    TEXT = "text"              # 純文字片段
    IMAGE_DESC = "image_desc"  # VLM 生成的圖片描述
    OCR_TEXT = "ocr_text"      # OCR 識別的文字
    VIDEO_DESC = "video_desc"  # 影片截圖描述（未來）


class Span(BaseModel):
    """Timeline Spans 最小單位"""
    kind: SpanKind               # 片段類型
    page_no: int                 # 頁碼（影片為時間戳）
    order_key: float             # 頁內排序鍵（y座標 / 段落索引 / timestamp）
    text: str                    # 內容文字
    source_ref: Optional[dict]   # 來源引用（bbox / xref / paragraph_id / timestamp）
    file_id: str                 # 所屬文件 ID


class ImageRef(BaseModel):
    """圖片引用（從 PDF/DOCX 抽取後，尚未經過 VLM）"""
    image_id: str                # 唯一識別（xref 或 hash）
    page_no: int                 # 所在頁碼
    bbox: tuple[float, float, float, float]  # 左上右下座標
    width: int
    height: int
    sha256: str                  # 圖片去重 Hash
    temp_path: Optional[str]     # 暫存路徑（送 VLM 前）
    source_type: str             # "pdf" | "docx" | "video"


class ProcessingReport(BaseModel):
    """每個文件的處理報告"""
    file_id: str
    classification: str           # "text_only" | "mixed" | "image_based"
    pages_processed: int
    images_extracted: int
    images_vlm_described: int
    images_vlm_failed: int
    ocr_pages: int
    total_text_chars: int
    total_spans: int
    duration_ms: int
    errors: list[dict]
    can_retry: bool              # 是否有可重試步驟
```

#### TimelineBuilder 整合規則

1. 所有 Span（TextSpan + ImageDescSpan + OCRTextSpan）依 `(page_no, order_key)` 排序
2. 相同 `page_no` 內，TextSpan 和 ImageDescSpan 按 `order_key` 交錯排列
3. 跨頁不混合，頁與頁之間以 `---PAGE_BREAK---` 標記
4. Chunk 邊界優先依 Span 邊界切分，避免將不同 Span 硬切成一半

### 5.4 圖片抽取系統

#### PDF 圖片抽取（PyMuPDF）

**使用 Library**：`PyMuPDF`（`fitz`）

**原因**：圖片抽取成熟、速度快、可取得精確位置（bbox、xref）。

```python
import fitz  # PyMuPDF


class PDFImageExtractor:
    """從 PDF 抽取內嵌圖片，含頁碼、bbox、xref"""

    def extract(self, file_path: str, max_pages: int | None = None) -> list[ImageRef]:
        images: list[ImageRef] = []
        seen_hashes: set[str] = set()

        with fitz.open(file_path) as doc:
            total = min(len(doc), max_pages) if max_pages else len(doc)
            for page_no, page in enumerate(doc[:total], start=1):
                for img_index, img in enumerate(page.get_images(full=True)):
                    xref = img[0]
                    base_image = doc.extract_image(xref)

                    # 去重（PDF 可能多次引用同一圖片）
                    img_hash = hashlib.sha256(base_image["image"]).hexdigest()
                    if img_hash in seen_hashes:
                        continue
                    seen_hashes.add(img_hash)

                    # 寫入暫存檔
                    ext = base_image["ext"]
                    temp_path = f"/tmp/img_{file_id}_{xref}.{ext}"
                    with open(temp_path, "wb") as f:
                        f.write(base_image["image"])

                    # 取得 bbox（該圖片在頁面上的位置）
                    img_list = page.get_image_info(xrefs=True)
                    bbox = next(
                        (i["bbox"] for i in img_list if i["xref"] == xref),
                        (0, 0, 0, 0),
                    )

                    images.append(ImageRef(
                        image_id=f"pdf_{xref}",
                        page_no=page_no,
                        bbox=bbox,
                        width=base_image["width"],
                        height=base_image["height"],
                        sha256=img_hash,
                        temp_path=temp_path,
                        source_type="pdf",
                    ))
        return images
```

#### DOCX 圖片抽取（python-docx）

**使用 Library**：`python-docx`（已在使用）

```python
import docx
import hashlib
from docx.oxml.ns import qn


class DOCXImageExtractor:
    """從 DOCX 抽取 inline 圖片，含段落近似位置"""

    def extract(self, file_path: str) -> list[ImageRef]:
        images: list[ImageRef] = []
        seen_hashes: set[str] = set()
        doc = docx.Document(file_path)

        for para_idx, para in enumerate(doc.paragraphs):
            for run in para.runs:
                if not run._element.findall('.//' + qn('w:drawing')):
                    continue

                # 取出 inline image
                for drawing in run._element.findall('.//' + qn('w:drawing')):
                    blips = drawing.findall('.//' + qn('a:blip'))
                    for blip in blips:
                        rId = blip.get(qn('r:embed'))
                        if not rId:
                            continue

                        image_part = run._element.getparent.getparent._part.related_parts.get(rId)
                        if not image_part:
                            continue

                        img_bytes = image_part.blob
                        img_hash = hashlib.sha256(img_bytes).hexdigest()
                        if img_hash in seen_hashes:
                            continue
                        seen_hashes.add(img_hash)

                        ext = image_part.content_type.split("/")[-1]
                        temp_path = f"/tmp/img_docx_{hashlib.md5(rId.encode()).hexdigest()[:8]}.{ext}"
                        with open(temp_path, "wb") as f:
                            f.write(img_bytes)

                        images.append(ImageRef(
                            image_id=f"docx_{rId}",
                            page_no=1,  # DOCX 無頁碼，以段落近似
                            bbox=(0, para_idx * 20, 0, para_idx * 20 + 20),  # 近似 y 座標
                            width=0,
                            height=0,
                            sha256=img_hash,
                            temp_path=temp_path,
                            source_type="docx",
                        ))
        return images
```

### 5.5 VLM Client（qwen3-vl）

#### 設計要點

- **統一接口**：所有 VLM 呼叫透過 `OllamaVLMClient` 進出
- **`thinking` 欄位 Bug 兼容**：qwen3-vl 處理圖片時輸出可能跑到 `thinking` 而非 `response`，Client 層做自動兼容
- **JSON 輸出支援**：圖片描述 prompt 要求 JSON 格式，同時兼容純文字回傳

#### Prompt 設計

```python
VLM_IMAGE_DESC_PROMPT = """你是文件理解助手。請用繁體中文描述這張圖片。

圖片元數據：

  "relations": ["關係描述1", "關係描述2", ...],

#### 實作

```python
import base64
import httpx
from pathlib import Path


class OllamaVLMClient:
    """Ollama VLM 統一 Client，含 thinking 欄位兼容"""

    def __init__(self, base_url: str = "http://localhost:11434", model: str = "qwen3-vl:latest"):
        self.base_url = base_url
        self.model = model
        self.timeout = 120.0

    def describe(self, image_path: str, metadata: dict) -> dict:
        """對單張圖片生成描述"""
        # 讀圖並 base64
        img_bytes = Path(image_path).read_bytes()
        img_b64 = base64.b64encode(img_bytes).decode()

        # 讀取可選的鄰近文字 context
        context = metadata.get("context", "")

        prompt = VLM_IMAGE_DESC_PROMPT.format(
            source_type=metadata.get("source_type", "pdf"),
            page_no=metadata.get("page_no", 1),
            image_index=metadata.get("image_index", 1),
            optional_context=f"\n鄰近文字：{context}" if context else "",
        )

        with httpx.Client(timeout=self.timeout) as client:
            response = client.post(
                f"{self.base_url}/api/generate",
                json={
                    "model": self.model,
                    "prompt": prompt,
                    "images": [img_b64],
                    "stream": False,
                    "options": {"temperature": 0.2, "num_predict": 1024},
                },
            )
            response.raise_for_status()
            result = response.json()

        # === thinking 欄位 Bug 兼容 ===
        # qwen3-vl 處理圖片時，輸出可能跑到 thinking 而非 response
        raw_text = result.get("response", "") or result.get("thinking", "")
        if not raw_text:
            return {"summary": "", "details": [], "entities": [], "relations": [], "confidence": 0}

        # 嘗試 JSON 解析，失敗則回退純文字
        raw_text = raw_text.strip()
        if raw_text.startswith("```"):
            import re
            raw_text = re.sub(r"^```(?:json)?\s*", "", raw_text)
            raw_text = re.sub(r"\s*```$", "", raw_text)

        try:
            import json
            data = json.loads(raw_text)
            return data
        except (json.JSONDecodeError, ValueError):
            # JSON 解析失敗，回退純文字描述
            return {
                "summary": raw_text[:500],
                "details": [],
                "entities": [],
                "relations": [],
                "confidence": 0.3,
            }
```

def _vlm_result_to_span(self, image_ref: ImageRef, vlm_result: dict, context: str = "") -> Span:
    """將 VLM 回應轉換為 ImageDescSpan"""
    summary = vlm_result.get("summary", "")

    # 格式化描述（帶視覺標記，方便在 Timeline 中識別）
    formatted_desc = (

        formatted_desc += "\n要點：" + "；".join(vlm_result["details"])

    return Span(
        kind=SpanKind.IMAGE_DESC,
        page_no=image_ref.page_no,
        order_key=image_ref.bbox[1],  # 使用 y1 座標作為排序鍵
        text=formatted_desc,
        source_ref={"bbox": image_ref.bbox, "image_id": image_ref.image_id},
        file_id=image_ref.image_id.split("_")[0],  # 需傳入 actual file_id
    )

### 5.6 TimelineBuilder（依頁交錯整合）

```python
from dataclasses import dataclass


@dataclass
class TimelineBuilder:
    """將 TextSpans + ImageDescSpans 按 page_no + order_key 交錯排列"""

    def build(
        self,
        text_spans: list[Span],
        image_desc_spans: list[Span],
    ) -> list[Span]:
        # 合併所有 Span
        all_spans = text_spans + image_desc_spans

        # 按 (page_no, order_key) 排序
        all_spans.sort(key=lambda s: (s.page_no, s.order_key))

        # 加入頁分隔標記（供 chunker 參考）
        result: list[Span] = []
        last_page = None
        for span in all_spans:
            if last_page is not None and span.page_no != last_page:
                # 頁分隔（不影響排序邏輯，chunker 依 page_no 切分 chunk）
                pass
            result.append(span)
            last_page = span.page_no

        return result

    def chunk_by_spans(
        self,
        spans: list[Span],
        chunk_size: int = 500,
        chunk_overlap: int = 100,
    ) -> list[str]:
        """依 Span 邊界分塊，優先在 Span 邊界切分"""
        chunks: list[str] = []
        current_chunk_chars: list[str] = []
        current_len = 0

        for span in spans:
            span_text = span.text
            # 若當前 chunk 加上此 span 會超限，先產出當前 chunk
            if current_len + len(span_text) > chunk_size and current_chunk_chars:
                chunks.append("".join(current_chunk_chars))
                # 重疊：取最後 overlap 字元
                overlap_text = "".join(current_chunk_chars)[-chunk_overlap:]
                current_chunk_chars = [overlap_text]
                current_len = len(overlap_text)

            current_chunk_chars.append(span_text)
            current_len += len(span_text)

        # 最後一塊
        if current_chunk_chars:
            chunks.append("".join(current_chunk_chars))

        return chunks
```

### 5.7 記憶體與併發管理

#### 有界併發（防止爆 RAM）

```python
import asyncio
from concurrent.futures import ThreadPoolExecutor
from threading import Semaphore


class BoundedConcurrency:
    """有界併發控制，限制同時處理的圖片數"""

    def __init__(self, max_concurrent: int = 3):
        self.semaphore = Semaphore(max_concurrent)

    def run(self, fn, items: list, *args, **kwargs) -> list:
        """對清單中的每項執行 fn，有界併發"""
        import threading
        results: list = []
        errors: list = []

        def worker(item):
            with self.semaphore:
                try:
                    result = fn(item, *args, **kwargs)
                    results.append((item, result))
                except Exception as e:
                    errors.append((item, e))

        threads = [threading.Thread(target=worker, args=(item,)) for item in items]
        for t in threads:
            t.start()
        for t in threads:
            t.join()

        return results


# 使用範例
concurrency = BoundedConcurrency(max_concurrent=3)
vlm_results = concurrency.run(
    vlm_client.describe,
    image_refs,
    metadata={"source_type": "pdf", "page_no": 1},
)
```

**配置原則**：
- 每文件同時處理 2–4 張圖（依 Ollama 服務吞吐調整）
- 文件之間由 Celery worker 併發處理（不額外限制）

### 5.8 錯誤處理策略

**核心原則：繼續處理（Degrade Gracefully），不因局部失敗而中斷整個文件處理。**

| 失敗類型 | 處理方式 | 可重試 |
|----------|----------|--------|
| 圖片抽取失敗 | 跳過該圖片，繼續處理其他圖片 | ❌ |
| VLM 描述失敗 | 圖片描述 Span 設為空文字，保留 ImageRef 供重試 | ✅ |
| OCR 失敗 | 記錄錯誤，文件仍可入庫 | ✅ |
| 整個文件解析失敗 | 寫入 `parse_failed` 狀態，回傳失敗 | ✅ |

**ProcessingReport 記錄**：

class VideoFrameExtractor:
    """從影片抽取關鍵截圖（未來擴展）"""

    def extract(self, file_path: str, interval_seconds: int = 5) -> list[ImageRef]:

## 向量化系統

### v5.0 更新說明

**2026-04-04**：v5.0 版本，Chunk 邊界優先依 Timeline Spans 切分，確保圖片描述與相鄰文字不被硬切成不同 chunk。

### 向量化流程（v5.0）

```
文件上傳
  ↓
Stage 0-2: 多模態處理（文字 + 圖片 → Timeline Spans）
  ↓
TimelineBuilder.build() → InterleavedSpans[]
  ↓
Chunk by Spans（Span 邊界優先，500 字/塊，100 字重疊）
  ↓
embed() 個別嵌入（bge-m3:latest，1024 維）
  ↓
Qdrant upsert（collection = knowledge_{root_id}）
  ↓
✅ 向量化完成，立即提供檢索能力
```

| 模型 | 維度 | 說明 |

| `bge-m3:latest` | 1024 | 預設多語言模型 |

## 知識圖譜系統

### v5.0 更新說明

**2026-04-04**：Graph Extraction 支援 Map-Reduce 多 chunk 處理，大型文件不再被截斷至 3000 字，而是分散至多個 chunk 呼叫 LLM 後合併去重。

### 處理流程（v5.0）

```
TimelineBuilder 產出 InterleavedSpans[]
  ↓
分塊（每 chunk 3000-4000 字元，保留 Span 邊界）
  ↓
┌──────────────────────────────────────────┐
│ Map Phase：並行呼叫 LLM（每 chunk 獨立）│
│                                          │
│ chunk_1 → graph.extract(chunk_1, ont)   │
│ chunk_2 → graph.extract(chunk_2, ont)   │
│ chunk_3 → graph.extract(chunk_3, ont)   │
│ ...（有界併發，2-3 個 worker）          │
└────────────────────┬─────────────────────┘
                     │ 產出 entities[] + relations[]
                     ▼
┌──────────────────────────────────────────┐
│ Reduce Phase：去重合併                    │
│                                          │
│ a) Entity 去重（依 name + type 合併）    │
│ b) Relation 去重（依 source + target）   │
│ c) 跨 chunk 關係補抽                     │
│    （overlap 區域 re-check entity 關係） │
└────────────────────┬─────────────────────┘
                     │
                     ▼
Ontology Schema 對齊（base_class / property 映射）
  ↓
GraphRAG 裁決層（置信度過濾）
  ↓
存儲到 ArangoDB
  ↓
✅ 完成
```

### Ontology 選擇策略（不變）

**優先級降級機制**:

1. **Tier 1**: Major Ontology（專業層）
2. **Tier 2**: Domain Ontology（領域層）
3. **Tier 3**: Base 5W1H Ontology（基礎層）
4. **Tier 4**: LLM 自由發揮

### Entity 去重規則

| 規則 | 說明 |
|------|------|
| 名稱相同 + type 相同 | 視為同一 entity，保留 description 最長者 |
| 名稱相同 + type 不同 | 視為不同 entity（同一術語在不同領域有不同意義） |
| 合併時衝突 | description 最長者優先 |
