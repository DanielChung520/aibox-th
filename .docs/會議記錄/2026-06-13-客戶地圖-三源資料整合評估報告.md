## 三源資料整合策略

### 資料角色定義

| 資料源 | 角色 | 地圖顏色 | 優先順序 |
|--------|------|---------|---------|
| **衛福部** | 產業未開發客戶（扣除已在業務王/Ragic 者） | 🟢 綠色 | 先匯入，再做比對去重 |
| **業務王** | 潛在客戶（業務已接觸但未成單） | 🟡 黃色 | 第二順位匯入 |
| **Ragic** | 既有客戶（已成交/既有往來） | 🔵 藍色 | 第三順位匯入 |

### 資料比對去重邏輯

```
衛福部全量資料 (31,381筆)
    │
    ├─ 與業務王比對（機構名稱 + 電話模糊比對）
    │   ├─ 命中 → 標記為「已有業務接觸」
    │   └─ 未命中 → 保留為「產業潛在客戶」
    │
    └─ 與 Ragic 比對（機構名稱 + 統一編號）
        ├─ 命中 → 標記為「既有客戶」
        └─ 未命中 → 保留原標記
```

## 風險與注意事項

| 風險 | 影響 | 緩解方式 |
|------|------|---------|
| 衛福部 CSV 31K 筆全部顯示可能造成前端卡頓 | 效能 | 使用 Leaflet.markercluster 分群，zoom in 後逐層顯示 |
| 業務王資料無 API，需手動匯出 CSV | 自動化 | 初期先手動匯出，後續評估有無 API 或自動化匯出機制 |
| Ragic 無法取得 API Key | 既有客戶資料無法匯入 | 先以衛福部 + 業務王上線，Ragic 待取得權限後補上 |
| 三源去重比對準確率 | 資料品質 | 先用機構名稱 + 電話號碼比對，人工覆核 |
