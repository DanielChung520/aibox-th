## Slide 5｜知識體系 — 告別幻覺的四層防護

### 視覺佈局

```
┌──────────────────────────────────────────────┐
│                                              │
│  告別幻覺：從文件到可靠的知識資產               │
│                                              │
│                                              │
│  Layer 1: 智慧導入                            │
│  不是粗暴切割，而是理解段落、圖表、表格後再向量化 │
│                                              │
│  Layer 2: 三層 Ontology                       │
│  Domain（領域）→ Major（專業）→ Basic（5W1H）  │
│                                              │
│  Layer 3: GraphRAG 知識圖譜                   │
│  知識節點 + 邊的抽取，文件之間的關聯可追溯       │
│                                              │
│  Layer 4: 持續學習                            │
│  每次互動記錄歸納，圖譜持續更新成長              │
│                                              │
│                                     準確性 ↗   │
│                                              │
└──────────────────────────────────────────────┘
```

### 講稿腳本（約 90 秒）

> 「幻覺是企業 AI 最大的信任殺手。
>
> 我們花了很大的力氣在解決這個問題。
>
> 大部分 RAG 系統的做法是：把文件切成一塊一塊，丟進向量資料庫，然後祈禱它找對答案。這太粗糙了。
>
> EEA 的做法完全不同——四個層層遞進的防護。
>
> **第一層**，文件導入時不是粗暴切割，而是先理解段落結構、識別圖表、解讀表格，再做智慧型向量化。
>
> **第二層**，我們建立了三層 Ontology。根據領域（Domain）、專業（Major）、基礎（Basic）為知識建立結構。即使找不到對應分類，還有 5W1H 的基礎框架兜底。
>
> **第三層**，用知識圖譜（GraphRAG）抽取知識節點與關聯，讓系統理解概念之間的脈絡。
>
> **第四層**，持續學習——每次互動都被記錄、歸納，反饋回知識體系。
>
> 這不是一個功能，這是 EEA 的知識基礎設施。」

### 講稿腳本（約 75 秒）

> EEA 已經打通了 Ragic 資料關聯，並接入了知識圖譜。
>
> 舉一個具體的例子：一張訂單發生了退貨。
>
> 傳統系統：你看到『訂單 A 已退貨』。

>
> 不只是查資料，而是把資料變成**可推理的企業記憶**。

## 附錄 A5｜ML/DL 數據模型服務 — 策略建議

> 你問到 ML/DL 數據模型這部分能不能給建議，以下是我的分析。

### 為什麼這是對的方向

1. **自然延伸** — 企業累積了知識圖譜、使用數據、領域標註資料後，下一步必然是「用這些數據訓練自己的模型」
2. **高護城河** — 客製化模型訓練是超級黏著服務，客戶幾乎不會換供應商
3. **高毛利** — 智力服務的邊際成本低、定價彈性高
4. **競爭門檻** — 多數 AI 平台做到 SaaS 就停了，能做到 model fine-tuning 層的很少

### 建議的三階段 ML/DL 策略

| 階段 | 服務 | 定價模式 | 技術準備 |
|------|------|---------|---------|
| **Phase 1 (Now)** | 平台內建 Analytics — 使用數據報表、Token 消耗分析、知識庫成長趨勢 | 含在 SaaS 訂閱內 | 已有 billing data，加上 logging 即可 |
| **Phase 2 (2026 Q4)** | **LoRA 微調服務** — 用企業知識庫數據微調開源模型（Llama/Qwen 等） | 專案報價：NT$200K–500K/案 | 需建立 LoRA pipeline + 評估框架 |
| **Phase 3 (2027+)** | **專屬 ML/DL 顧問服務** — 從數據清洗、特徵工程到模型部署的一條龍服務 | 年度顧問合約：NT$1M+/年 | 需建立數據科學團隊或策略夥伴 |

### 具體可以賣的 ML/DL 服務項目

| 服務項目 | 說明 | 目標客戶 |
|---------|------|---------|
| **企業專屬 LLM 微調** | 用 LoRA/QLoRA 調校開源模型，融入企業術語與知識 | 中型以上製造業、物流業 |
| **異常檢測模型** | 從生產數據中訓練異常偵測模型（退貨預測、設備異常） | 製造業 |
| **需求預測模型** | 用歷史訂單 + 外部數據做銷售預測、庫存建議 | 零售/經銷商 |
| **NLP 分類模型** | 客製文件分類、合約審查、客訴分析模型 | 金融/保險/法律 |
| **資料漂移監控** | 監控模型上線後的效能衰退，自動觸發重新訓練 | 所有已導入模型的客戶 |

### 執行建議

1. **不要現在就建 ML 團隊** — Phase 1 先靠平台數據累積信任，Phase 2 再用 LoRA fine-tuning 試水溫
2. **先從 LoRA 開始** — 不需要從頭訓練，LoRA 微調成本低、交付快、效果好
3. **找一個標竿客戶做案例** — 找一個資料量大的客戶，免費或低價做第一個 fine-tuning 專案，產出 case study 後再標準化報價
4. **注意 GPU 成本** — 微調需要 GPU，初期可以租用雲端 GPU，不需要自建
5. **建立評估標準** — 企業客戶需要看到「微調後準確率提升 X%」的量化證據，建議先建立 evaluation benchmark

## 附錄｜簡報製作總提醒

### 設計原則

1. **色調**：暗色系（海軍藍/石墨灰）+ 電藍品牌色 accent → 跟你宣傳片風格一致
2. **字體**：中文使用 Noto Sans TC 或思源黑體，英文使用 Inter
3. **圖片**：你的 AI 生成宣傳片畫面非常適合當背景圖
4. **少字多圖**：每頁講稿我寫了文字，但投影片上「最多 20 個字」
5. **Demo 影片**：YouTube 連結給我後，我在 Slide 4–8 嵌入 demo 敘述

### 投影片製作建議工具

- **Canva** — 最快速，有大量企業模板，支援協作
- **Keynote** — macOS 用戶首選，動畫順暢
- **Gamma.app** — AI 生成簡報，但你已有完整腳本，Canva/Keynote 更可控

### 字數控制

每頁投影片上的文字不超過 20 字。
所有細節在講稿裡講，投影片只是視覺輔助。
VC 一分鐘看一頁，不要讓他們「讀」你的簡報。
