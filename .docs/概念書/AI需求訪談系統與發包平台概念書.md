## 1. 背景與問題

### 市場現況

市場上大多數 AI Agent 平台（ Dify、Coze、LangChain 等）宣稱「每個人都能寫智能體」，但：
- 用戶知道怎麼描述需求嗎？
- 沒有受過需求訪談訓練的人，會漏掉很多重要的假設
- 做出來的 Agent 好壞，取決於用戶的「描述能力」，而不是「需求本身」
- 用戶發現不符合預期時，已是上線之後

### 核心問題

> **「每個人都能寫」是偽命題，應該是「每個人都能說清楚目標，AI 幫你想清楚、做出來」**

## 2. 我們提出的創新方向

### 2.1 AI 需求訪談系統（Phase 1 - 近期實作）

讓 AI 扮演「需求訪談者」的角色，在用戶填寫需求表的過程中，被動陪伴、主動補漏。

#### 設計原則

| 原則 | 說明 |
|------|------|
| **被動感知** | 艾企感知用戶正在填寫需求表，但不主動打斷 |
| **預測提示** | 根據當前欄位、填寫內容，預測用戶可能需要的提示 |
| **環境專家** | 像一個安靜站在旁邊的顧問，你知道他在，可以隨時問 |

#### 用戶體驗

```
┌──────────────────────────────────────────────────────────┐
│  需求提交頁面                                             │
│                                                           │
│  ┌─────────────────────────┐  ┌──────────────────────┐  │
│  │ 【表單區】              │  │ 【艾企討論區】        │  │
│  │                         │  │                      │  │
│  │ 需求目標：___________   │  │  💬 艾企             │  │
│  │                         │  │  「我可以在任何時候  │  │
│  │ 預期效果：___________   │  │   幫你，只要點我」   │  │
│  │                         │  │                      │  │
│  │ 問題描述：___________   │  │  看到您在填「目標」  │  │
│  │                         │  │  欄，可以問我任何    │  │
│  └─────────────────────────┘  │  相關問題             │  │
│                               └──────────────────────┘  │
│                                                           │
│  【❓ 常見問題】  【📋 需求範本參考】  【📤 提交需求】   │
└──────────────────────────────────────────────────────────┘
```

#### 觸發時機

| 觸發 | 行為 |
|------|------|
| 用戶 hover/focus 某欄位 | 艾企被動回應該欄位相關問題 |
| 用戶停頓很久 | 艾企預測可能卡住，顯示提示 |
| 用戶直接問艾企 | 召喚討論模式，深度諮詢 |
| 用戶提交前 | 艾企自動整理摘要，附在需求文件裡 |

### 2.2 混合模型架構

```
┌─────────────────────────────────────────────────────────┐
│                    任務特性                               │
│                                                         │
│  日常性 / 即時性        ↔        複雜推理 / 專家咨詢     │
│                                                         │
│        ↓                                        ↓       │
│                                                         │
│  ┌───────────────┐                      ┌──────────────┐│
│  │  本地模型      │                      │  外部模型     ││
│  │  (Ollama)     │                      │  (GPT-4/Claude)││
│  │               │                      │              ││
│  │  • Ambient    │                      │  • 複雜分析  ││
│  │  • 快速回覆   │                      │  • 深度推理  ││
│  │  • 隱私敏感   │                      │  • 需求訪談  ││
│  └───────────────┘                      └──────────────┘│
└─────────────────────────────────────────────────────────┘
```

#### 任務分流原則

| 場景 | 模型 | 原因 |
|------|------|------|
| 用戶 hover 某欄位，快速提示 | 本地（Ollama） | 低延遲、簡單提示 |
| 用戶問複雜的串接問題 | 外部（GPT-4） | 需要深度推理 |
| 需求訪談最終摘要生成 | 外部（GPT-4/Claude） | 品質要求高 |
| 即時多輪對話 | 本地 | 需要低延遲互動 |
| 理解用戶模糊描述背後意圖 | 外部 | 需要複雜推理 |

### 2.3 企業級發包平台（Phase 2 - 中期方向）

#### 願景

建立一個「AI 工作的雙邊市場」，讓企業和 AI 工作者精準匹配。

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│   企業（需求方）              平台                AI 工作者  │
│                                                             │
│   「我要一個                    「AI 幫你整理需求，           │
│    Ragic 小幫手」              發包給自由工作者」            │
│         │                          ↕                        │
│         │                     ┌─────────────┐              │
│         │                     │   發包系統   │              │
│         │                     │  ・需求審核  │              │
│         │                     │  ・報價匹配  │              │
│         │                     │  ・品質把關  │              │
│         │                     └─────────────┘              │
│         │                          ↕                        │
│         │              ┌────────────────────────┐         │
│         └─────────────→│   外部 AI 自由工作者     │←───────┘
│                        │   ・接案投標            │
│                        │   ・遠端協同            │
│                        └────────────────────────┘
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

#### 隱私分層架構（核心設計）

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│   【企業視角】          【平台】          【AI 工作者視角】  │
│                                                             │
│   「我」               「我知道」           「我只看到」     │
│                                                             │
│   ・公司名稱            ・真實身份           ・任務內容      │
│   ・產業領域            ・任務需求           ・技術要求      │
│   ・內部流程            ・時程報價           ・驗收標準     │
│   ・商業敏感資料        ・品質把關           ・報酬金額     │
│                                                             │
│   ════════════════════════════════════════════════════     │
│                       隔離層                                │
│   「企業身份」只存在平台，AI工作者完全看不到                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

| 隔離機制 | 做法 |
|----------|------|
| **身份隔離** | AI 工作者只能看到任務內容，看不到企業名稱/產業/任何人資訊 |
| **通訊隔離** | 對話通過平台轉接，雙方不直接交換聯繫方式 |
| **資料隔離** | 企業上傳的參考文件由平台托管，不直接給工作者 |
| **金流隔離** | 報酬由平台統一處理，工作者不知道企業真實預算 |
| **NDA 機制** | 工作者接案前需簽保密協議，平台有法律約束力 |

#### 脫敏 context 範例

| 原始資訊 | 脫敏後 |
|----------|--------|
| 「XYZ 軟體公司的內部 IT 客服」 | 「某軟體公司的內部 IT 客服」 |
| 「ABC 製造的庫存查詢系統」 | 「某製造公司的庫存查詢系統」 |

## 3. 價值評估

| 維度 | 評分 | 說明 |
|------|------|------|
| **市場差異化** | ⭐⭐⭐⭐⭐ | 市場上沒有「AI幫你想清楚再做」的功能 |
| **降低需求失敗率** | ⭐⭐⭐⭐ | AI 主動補漏，減少來回確認 |
| **用戶信任度** | ⭐⭐⭐⭐ | 用戶覺得系統「懂我」，不只是工具 |
| **商業價值** | ⭐⭐⭐⭐ | 「AI幫你想清楚」比「AI幫你生出來」更有賣點 |
| **平台商業模式** | ⭐⭐⭐⭐⭐ | 雙邊市場、網路效應、長期價值高 |

## 4. 實作路徑

### Phase 1：AI 需求訪談系統（MVP）

**目標**：用現有團隊實作艾企需求引導功能

| 階段 | 工作項 | 難度 |
|------|--------|------|
| **1.1** | FormContextProvider 追蹤 page + field | 低 |
| **1.2** | 艾企 API 支援接收 FormContext | 中 |
| **1.3** | IntentPredictor 引擎（基於欄位的簡單規則） | 中 |
| **1.4** | Tooltip/floating hint UI | 低 |
| **1.5** | 提交前結構化摘要生成 | 中 |

### Phase 2：企業發包平台

**目標**：開放外部 AI 工作者接案

| 階段 | 工作項 |
|------|--------|
| **2.1** | 身份隔離架構實作 |
| **2.2** | 發包/投標系統 |
| **2.3** | 報價/時程管理 |
| **2.4** | 品質審核機制 |
| **2.5** | 金流/付款系統 |

## 6. 討論記錄

### 2026-04-22 討論摘要

1. **提出背景**：市場上「每個人都能寫智能體」是偽命題，用戶描述能力決定成品品質
2. **創新方向**：AI 做需求訪談者，被動陪伴、主動補漏
3. **技術可行性**：混合模型架構（本地+外部），技術可行
4. **商業模式**：雙邊市場，企業隱私保護是核心設計
5. **初期策略**：先由團隊內部開發，未來再開放外部接案
