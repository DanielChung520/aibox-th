### 目的

確保道霖 (dawnlink) Ragic Schema 的變更能夠安全、可追蹤、可復原地執行，支援「產品專案化」的迭代開發模式。

|------|------|

| **同步目標** | Qdrant (`ragic_schemas`, `ragic_intents`) + ArangoDB (`intent_catalog`) |

| **影響範圍** | 所有 Ragic 表單、Field Link、系統參數 |

## 🔙 Rollback 復原計劃

### 何時執行 Rollback

| 情況 | 動作 |
|------|------|
| 階段 2-4 發生錯誤且無法快速修復 | 立即 Rollback |
| 使用者回饋有重大問題（影響核心業務） | 協商後 Rollback |
| 資料一致性問題影響 > 10% 資料 | 立即 Rollback |

### Rollback 步驟

#### Rollback 1：Schema 復原

```bash
# 1. 停止所有 Ragic 同步服務
pkill -f "01_sync_ragic_schema"

# 2. 從備份復原 Schema
cd .docs/Ragic/dawnlink/
cp dawnlink_YYYYMMDD_schema.json backup/
# 在 Ragic 後台手動匯入或使用 API

# 3. 驗證 Schema 已復原
# 檢查關鍵 Sheet 是否存在
```

#### Rollback 2：資料庫復原

```bash
# 1. 停止 ArangoDB
docker stop arangodb

# 2. 從快照復原
docker run --rm -v arangodb_data:/data arangodb:latest \
  arangod --restore --backup /backup/arangodb_YYYYMMDD

# 3. 重啟 ArangoDB
docker start arangodb

# 4. 驗證資料庫正常
curl http://localhost:8529/_api/version
```
