# Ragic 小幫手 開發規格書
需求編號：A01-2617-001
## 需求概要
- **目標**：我要做一個通信軟件的幫手，主要是協助企業Ragic 使用者，對Ragic 基本操作知識，的問題，提供回答、指引，同時接受抱怨，記錄問題等。
- **預期效果**：當user 問相關Ragic 操作或Ragic 系統相關信息，可以快速回答。而且user 反應的問題，哪怕就只是抱怨，也能在後台做個記錄。未來希望除了line，也能在Whatever 使用，
- **問題描述**：現在大部分的user都在line 這類的通信軟件

## 摘要
開發一個名為「Ragic 小幫手」的 AI Agent，專門協助企業用戶解決 Ragic 軟體操作問題與系統相關疑問，同時能記錄用戶抱怨並支援多通訊平台（如 LINE），未來可擴充至其他平台。該 Agent 將整合知識庫、記憶系統與工具調用，並透過 Rust API Gateway 進行服務間通訊，符合本系統架構與開發規範。

## 模組規劃
| 模組 | 說明 | 優先級 |
|------|------|--------|
| Ragic 小幫手 Agent | 核心智能體，負責接收用戶訊息、解析意圖、調用知識庫與工具、回應用戶並記錄抱怨。 | high |
| LINE Bot 整合模組 | 負責接收 LINE 訊息、轉發至 Ragic 小幫手 Agent，並回傳回應。 | high |
| 抱怨記錄與後台管理 | 將用戶抱怨記錄至 ArangoDB，供後台審查與分析。 | medium |
| Ragic 知識庫整合模組 | 使用 HybridRAG 模組查詢 Ragic 相關操作與系統資訊，提供準確回答。 | high |

## 風險
- LINE Bot 訊息處理與轉發可能因平台限制導致延遲或錯誤
- HybridRAG 知識庫更新不即時影響回答準確性
- 抱怨記錄模組需與後台流程整合，可能產生資料不一致
- Rust API Gateway 設計複雜度高，需確保服務穩定性

## 已授權知識庫
